# «Слышу Рядом» — продукт, ограничения и индекс требований

Версия 3.0 · 27.10.2026 · заменяет версию 2.0 (09.10.2026) и продуктовую спецификацию v1.1.

## 0. Как пользоваться

Документ держит то, что не принадлежит одной функции: что за продукт, принципы, ограничения, глоссарий, метрики и индекс идентификаторов `REQ-…`. Поведение по функциям описано в `openspec/specs/`.

Источники правды, по убыванию:

1. **Код в `main`** — то, что реально работает. Спека противоречит коду — прав код, расхождение называется в отчёте и PR.
2. **`openspec/specs/<capability>/spec.md`** — проверяемое поведение по функциям, снято с кода 27.10.2026 (23 capability). Меняется только через change и его архивацию.
3. **`openspec/changes/*`** — то, чего в коде ещё нет: дельты к спекам, решения (`design.md`), задачи.
4. **Этот документ** — продукт, принципы, ограничения, глоссарий, метрики, индекс.

Как менять поведение — скилл `openspec` (`.agents/skills/openspec/SKILL.md`). Идентификаторы `REQ-…` остаются ссылками из кода, тестов и задач; индекс (§5) отвечает, в какой capability лежит требование и сделано ли оно.

Где искать то, что раньше было в этом документе:

| Тема | Где |
|---|---|
| Архитектура, компоненты, развёртывание | `README.md`, `agent/README.md`, `k8s/README.md`, `AGENTS.md` |
| Бизнес-логика агента, голос, кризис, память | `openspec/specs/` (`dialog`, `dialog-voice`, `crisis-safety`, `memory-notes`, `memory-search`, `orb-mood`) |
| Контракты `agent-api` и публичный API | `openspec/specs/agent-api`, `app/packages/contracts` |
| Лимиты, сроки, производительность | capability-владельцы: `dialog`, `dialog-voice`, `data-retention` |
| Конфигурация | `agent/.env.example`, `k8s/*/00-*.yaml`, `app/packages/core/src/config/env.ts` |
| Аналитика | `docs/analytics.md`, `openspec/specs/product-analytics` |
| Расхождения кода и замысла, дорожная карта | `openspec/changes/*` и задачи Multica |

Нотация: **MUST / SHALL** — обязательно; **SHOULD** — желательно; **MAY** — допустимо. Идентификаторы: `REQ-<ОБЛАСТЬ>-<NN>` — требования продукта, `CON-<ОБЛАСТЬ>-<NN>` — ограничения. Области: `PRD` продукт, `DLG` диалог, `SAFE` кризис, `GEN` генерация, `VOICE` голос, `MEM` память, `MODE` режимы, `CARE` антизависимость и мост к людям, `WELL` дневник и тесты, `DATA` данные и приватность, `ACC` аккаунты, `OPS` эксплуатация, `OBS` наблюдаемость.

## 1. Продукт

### 1.1. Резюме

Голосовой ИИ-компаньон для эмоциональной разгрузки. Выслушивает без осуждения в любой момент, помнит человека между разговорами, помогает назвать и выразить эмоции — и системно возвращает человека к живым людям: друзьям, группам поддержки, специалистам.

Это не замена психотерапии и не «виртуальный партнёр». Это мост: разгрузка здесь и сейчас + путь к живому контакту.

| Параметр | Значение |
|---|---|
| Название | «Слышу Рядом» (домен `слышу-рядом.рф`); имя агента в разговоре — «Рядом» |
| Контекст | Конкурс Sber500xDisrupt, гипотеза «Место, где можно выговориться», номинация «Высокочастотная поверхность» (≥ 25 обращений к решению на DAU) |
| Основной интерфейс | Голос (речь в речь, Gemini Live); текст — запасной |
| Платформы | Веб-приложение, PWA, Android и iOS (одна кодовая база на TypeScript + Capacitor), Telegram Mini App |
| Аудитория | 18+ |
| Данные | 152-ФЗ, вход без регистрации, «стереть всё» одной кнопкой |

### 1.2. Принципы (манифест) — обязательны для любой бизнес-логики

| ID | Принцип | Что значит для кода |
|---|---|---|
| `REQ-PRD-01` | Слушаем, не судим | Промпты и шаблоны MUST NOT содержать оценок, поучений, «надо было» |
| `REQ-PRD-02` | Советы — только по запросу | По умолчанию — слушание, отражение, помощь назвать эмоцию |
| `REQ-PRD-03` | Без ярлыков | Подстройка под человека идёт по его заметкам; профиль личности не строится (решение B5), и ни ярлык, ни диагноз MUST NOT показываться |
| `REQ-PRD-04` | Успех — когда легче и ближе к людям | Метрики и логика MUST NOT оптимизировать время в приложении |
| `REQ-PRD-05` | Время — часть заботы | Агент знает, сколько прошло с прошлого разговора, и ведёт себя соответственно |
| `REQ-PRD-06` | Кризис важнее продукта | Кризисный протокол перекрывает любой режим, лимит и метрику |
| `REQ-PRD-07` | Приватность по умолчанию | Без рекламы, без продажи данных, без обучения общих моделей на личных диалогах |

Тон — «спокойный взрослый рядом»: тепло без сюсюканья, внимание без допроса, честность без оценок.

### 1.3. Аудитория

| Сегмент | Боль | Что даём | Статус |
|---|---|---|---|
| Ядро: взрослые 20–45, «некому выговориться» | Терапия дорогая и с ожиданием, друзей грузить неловко, стигма | Разгрузка 24/7 без записи и оценки | есть |
| В выздоровлении от зависимостей | Между группами и звонками наставнику накрывает | Режим «Выздоровление»: чекины HALT, деэскалация, связь с людьми | нет |
| В терапии | Между сессиями нужна опора | Дневник настроения, самопроверка, материал к сессии | частично |
| Острые периоды (расставание, переезд, выгорание) | Нужна ежедневная опора | Ежедневная опора + мост к специалисту | частично |

### 1.4. Ключевые сценарии

| ID | Сценарий | Статус |
|---|---|---|
| А | «23:40, тяжело после ссоры»: одна кнопка «Поговорить» → голосом 10 минут → агент отражает и помогает назвать эмоции → завершение «что забираешь с собой» → утром бережное напоминание | частично: уведомлений нет (`add-notifications`) |
| Б | «Между группами»: вечерний чекин HALT → напряжение 7/10 → деэскалация → напоминание про наставника → счётчик чистого времени | нет |
| В | «Три недели тишины»: агент замечает паузу и продолжает с учётом прошлого | частично: время с прошлого разговора считается, но на приветствие и ответы не влияет (`REQ-DLG-02`) |
| Г | «Красная зона»: агент видит риск → останавливает сценарий → короткая деэскалация → лист с горячими линиями → предложение набрать сейчас; без удержания в диалоге | частично: детектор — список слов |

## 2. Глоссарий

| Термин | Значение |
|---|---|
| Агент | Сервис `agent/` (Python): владеет разговорами и всей логикой разговора |
| Шлюз, API приложения | `app/services/api` (Node.js, Hono): аккаунты, лимиты, WebSocket-шлюз клиент ↔ агент. Единственная вызывающая сторона агента вместе с админкой |
| Разговор (диалог) | Ресурс агента: последовательность сообщений от начала до завершения. У человека не больше одного открытого разговора. В контрактах и коде — `dialog` |
| Реплика | Одно сообщение человека — текстом или голосом |
| Ответ | Сообщение агента |
| Приветствие | Первая фраза агента в разговоре |
| Сводка разговора | Название, темы, напряжение до и после, итог разговора |
| Итог разговора | Текст «Что забираешь с собой?»: человек пишет его при завершении или агент подводит сам |
| Итоги недели | Текст за неделю по отметкам дневника и итогам разговоров |
| Напряжение | Самооценка человека по шкале 1–10 |
| Заметка | Короткое утверждение о человеке в памяти; человек видит, правит и удаляет каждую |
| Память | Заметки между разговорами и поиск по словам из прошлых разговоров; включает сам человек, на паузе заметки хранятся, но не используются |
| Блок памяти | То, что агент вставляет в сессию модели из заметок |
| «Без памяти» | Режим разговора: заметки и поиск не используются и не пополняются, итог не подводится; сам разговор идёт и хранится как обычный, 90 дней |
| Гость | Аккаунт без подтверждённой почты и без привязанного Telegram; открывается ключом устройства |
| Кадр `safety` | Сигнал «человеку нужна помощь сейчас»: клиент открывает лист с линиями помощи |
| Кадр `mood` | Тон последней реплики (`tone`, `intensity`): клиент красит шарик (`REQ-VOICE-10`); к кризису отношения не имеет |
| Режим | Вариант разговора; сейчас один. Остальные из замысла (`chat`, `gestalt_diary`, `recovery`, `rituals`, `warmth`) не реализованы |
| Разговор без рук | Голосовой режим: клиент сам находит начало и конец реплики, человек может перебить голосом |
| Gemini Live | Единственный голосовой контур: слушает, отвечает и говорит одна модель |
| Фоновая модель | Модель за прокси, которой агент пользуется для итогов разговоров и недели и для заметок памяти; в разговоре не участвует |

## 3. Ограничения решения

Ограничения не обсуждаются в рамках задачи на бизнес-логику: их изменение — отдельное решение владельца продукта.

### 3.1. Правовые и этические

| ID | Ограничение |
|---|---|
| `CON-LAW-01` | Сервис самоподдержки, MUST NOT позиционироваться как медицинская услуга или психотерапия. Агент MUST NOT ставить диагнозы и назначать лекарства. Дисклеймер — в онбординге и оферте |
| `CON-LAW-02` | Возраст 18+. Человек, указавший возраст до 18, не получает доступа: согласие не записывается (`AGE_RESTRICTED`) |
| `CON-LAW-04` | Без рекламы, без продажи данных, без обучения общих моделей на личных диалогах (`REQ-PRD-07`) |
| `CON-ETH-01` | Анти-зависимость: MUST NOT генерировать контент, поощряющий зависимость («только я тебя понимаю», ревность к живым людям); при переиспользовании — мягкая рекомендация живого контакта, без жёстких запретов |
| `CON-ETH-02` | Если появится режим «Тепло»: никакой романтической эксклюзивности и сексуализации, потолки — в системном промпте и в safety-проверке; до ревью консультантами режим MUST NOT включаться |
| `CON-ETH-03` | Уважение к анонимным сообществам: термин «наставник»; MUST NOT использовать имена, атрибутику и площадки 12-шаговых программ и заявлять аффилиацию |
| `CON-ETH-04` | Кризисные скрипты и список горячих линий MUST проходить ревью консультантов (практикующих психологов) до релиза |

### 3.2. Данные и приватность

| ID | Ограничение |
|---|---|
| `CON-DATA-01` | Аудио человека MUST NOT сохраняться нигде — ни на диске, ни в кэше. В кэше допустимо только аудио фраз агента |
| `CON-DATA-02` | Тексты реплик и ответов MUST NOT попадать в логи и метрики (только идентификаторы, длины, длительности). В трейсах — только маскированный текст |
| `CON-DATA-03` | Агенту передаётся только `userId` (UUID); почта и имя агенту MUST NOT передаваться |
| `CON-DATA-04` | «Стереть всё» — синхронно у агента, необратимо, с подтверждением; данные не объявляются удалёнными, пока агент не подтвердил стирание |
| `CON-DATA-05` | Два срока с разным отсчётом, оба сейчас по 90 дней, и их нельзя смешивать. Разговор (текст и итог) стирается через 90 дней после последнего сообщения у всех аккаунтов; подтверждённая почта этот срок не продлевает. Гостевой аккаунт (без подтверждённой почты и без Telegram), который не открывали 90 дней, стирается автоматически вместе со всем, что в нём есть, и данными агента (фоновая задача шлюза). Тексты для людей говорят о каждом сроке отдельно (`data-retention`) |
| `CON-DATA-06` | Секреты — только в Secret k8s и локально у администратора; в git — плейсхолдеры `<CHANGE_ME_*>`. В коде, PR и комментариях MUST NOT быть значений секретов |
| `CON-DATA-07` | Тексты, уходящие во внешние модели, SHOULD проходить PII-маскирование (`REQ-DATA-03`, `memory-notes`) |

### 3.3. Технические

| ID | Ограничение | Почему |
|---|---|---|
| `CON-TECH-01` | Агент — только внутри кластера: без HTTPRoute, доступ по внутреннему токену `Authorization: Bearer` и NetworkPolicy (`prod → agent:8001`) | Изоляция ПДн-обработки |
| `CON-TECH-02` | Контракт `agent-api` расширяется только добавлением полей; неизвестные поля и кадры игнорируются в обе стороны. Публичный контракт клиента (`app/packages/contracts`) — тоже только добавление: мобильные сборки живут месяцами | Совместимость старых клиентов |
| `CON-TECH-03` | `tts_start` SHOULD приходить не позже 0,9 с после `assistant_end`; опоздавшая озвучка просто начинается позже, клиент ответ своим голосом не читает (так читал, и получался двойной голос). Своим голосом клиент читает только приветствие | Голос — основной интерфейс |
| `CON-TECH-04` | По `tts_cancel` озвучка прекращается немедленно; в hands-free агент должен замолчать в пределах 300 мс от начала речи человека | Перебивание голосом |
| `CON-TECH-05` | Звук: вход PCM16 LE моно 16 кГц, кадры по 100 мс; выход агента PCM16 LE моно 24 кГц, кадры по 200 мс. Формат в кадрах не передаётся. К клиенту шлюз отдаёт озвучку в кодеке, согласованном в `hello` (`opus`/`mulaw`/`pcm16`, `REQ-VOICE-09`, `dialog-voice`); без согласования — PCM16, как раньше | Фиксирован в контракте v1; клиентский контракт расширен только полями |
| `CON-TECH-06` | Конфигурация агента — только через pydantic-settings (`agent/app/core/config.py`, `validation_alias` на каждое поле, `SecretStr`, fail-fast); хардкод конфигов запрещён | `agent/AGENTS.md`, «Конфигурация» |
| `CON-TECH-07` | Кризисная ветвь MUST быть детерминированной и не зависеть от генеративной модели | Предсказуемость в худший момент |
| `CON-TECH-08` | Отказ любой внешней модели MUST NOT оставлять человека без ответа и MUST NOT вешать конвейер дольше таймаута | Деградация, а не падение |
| `CON-TECH-09` | Инфраструктура: только production, кластер Timeweb (Москва), образы только из реестра проекта | Текущие ресурсы |

### 3.4. Организационные

| ID | Ограничение |
|---|---|
| `CON-ORG-01` | Изменения — только через pull request в `main`; мёрж и деплой выполняет человек |
| `CON-ORG-02` | Общие файлы (CI, манифесты k8s/Istio, схемы БД, lock-файлы) меняются только по явному требованию задачи |

## 4. Метрики

### 4.1. Конкурсные

| Метрика | Порог | Цель |
|---|---|---|
| DAU (устойчиво, 23 из 28 дней зачётного периода) | ≥ 1 000 | 1 500–2 500 |
| Обращений к решению на DAU (среднесуточно) | ≥ 10 допуск / ≥ 25 номинация | 30+ |
| Реальные пользователи этапа 1 | ≥ 70 | 150 |
| Клиентские интервью этапа 1 | ≥ 30 | 30–40 |

Обращение к компоненту — вызов модели или сервиса в конвейере: реплика ≈ STT + safety + эмоции + retrieval + генерация + TTS (до 6 вызовов), завершение ≈ суммаризация + запись памяти + обновление профиля (3). Одна честная сессия из 8–12 реплик даёт 30–50 обращений. Тестовые и отладочные вызовы исключаются тегом окружения; лог вызовов прозрачен для антифрод-проверки (`REQ-OBS-02`).

### 4.2. Продуктовые

- North star: доля диалогов со снижением напряжения (Δ ≤ −2 по шкале 1–10) ≥ 70 %. Требует `tensionBefore` (`REQ-DLG-07`; сейчас агент его не заполняет).
- Активация: первая завершённая голосовая сессия в день установки ≥ 60 %.
- Удержание: D1 ≥ 45 %, D7 ≥ 25 %, D30 ≥ 15 %.
- Диалогов на DAU ≥ 1,5; завершаемость ритуалов ≥ 50 %.
- Динамика балла теста «Самочувствие» за 4 недели у активных — положительная. «Самочувствие» — наш тест вместо WHO-5 (`self-check`). Баллы в аналитику не уходят, поэтому метрика считается только запросом к `self_check_results` приложения и только по тем, кто дал согласие на хранение результатов.

### 4.3. Безопасность и мост к людям

- Recall кризисного классификатора ≥ 0,9; время до показа помощи < 1 с.
- ≥ 10 % MAU открыли «Люди рядом»; конверсия в контакт отслеживается.
- 100 % пользователей с паттерном переиспользования получили мягкую рекомендацию живого контакта.
