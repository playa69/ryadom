# Сквозные тесты и проверка в браузере

Проверяется **локальный стенд**, не прод: прод — только чтение (скилл `logs`). Набор — `app/e2e` (Playwright, больше
сотни тестов, проекты `desktop` и `mobile` (Pixel 7 с фейковым микрофоном), один воркер, около 10 минут).

## Полный прогон

```bash
cd app
pnpm test:e2e                                                        # весь набор
pnpm --filter @ryadom/e2e exec playwright test --project=mobile app-dialog   # часть: проект и файл
pnpm --filter @ryadom/e2e report                                     # HTML-отчёт из e2e/report
```

`webServer` в `playwright.config.ts` запускает `e2e/scripts/stack.mjs`: compose `e2e/compose.yaml` (PostgreSQL в tmpfs
:55434, Mailpit :1027/:8027, мок агента :8081, с `--build`), миграции, **прод-сборки** приложений и серверы: landing
:3100, admin :3101, api :3102, web :3103, PWA :3104 (`vite preview`). Готовность — `http://127.0.0.1:3100/api/health`;
в конце стенд снимается вместе с томами.

- Долго: запускай в фоне с логом в файл и смотри итог (`grep -v '^\[WebServer\]'` убирает шум стенда).
- **Чужой стенд на этих портах будет переиспользован** (`reuseExistingServer` вне CI) — и тесты пройдут против чужого
  кода. Перед прогоном проверь, что 3100–3104 свободны (`ss -ltn`); занято — не останавливай чужое без спроса.
- Порты зашиты, поэтому параллельные прогоны на одной машине идут по очереди. На машине агента:
  `flock "$XDG_RUNTIME_DIR/ryadom-e2e.lock" pnpm test:e2e`. Рядом с занятым стендом — копия `stack.mjs` и compose
  на сдвинутых портах, а тестам адреса передаются через `E2E_WEB_URL`, `E2E_APP_URL`, `E2E_WEBAPP_URL`, `E2E_PWA_URL`,
  `E2E_MAIL_URL`, `E2E_AGENT_URL`.
- Браузер Playwright для набора — один раз: `pnpm --filter @ryadom/e2e exec playwright install chromium`.

Новые тесты — рядом с похожими в `e2e/tests/`, общие шаги (вход, коды из Mailpit, Telegram) — в `e2e/support/`; в тесте
и PR указывай `REQ-…` из docs/spec.md.

## Ручная проверка (Playwright MCP)

Стенд — скилл `local-dev` (`pnpm dev`) или на машине агента `app-up`. Поверхности: landing, web, PWA и админка; в dev
каждое приложение на своём порту и в корне, без прод-префиксов `/app`, `/pwa`, `/admin`. Вход — анонимно, по коду из
Mailpit или в админку (скилл `local-dev`).

- **Микрофон:** на новом origin `getUserMedia` ждёт ответа на запрос разрешения, и вызов висит до тайм-аута MCP. Сначала
  выдай разрешение: `page.context().grantPermissions(['microphone'], { origin })` (`browser_run_code_unsafe`).
- **Звук:** на машине человека браузер играет голос мока в её реальный выход, то есть в наушники человека: предупреди
  или проверяй без голоса. Headless Chromium без звуковой карты (машина агента) играет в никуда.
- **Скриншоты:** каталог `screenshots/` (в git не попадает), плоско, по приложению и ширине: 390, 820, 1280, 1920.
  Перед тем как показывать — посмотри сам: съехавшая вёрстка или оверлей dev-сервера не скриншот «после».
- **Картинки в PR:** комментарием (`gh pr comment --body-file`), файлы — в отдельной orphan-ветке
  `assets/pr-<N>-screenshots`, не в ветке PR.

## Что не проверяется

Звук на слух и качество голоса, настоящие модели (мок отвечает шаблонами; настоящий агент — `local-dev`), реальные
устройства (iOS до 26, Android WebView, Firefox), Telegram Mini App внутри клиента Telegram, нагрузка. В отчёте
перечисляй непроверенное прямо, не выдавай частичную проверку за полную.
