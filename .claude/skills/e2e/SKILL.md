# Сквозные тесты и проверка в браузере

Проверяется **локальный стенд**, не прод: прод — только чтение (скилл `logs`). Набор — `app/e2e` (Playwright, больше
сотни тестов, проекты `desktop` и `mobile` (Pixel 7 с фейковым микрофоном), один воркер; весь набор — около 10 минут
плюс сборка). Это **не часть `pnpm test`**: юнит-тесты и e2e запускаются разными командами, и turbo пакет
`@ryadom/e2e` в `test` не включает.

## Сколько гонять

- **По ходу задачи** (каждая правка, каждый ответ на комментарий) — только спеки затронутой функции, на обоих проектах:
  `pnpm e2e web-memory app-memory` (имена файлов в `e2e/tests/`). Плюс typecheck и юнит-тесты затронутых пакетов
  (скилл `local-dev`).
- **Перед сдачей** (человек спрашивает «готово?», PR идёт на ревью или слияние) — весь набор `pnpm e2e`, один раз.
- Упал тест чужой функции — перезапусти его отдельно: `web-shell` изредка флакает; падает снова — разбирайся.

## Запуск

```bash
cd app
pnpm e2e                                    # весь набор
pnpm e2e --project=mobile app-dialog        # часть: проект и файлы (аргументы — как у playwright test)
pnpm --filter @ryadom/e2e report            # HTML-отчёт из e2e/report
```

`pnpm e2e` берёт слот worktree (скилл `local-dev`, раздел «Стенд worktree»), проверяет, что порты стенда свободны, и
запускает Playwright. `webServer` в `playwright.config.ts` запускает `e2e/scripts/stack.mjs`: compose-проект
`ryadom-<id>-e2e` (PostgreSQL в tmpfs, Mailpit, мок агента — образ один на машину, тег по хэшу мока), миграции,
**прод-сборки** приложений и серверы: landing, api, web, PWA (`vite preview`); админки в этом стенде нет. Порты —
`20000 + 100·N + 50 + k` (слот 0 — прежние: landing 3100, api 3102, web 3103, PWA 3104, PostgreSQL 55434, Mailpit
1027/8027, мок 8081; полная карта — `local-dev`). Адреса стенда — `pnpm stand:env` (`E2E_*_URL`). Готовность —
`<landing>/api/health`; в конце стек снимается вместе с контейнерами и томами, деревом процессов.

- **Чужой стенд не используется молча.** Стек не стартует, если порт стенда занят: `pnpm e2e` останавливается до
  запуска и называет порты; Playwright сам отказывается, если `<landing>/api/health` уже отвечает. Старая привычка
  «`reuseExistingServer` вне CI» убрана: переиспользовать уже поднятый стек можно только явно, `E2E_REUSE=1`
  (`pnpm stand:up --e2e` поднимает такой стек отдельно, `E2E_REUSE=1 pnpm e2e web-memory` гоняет спеки на нём без
  пересборки, `pnpm stand:down` его снимает). Живой стек своего стенда `pnpm e2e` не трогает: откажется, подскажет
  `E2E_REUSE=1`.
- **Параллельные прогоны из разных worktree** — у каждого свой слот, свои порты и compose-проект: ничего задавать не
  надо. `E2E_PORT_OFFSET` и `COMPOSE_PROJECT_NAME` больше не нужны. Два стенда в одном worktree (разные `STAND_ID`)
  делят папки сборки: запускай их по очереди.
- **Сборки — через Turborepo с кэшем:** приложение, чьи исходники (и исходники его пакетов) не менялись с прошлой
  сборки, приходит из кэша за секунды. `TURBO_CACHE_DIR` даёт один кэш нескольким checkout'ам.
- Упавший прогон не оставляет контейнеры: обёртка `pnpm e2e` снимает проект после Playwright (на Windows он убивает
  стек жёстко, без шанса убрать за собой). Остатки после `kill` — `pnpm stand:down` или `pnpm stand:gc`.
- Долго: запускай в фоне с логом в файл и жди завершения, а не опрашивай в цикле; в логе `grep -v '^\[WebServer\]'`
  убирает шум стенда.
- Браузер Playwright для набора — один раз на версию Playwright:
  `pnpm --filter @ryadom/e2e exec playwright install chromium`.

Новые тесты — рядом с похожими в `e2e/tests/`, общие шаги (вход, коды из Mailpit, Telegram) — в `e2e/support/`, адреса
стенда — константы из `playwright.config.ts` (`APP_URL`, `MAIL_URL`, `AGENT_URL`, `DATABASE_URL`, …), а не зашитые
порты. В тесте и PR указывай требование OpenSpec и `REQ-…` из docs/spec.md, если есть.

**Шаги сценария с доказательством** — вызов `await step(page, '<slug>', '<подпись по-русски>')` из
`e2e/support/evidence.ts` после `expect` шага; без `EVIDENCE=<TASK>` он ничего не делает, так что вызовы остаются в
спеке насовсем. Как снимать и что класть в отчёт — скилл `screenshots`.

## Ручная проверка (Playwright MCP)

Стенд — скилл `local-dev` (`pnpm stand:up`; адреса — `pnpm stand:env`). Поверхности: landing, web, PWA и админка;
в dev каждое приложение на своём порту и в корне, без прод-префиксов `/app`, `/pwa`, `/admin`. Вход — анонимно, по коду
из Mailpit или в админку (скилл `local-dev`).

- **Микрофон:** на новом origin `getUserMedia` ждёт ответа на запрос разрешения, и вызов висит до тайм-аута MCP. Сначала
  выдай разрешение: `page.context().grantPermissions(['microphone'], { origin })` (`browser_run_code_unsafe`).
- **Звук:** на машине человека браузер играет голос мока в её реальный выход, то есть в наушники человека: предупреди
  или проверяй без голоса. Headless Chromium без звуковой карты (машина агента) играет в никуда.
- **Скриншоты** — скилл `screenshots` (скриптом, только нужные экраны), а не руками через MCP.

## Что не проверяется

Звук на слух и качество голоса, настоящие модели (мок отвечает шаблонами; настоящий агент — `local-dev`), реальные
устройства (iOS до 26, Android WebView, Firefox), Telegram Mini App внутри клиента Telegram, нагрузка. В отчёте
перечисляй непроверенное прямо, не выдавай частичную проверку за полную.
