# dialog-share

## Purpose

Ссылка на один разговор: человек создаёт её из журнала или с экрана разговора и отправляет близким или специалисту, получатель без входа читает выбранный разговор, пока ссылка действует. Тексты хранит агент; приложение хранит только хеш токена, срок и границу среза. Функция включена всегда, выключателя нет.

## Requirements

### Requirement: Создание ссылки

API SHALL создавать ссылку на `POST /api/dialogs/{dialogId}/share` с необязательным `ttlHours` из {24, 72, 168} (по умолчанию 24); запрос требует активной сессии владельца. Ответ содержит `shareId`, `url` вида `<адрес веб-клиента>/s/<token>`, `createdAt`, `expiresAt`, `viewCount` и `lastViewedAt`. Токен MUST вычисляться как HMAC от `shareId` секретом сервера и MUST NOT храниться (хранится только его хеш). У разговора MUST быть не более одной активной ссылки, у аккаунта — не более пяти активных, создавать ссылки можно не чаще 10 раз в час. Ссылка всегда открывает веб-клиент, каким бы клиентом её ни создали.

Поверхности: api · agent

#### Scenario: (API) Успешное создание
- **WHEN** владелец просит ссылку на 72 часа для своего разговора с сообщениями
- **THEN** ответ содержит `url` вида `<адрес веб-клиента>/s/<токен>` и `expiresAt` на 72 часа позже `createdAt`
- **AND** в хранилище приложения нет самого токена

#### Scenario: (API) Ссылка уже есть
- **WHEN** у разговора есть активная ссылка и владелец просит создать ещё одну
- **THEN** отказ с кодом `SHARE_EXISTS`, а `GET /api/dialogs/{dialogId}/share` возвращает ту же ссылку

#### Scenario: (API) Недопустимый срок
- **WHEN** `ttlHours` равно 1 или 200
- **THEN** запрос отклонён ответом `400`, ссылка не создаётся

#### Scenario: (API) Чужой, несуществующий или пустой разговор
- **WHEN** запрашивается ссылка на разговор другого аккаунта, несуществующий разговор или разговор без сообщений
- **THEN** отказ с кодом `DIALOG_NOT_FOUND`

#### Scenario: (API) Лимиты
- **WHEN** у аккаунта уже пять активных ссылок
- **THEN** отказ с кодом `SHARE_LIMIT`, новая ссылка не создаётся
- **AND** при более чем 10 созданиях за час API отвечает `429`

#### Scenario: (API) Просроченная ссылка не мешает новой
- **WHEN** срок прежней ссылки разговора истёк, а владелец создаёт новую
- **THEN** новая ссылка создаётся, а истёкшая не занимает место среди активных

### Requirement: Граница среза

Ссылка SHALL открывать только сообщения до последнего сообщения разговора на момент создания; сообщения, появившиеся позже, MUST NOT быть видны по этой ссылке.

Поверхности: api · web

#### Scenario: Разговор продолжился
- **WHEN** после создания ссылки в разговоре появились новые реплики
- **THEN** получатель их не видит, а страница сообщает, что разговор ещё шёл и показан на момент создания ссылки

#### Scenario: Граничное сообщение исчезло
- **WHEN** сообщения, на котором ссылка обрезана, в разговоре больше нет
- **THEN** получатель видит единый отказ, а не весь разговор

### Requirement: Просмотр получателем

`GET /api/shared/{token}` SHALL работать без входа и возвращать `startedAt`, `sharedAt`, `expiresAt`, `isOpen` и список `{role, text, createdAt}`; `isOpen` истинно, если разговор не был завершён к моменту создания ссылки. Ответ MUST NOT содержать аудио, сводку, итог, заголовок, темы, напряжение, идентификаторы разговора и человека, почту и имя. Страница `/s/<token>` веб-клиента SHALL быть только для чтения: шапка с пометкой «Только чтение», плашка «С тобой поделились разговором от <дата>.» (с пометкой «Он ещё шёл, показано на <дата>.» при `isOpen` и словами «Ссылка действует до <дата>.»), сообщения как в живом разговоре, без поля ввода и кнопок записи, и ссылка «Что такое «Рядом»». Каждое успешное открытие увеличивает `viewCount` и обновляет `lastViewedAt`.

Поверхности: api · web

#### Scenario: (Web) Открытие действующей ссылки
- **WHEN** получатель открывает действующую ссылку в чистом браузере
- **THEN** он видит плашку с датой разговора и сроком, сообщения в порядке разговора и подпись «Ты видишь только этот разговор.»

#### Scenario: (API) Содержимое ответа
- **WHEN** запрашивается действующая ссылка
- **THEN** в ответе только поля `startedAt`, `sharedAt`, `expiresAt`, `isOpen` и `messages`

#### Scenario: (Web) Агент недоступен
- **WHEN** агент не отвечает
- **THEN** API отвечает `503`, страница показывает «Не получилось открыть», «Попробуй ещё раз чуть позже.» и кнопку «Повторить», а не «Ссылка больше не действует»

### Requirement: Единый отказ

Неизвестный, просроченный и отозванный токен, ссылка на удалённый или исчезнувший у агента разговор и ссылка заблокированного или удалённого владельца SHALL получать одинаковый ответ `404` с одинаковым телом; причина MUST NOT различаться ни в ответе, ни на странице.

Поверхности: api · web

#### Scenario: (API) Причина не раскрывается
- **WHEN** открывают просроченную, отозванную и выдуманную ссылки
- **THEN** все три ответа `404` с одним и тем же телом

#### Scenario: (Web) Страница отказа
- **WHEN** ссылка не работает по любой из причин
- **THEN** страница показывает «Ссылка больше не действует» и «Срок истёк, ссылку отозвали или разговор удалён. Попроси отправителя создать новую.»

### Requirement: Защита ссылки

Ответы `/api/shared/*` SHALL нести `Cache-Control: no-store`, `Referrer-Policy: no-referrer` и `X-Robots-Tag: noindex, nofollow`; страница `/s/*` веб-клиента SHALL нести `Cache-Control: no-store`, `Referrer-Policy: no-referrer` и признак `noindex, nofollow`. Открытие ссылок MUST ограничиваться 60 запросами в минуту с одного адреса (иначе `429`), чтобы подбор токенов упирался в лимит. Токен MUST NOT попадать в журнал запросов API (путь записывается как `/api/shared/:token`) и в продуктовую аналитику; адрес и User-Agent получателя MUST NOT сохраняться.

Поверхности: api · web

#### Scenario: (API) Заголовки
- **WHEN** запрашивается действующая или недействующая ссылка
- **THEN** присутствуют `Cache-Control: no-store`, `Referrer-Policy: no-referrer` и `X-Robots-Tag: noindex, nofollow`

#### Scenario: (Web) Страница не индексируется и не кэшируется
- **WHEN** открывается `/s/<token>`
- **THEN** ответ страницы содержит `Cache-Control: no-store` и `Referrer-Policy: no-referrer`, а страница не индексируется

#### Scenario: (Web) Превью мессенджера
- **WHEN** ссылку вставляют в мессенджер
- **THEN** превью не содержит текста разговора, потому что текст загружается страницей отдельным запросом

### Requirement: Управление ссылкой

Владелец SHALL в любой момент получать свою активную ссылку на `GET /api/dialogs/{dialogId}/share` (`url`, срок, `viewCount`, `lastViewedAt`; если ссылки нет — успешный ответ с `null`, а не ошибка) и отзывать её на `DELETE /api/dialogs/{dialogId}/share` (идемпотентно). Отозванная ссылка MUST немедленно давать единый отказ. Срок продлить нельзя: нужно отозвать ссылку и создать новую.

Поверхности: api · web · pwa · android · ios · tg

#### Scenario: (API) Ссылки нет
- **WHEN** владелец запрашивает ссылку разговора, которого не делили
- **THEN** успешный ответ с `null`

#### Scenario: Повторное открытие
- **WHEN** владелец снова нажимает «Поделиться» на разговоре с активной ссылкой
- **THEN** он видит ту же ссылку, срок и число просмотров, а не форму создания

#### Scenario: Отзыв
- **WHEN** владелец отзывает ссылку и повторяет отзыв
- **THEN** оба запроса успешны, следующий запрос получателя получает `404`, а владелец может создать новую ссылку

### Requirement: Прекращение действия ссылки

Ссылка MUST прекращать действовать при удалении разговора человеком (`dialog-history`), при удалении разговора агентом по сроку хранения (`data-retention`), при удалении или блокировке аккаунта и по истечении срока; наличие разговора, срок и владелец проверяются при каждом открытии. Строки ссылок MUST удаляться при удалении аккаунта любым способом: человеком, администратором или чисткой неактивных гостей (`account-deletion`, `data-retention`). «Забыть всё» в разделе «Память» ссылки не отзывает: оно стирает только память.

Поверхности: api · agent

#### Scenario: (API) Удаление разговора
- **WHEN** владелец удаляет разговор
- **THEN** ссылка немедленно отзывается и даёт единый отказ

#### Scenario: (API) Удаление аккаунта
- **WHEN** аккаунт владельца удалён: им самим, администратором или чисткой неактивных гостей
- **THEN** все его ссылки дают единый отказ, строки ссылок удалены до того, как удаление объявлено

#### Scenario: (API) Блокировка владельца
- **WHEN** аккаунт владельца заблокирован
- **THEN** открытие ссылки даёт `404`

#### Scenario: (API) Разговор удалён по сроку хранения
- **WHEN** агент удалил разговор по сроку хранения, а срок ссылки ещё не истёк
- **THEN** открытие ссылки даёт `404`

### Requirement: Кнопка «Поделиться» и лист ссылки

Клиенты SHALL предлагать «Поделиться разговором» на записи журнала (если в разговоре есть сообщения) и на экране разговора (когда человек уже что-то сказал): в вебе кнопкой «Поделиться» и окном «Поделиться разговором», в мобильном клиенте значком в панели экрана (на записи журнала на широком экране — кнопкой «Поделиться разговором») и листом. Без активной ссылки лист SHALL предупреждать «Получатель увидит весь текст разговора как есть. Сводка, оценки напряжения и голос не передаются. Ссылку можно отозвать в любой момент.», предлагать срок «24 часа» (по умолчанию), «3 дня» и «7 дней» (в мобильном клиенте «24 ч») и создавать ссылку только по нажатию «Создать ссылку». С активной ссылкой лист SHALL показывать «Ссылка активна», её адрес, «Действует до <дата> · N просмотров», «Скопировать» (в мобильном клиенте «Скопировать ссылку»), «Отправить…» там, где доступно системное «Поделиться», подсказку «Чтобы сменить срок, отзови ссылку и создай новую.» и «Отозвать ссылку» с подтверждением «Да, отозвать» / «Нет».

Поверхности: web · pwa · android · ios · tg

#### Scenario: Выбор срока
- **WHEN** открыт лист «Поделиться» разговора без ссылки
- **THEN** выбран срок «24 часа», доступны «3 дня» и «7 дней», создание — по кнопке «Создать ссылку»

#### Scenario: Нет системного «Поделиться»
- **WHEN** системное «Поделиться» недоступно
- **THEN** есть только «Скопировать», кнопки «Отправить…» нет

#### Scenario: Ошибки листа
- **WHEN** создание или чтение ссылки отказано
- **THEN** лист показывает «У этого разговора уже есть ссылка» (`SHARE_EXISTS`), «Активных ссылок уже пять. Отзови одну из них в другом разговоре» (`SHARE_LIMIT`), «Этот разговор не найден» (`DIALOG_NOT_FOUND`) или «Аккаунт недоступен»
- **AND** при сбое чтения лист предлагает «Повторить»

#### Scenario: (Web) Отправка
- **WHEN** человек нажимает «Отправить…»
- **THEN** системное окно получает текст «Поделился(-ась) разговором с тобой в «Рядом». Ссылка действует до <дата>.» и адрес ссылки

#### Scenario: (PWA, Android, iOS, Telegram) Значок в панели
- **WHEN** в разговоре или записи журнала есть сообщения
- **THEN** в правой части панели есть значок «Поделиться разговором» перед кнопкой SOS

### Requirement: Страницы ссылок закрыты в robots.txt

Файл `robots.txt` сайта SHALL запрещать поисковым роботам страницы ссылок на разговоры (`/s/`, в проде `/app/s/`) в дополнение к заголовку и признаку `noindex` самой страницы (см. «Защита ссылки»). Остальные страницы сайта остаются разрешёнными.

Поверхности: landing · web

#### Scenario: robots.txt
- **WHEN** робот запрашивает `/robots.txt` сайта
- **THEN** путь страниц ссылок запрещён, а остальной сайт разрешён
