# sber500-dashboard Specification

## Purpose
Дашборд метрик команды для организаторов Sber500: три числа по дням без доступа к разговорам и к внутренним системам.

## Requirements

### Requirement: Метрики по дням для Sber500

Сервис дашборда SHALL отдавать по адресу `/dashboard` страницу, а по `/dashboard/api` — JSON с шестью числами за каждые московские сутки (Europe/Moscow) всего периода конкурса: с 2026-11-05 по текущие сутки включительно. Прошлые (завершённые) сутки MUST читаться из неизменяемых снимков; текущие сутки MUST считаться из сырых источников (базы `agent` и `app`, API Langfuse) при каждом обновлении часового кэша, предварительны (числа могут уточняться до закрытия суток) и MUST NOT сохраняться как закрытый снимок. `total_users` текущих суток — `total_users` снимка за предыдущие сутки плюс `new_users` текущих суток.

Из всех метрик MUST быть исключён нереальный трафик: аккаунты, помеченные `test` или `internal` (команда, боты, нагрузочные и автотесты).

Метрики за сутки:

- **`dau`** — уникальные аккаунты, у которых за сутки есть хотя бы одно принятое пользовательское сообщение.
- **`daily_active_account`** — внутренняя метрика: уникальные аккаунты со строго больше чем 10 пользовательскими сообщениями за сутки.
- **`new_users`** — аккаунты (включая анонимные), чьё первое известное сообщение пришлось на эти сутки. Первый известный день аккаунта — минимум из отметки первого сообщения в счётчике реплик, первого сохранённого сообщения в базе агента и первой трассы хода live-диалога в Langfuse; каждый аккаунт считается новым ровно один день за всю историю.
- **`total_users`** — накопленный итог: `total_users` прошлых суток плюс `new_users` этих суток; удалённые аккаунты не вычитаются.
- **`llm_requests`** — логические вызовы API LLM любых провайдеров, инициированные действиями пользователей: ответы в диалоге и вызванные разговором вызовы (итог разговора, извлечение памяти, оценка настроения). Технические ретраи одного логического вызова (в том числе повторная просьба ответить на реплику, оставшуюся без ответа) MUST считаться одним вызовом. Чисто системные операции (прогревы, плановые дайджесты и сводки, служебные проверки) и обращения, не являющиеся вызовом LLM (кризисный фиксированный текст, озвучка), MUST не считаться. Источник — записи вызовов моделей (observations типа GENERATION) в Langfuse с привязкой к аккаунту через их трассы.
- **`tool_requests`** — успешно выполненные логические вызовы агента к серверу памяти (Cognee как MCP/tool server): поиск и чтение (сводка/чанки/зерно согласия), запись (документ и построение графа — один логический вызов записи), удаление (документ, весь датасет). Ошибки и отказы MUST не считаться; технический ретрай внутри одного логического вызова (перелогин после 401 и повтор запроса) MUST не создавать нового вызова; служебные обращения (логин, вспомогательное чтение списка датасетов) MUST не считаться. Действия в UI, не проходящие через агента, не считаются. Источник — записи типа TOOL в Langfuse с привязкой к аккаунту через их трассы. На странице метрика MUST быть подписана «Tool calls — Память»; техническое поле JSON — `tool_requests`.

Сохранённая история сообщений в базе агента неполна (дни 11–16.11.2026 не записаны, провалы есть и в другие дни), поэтому «сообщения» для `dau` и `daily_active_account` MUST считаться по двум источникам вместе: базе агента и восстановленным из Langfuse ходам live-диалога — записям GENERATION `live_turn_voice`/`live_turn_text`, где одна трасса (traceId) с такой записью считается одним сообщением, а привязка к аккаунту идёт через userId трассы. Дедупликация MUST быть по тройке (московские сутки, аккаунт, traceId): повторная GENERATION той же трассы (технический ретрай) MUST NOT увеличивать число сообщений. Ретраи хода (`live_turn_recovery`), вызванные разговором вызовы (итог, настроение, память) и записи TOOL сообщениями MUST не считаться. Для каждой пары «сутки, аккаунт» MUST браться большее из двух чисел (max), а не сумма: источники описывают одни и те же ходы, и сумма считала бы сохранённые сообщения дважды. Объединённый расчёт MUST быть единым для снимков, backfill и предварительных текущих суток. Это приближение: ход, потерянный обоими источниками по-разному, недосчитывается; завышения за счёт двойного счёта нет.

Агент SHALL создавать на каждый логический вызов к серверу памяти одно TOOL-наблюдение Langfuse: имя операции, исход (успех/ошибка), привязка к трассе с аккаунтом человека; содержимое памяти и тексты MUST NOT попадать в наблюдение.

Наружу MUST уходить только суммы: ни текстов, ни идентификаторов людей.

Поверхности: dashboard · agent

#### Scenario: Страница
- **WHEN** организатор открывает `/dashboard` с верными логином и паролем
- **THEN** видит графики и таблицу за каждые сутки конкурса с 2026-11-05 по текущие московские сутки включительно с шестью метриками, определения метрик и время обновления; текущие сутки помечены как предварительные

#### Scenario: JSON
- **WHEN** запрос `GET /dashboard/api` с верными логином и паролем
- **THEN** ответ содержит период с 2026-11-05 по текущие московские сутки включительно, время обновления, определения и по каждому дню `date`, `dau`, `llm_requests`, `tool_requests`, `total_users`, `new_users` и `daily_active_account`

#### Scenario: Текущие сутки предварительные
- **WHEN** текущие московские сутки ещё не закрыты
- **THEN** они показаны на странице и в JSON с реальными предварительными данными из сырых источников (не нулевой заглушкой), обновляются при каждом обновлении часового кэша и не сохраняются как снимок; `new_users` текущих суток при этом MUST учитывать первый известный день аккаунта по всей истории конкурса (включая ранние трассы Langfuse, свёрнутые постранично без загрузки истории в память), а не только записи этих суток: аккаунт, говоривший раньше, не становится «новым» сегодня

#### Scenario: Сутки без активности
- **WHEN** за сутки нет ни одного пользовательского сообщения
- **THEN** у этих суток `dau`, `daily_active_account`, `new_users`, `llm_requests` и `tool_requests` равны 0, а `total_users` равен итогу накануне

#### Scenario: Тестовый трафик исключён
- **WHEN** за сутки сообщения, вызовы LLM и вызовы памяти делали только аккаунты с типом трафика `test` или `internal`
- **THEN** у этих суток `dau`, `daily_active_account`, `new_users`, `llm_requests` и `tool_requests` равны 0 и `total_users` не растёт

#### Scenario: Накопленный итог не уменьшается
- **WHEN** аккаунт, чьё первое сообщение было в прошлые сутки, удалён
- **THEN** `total_users` прошлых и будущих суток не уменьшается

#### Scenario: Ретраи — один вызов
- **WHEN** один логический вызов LLM или вызов к серверу памяти потребовал технических ретраев (повтор внутри клиента, повторная просьба ответить на реплику, оставшуюся без ответа, перелогин после 401 и повтор запроса)
- **THEN** в `llm_requests` и `tool_requests` этих суток он посчитан один раз

#### Scenario: Ошибки вызовов памяти не считаются
- **WHEN** вызов агента к серверу памяти завершился ошибкой или отказом
- **THEN** в `tool_requests` он не посчитан, а успешные вызовы этих суток посчитаны

#### Scenario: Вызванные разговором вызовы считаются, системные — нет
- **WHEN** после разговора агент построил итог, извлёк память и оценил настроение, а также в эти сутки прошли прогрев и плановая сводка
- **THEN** итог, извлечение памяти и оценка настроения посчитаны в `llm_requests`, а прогрев и плановая сводка — нет

#### Scenario: Сообщения восстанавливаются из трейсинга
- **WHEN** за сутки часть пользовательских сообщений не сохранилась в базе агента, но трассы ходов live-диалога есть в Langfuse
- **THEN** `dau`, `daily_active_account` и `new_users` считаются по объединению базы и трейсинга: ход, видный только в Langfuse, учтён; ход, видный в обоих источниках, посчитан один раз (для пары «сутки, аккаунт» — большее из двух чисел); повторная запись GENERATION той же трассы и ретрай хода нового сообщения не создают; то же объединение действует для предварительных текущих суток

### Requirement: Вход и нагрузка

Дашборд SHALL пускать только по basic auth с одной учётной записью. Неудачные входы MUST быть ограничены: не больше 10 в минуту с одного IP. Запросы к странице и JSON MUST обслуживаться из кэша в памяти (не дольше часа): завершённые сутки кэш читает из хранилища снимков, текущие сутки — из сырых источников (базы `agent` и `app`, API Langfuse); обращений к хранилищу и сырым источникам на каждый запрос страницы быть не должно.

Поверхности: dashboard

#### Scenario: Без пароля
- **WHEN** запрос без логина и пароля или с неверными
- **THEN** ответ 401, данных нет

#### Scenario: Перебор пароля
- **WHEN** с одного IP за минуту больше 10 неверных входов
- **THEN** до конца минуты этот IP получает 429

#### Scenario: Повторные открытия
- **WHEN** страницу открывают много раз в течение часа
- **THEN** хранилище снимков и сырые источники запрашиваются не чаще одного раза — при обновлении часового кэша

#### Scenario: Источник недоступен
- **WHEN** чтение хранилища снимков или сырых источников для текущих суток не удалось, а прошлый результат в памяти есть
- **THEN** отдаётся прошлый результат; если прошлого нет — 503

### Requirement: Суточные снимки метрик

Сервис дашборда SHALL после полуночи по Москве закрывать прошедшие сутки снимком: шесть метрик считаются из сырых источников один раз, сохраняются в собственное хранилище дашборда и дальше MUST NOT пересчитываться и перезаписываться. Хранилище MUST содержать только агрегаты: дату и целые числа метрик — без текстов разговоров и идентификаторов аккаунтов. Запись в базы `agent` и `app` MUST отсутствовать. Снимки закрывают только завершённые сутки: текущие сутки MUST NOT сохраняться снимком, их предварительные данные описаны в требовании «Метрики по дням для Sber500». Завершённый день без снимка (сервис был выключен, история до выката) MUST закрываться досчётом из сырых источников один раз.

Поверхности: dashboard

#### Scenario: Закрытие суток
- **WHEN** наступает новая календарная дата по Москве
- **THEN** в течение первого часа сутки за вчера сохраняются снимком и показываются на странице

#### Scenario: Удаление не переписывает прошлое
- **WHEN** после закрытия суток человек удалил разговор или аккаунт
- **THEN** снимок этих суток и числа на странице за них не меняются

#### Scenario: Пробел закрывается сам
- **WHEN** сервис был выключен и снимка за одни из завершённых суток периода нет
- **THEN** после запуска этот день досчитывается из сырых источников, сохраняется и появляется на странице

#### Scenario: Восстановление истории
- **WHEN** выполняется первоначальное наполнение хранилища (backfill)
- **THEN** снимки за прошлые завершённые сутки считаются из сырых источников: `dau`/`daily_active_account` — по объединению базы агента и восстановленных из Langfuse ходов (max по паре «сутки, аккаунт»), `new_users` — по первому известному сообщению аккаунта (минимум из отметки первого сообщения, первого сохранённого сообщения и первой live-turn трассы Langfuse, дедупликация по аккаунту, в том числе через границу окон выгрузки), `llm_requests` — из записей вызовов моделей Langfuse в пределах их доступной истории, `tool_requests` — из записей TOOL Langfuse начиная со дня включения их записи агентом; текущие сутки снимком не пишутся; уже существующие снимки не перезаписываются, а дни до начала точного учёта честно помечены на странице

#### Scenario: Пересчёт снимков, посчитанных по неполной базе
- **WHEN** снимки прошлых суток записаны версией без восстановления сообщений из трейсинга и занижены (дни 05.11–16.11.2026)
- **THEN** они пересчитываются только после отдельного разрешения владельца на удаление строк за эти дни: удаление выполняется вручную, затем backfill новой версии закрывает дни заново; без разрешения существующие снимки не изменяются

#### Scenario: Хранятся только агрегаты
- **WHEN** снимок за сутки сохранён
- **THEN** в хранилище дашборда есть только дата, значения шести метрик и время расчёта — ни текстов, ни идентификаторов людей

### Requirement: Восстановленные Tool calls Cognee

Дашборд SHALL дополнять `tool_requests` фактически подтверждёнными успешными операциями Cognee за 05.11–17.11.2026: успешными `search`, парами `add+cognify` (одна пара — один вызов записи) и успешными удалениями. За 05.11–09.11 источник — `pipeline_runs`, за 10.11–17.11 — HTTP access-логи. Значения дня MUST быть не меньше восстановленного числа и не меньше числа TOOL-наблюдений Langfuse (максимум, не сумма). Собственные диагностические вызовы `postdeploy-synthetic-*` MUST NOT учитываться.

Восстановленные значения MUST храниться отдельно от неизменяемых снимков Langfuse как суточные агрегаты без идентификаторов и текстов людей. По решению владельца восстановление включает все фактические вызовы без сопоставления с аккаунтами и проверки `traffic_type`; это исключение из общего правила исключения test/internal относится только к восстановленным историческим Tool calls.

Поверхности: dashboard

#### Scenario: История Tool calls заполнена
- **WHEN** организатор открывает страницу или JSON дашборда
- **THEN** за 05.11–17.11.2026 отображаются подтверждённые журналами Cognee Tool calls: 13, 32, 2, 50, 92, 43, 44, 8, 40, 2, 66, 2 и 1 соответственно; ошибочные HTTP-вызовы и диагностические `postdeploy-synthetic-*` не увеличивают числа

#### Scenario: Восстановление не дублирует Langfuse
- **WHEN** за одни сутки есть восстановленное число Cognee и TOOL-наблюдения Langfuse
- **THEN** в `tool_requests` берётся большее из двух чисел, а не их сумма; исходный снимок Langfuse не перезаписывается

### Requirement: Ежедневная выгрузка и retention для Sber500

`REQ-OBS-06`. Сервис SHALL отдавать агрегаты в JSON по `GET /api/v1/metrics/daily` с отдельным Bearer-токеном. Обязательные `date_from` и `date_to` задают включительный диапазон до 90 календарных суток в `Europe/Moscow`; `date_to` не позже текущих суток. Идентификаторы и тексты пользователей MUST NOT передаваться или храниться в агрегатах выгрузки.

Поверхности: api

#### Scenario: Формат ответа

- **WHEN** запрос авторизован и даты валидны
- **THEN** JSON содержит `startup_id`, `timezone`, `generated_at` и массив `data` по порядку дат. Каждая строка содержит `date`, `dau`, `llm_requests`, `tool_requests`, `total_users`, `new_users`, `retained_d1`, `retained_d3`, `retained_d7`, `retained_d14` и `is_final`. Последнее поле относится к дате строки.

#### Scenario: Защита и проверка запроса

- **WHEN** токен отсутствует или неверен, даты отсутствуют либо диапазон невалиден, или исчерпан лимит
- **THEN** сервис возвращает соответственно 401, 400 или 429 с JSON-полем `error` и без метрик

### Requirement: Когорты регистрации в выгрузке Sber500

`new_users` SHALL считать аккаунты, созданные в эти сутки, включая анонимные. `total_users` SHALL считать накопленное число регистраций. `retained_dN` SHALL считать уникальные аккаунты из когорты регистрации с сообщением агенту ровно в день `date + N`, по тем же источникам и правилам, что и DAU. День определяется по Москве. Аккаунты с метками `test` и `internal` исключаются.

Поверхности: api

#### Scenario: Сообщения ровно в целевые сутки

- **WHEN** аккаунт зарегистрировался 16 ноября и отправил несколько сообщений 23 ноября
- **THEN** в строке за 16 ноября `retained_d7` остаётся `null` в течение 23 ноября и после закрытия суток учитывает этот аккаунт ровно один раз

#### Scenario: История и дни без активности

- **WHEN** коллектор запрашивает последние 15 завершённых суток
- **THEN** ответ содержит 15 строк, зрелые значения retention рассчитаны и за прошлые даты, пустой завершённый день присутствует с нулевыми дневными счётчиками
- **AND** целевые сутки, которые идут или не наступили, дают `null`, закрытые целевые сутки без возвратов дают 0

### Requirement: Таблица удержания на дашборде Sber500

Страница `/dashboard` SHALL показывать число регистраций и D1, D3, D7 и D14 по московским датам когорт. Таблица SHALL использовать агрегаты ежедневной выгрузки. Доступ к странице использует действующий вход дашборда.

Поверхности: web

#### Scenario: Закрытые и незакрытые целевые сутки

- **WHEN** пользователь открывает таблицу удержания
- **THEN** закрытые целевые сутки отображаются числом, включая 0, а незакрытые — прочерком с пояснением

#### Scenario: Агрегаты ещё готовятся

- **WHEN** агрегаты удержания пока недоступны
- **THEN** раздел сообщает об этом, а остальные метрики страницы остаются доступны
