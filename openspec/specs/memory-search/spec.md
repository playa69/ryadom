# memory-search

## Purpose
Рядом может вспомнить дословно то, что человек сам говорил в прошлых разговорах: из его реплик строится личный индекс, и по ходу разговора агент ищет в нём слова, близкие к сказанному. Поиск работает вместе с заметками (capability `memory-notes`), у него свой переключатель, а удалённое человеком не возвращается ни из заметок, ни из прошлых разговоров.

## Requirements

### Requirement: Переключатель «Опираться на прошлые разговоры»
Поиск по прошлым разговорам SHALL управляться отдельным переключателем «Опираться на прошлые разговоры» (подсказка: «Рядом может вспомнить, что ты говорил раньше, дословно»). Он включён по умолчанию, меняется без листа согласия вызовом `PUT /api/memory/settings` с `chatSearchEnabled`, а значение приходит в `GET /api/memory` как `chatSearchEnabled`. Пока «Память» выключена или недоступна, переключатель неактивен и поиск не используется. Выключение MUST удалять индекс прошлых разговоров человека целиком (через очередь с повторами), останавливать поиск в разговоре сразу и снимать ожидающие операции индекса; журнал и заметки остаются. Включение MUST пересобирать индекс в фоне из всех завершённых разговоров журнала, которые не удалены и не «Без памяти». Отдельного показа хода пересборки нет.

Поверхности: agent · api · web · pwa · android · ios · tg

#### Scenario: Выключить поиск
- **WHEN** человек выключил «Опираться на прошлые разговоры»
- **THEN** индекс удаляется целиком, находок в разговоре больше нет, журнал и заметки на месте
- **AND** открытая сессия голоса к следующему ходу открывается заново без прежних находок (см. capability `dialog-voice`)

#### Scenario: Включить поиск
- **WHEN** человек снова включил «Опираться на прошлые разговоры»
- **THEN** индекс в фоне пересобирается из завершённых разговоров журнала, кроме удалённых и «Без памяти»

#### Scenario: (web) Память на паузе
- **WHEN** «Память» выключена
- **THEN** переключатель «Опираться на прошлые разговоры» неактивен, ранее выбранное значение сохранено

#### Scenario: По умолчанию включён
- **WHEN** человек включает память впервые
- **THEN** `chatSearchEnabled` равен `true`

### Requirement: Что попадает в индекс прошлых разговоров
Для завершённого разговора агент SHALL строить один документ с репликами человека, начинающийся строкой «Реплики человека в разговоре от YYYY-MM-DD:». Реплики агента MUST NOT попадать в индекс. Каждая реплика проходит маскирование персональных данных (почта, ссылки, ники, телефоны, карты, документы, адреса, длинные числа заменяются метками вроде `[телефон]`). Из документа MUST исключаться: реплики с признаками кризиса (набор признаков кризисного протокола, см. capability `crisis-safety`); реплики с диагнозами, лекарствами, самоповреждением, документами и платёжным (то же «никогда», что у заметок, см. capability `memory-notes`); просьбы вроде «забудь», «убери», «поправь», в которых названа тема, которую человек хочет убрать; реплики, в которых после маскирования остались карта или документ; реплики, из которых человек убрал заметку (см. «Удалённая заметка не возвращается»). Если после этого осталось меньше двух реплик, документа нет. Индекс принадлежит человеку: поиск идёт только по его собственному индексу. Индекс производный: его можно пересобрать из журнала. Разговор «Без памяти» MUST NOT попадать в индекс.

Поверхности: agent

#### Scenario: Реплики агента не в индексе
- **WHEN** разговор завершён, и в индексе выполнен поиск по фразе, которую сказал только агент
- **THEN** поиск её не находит

#### Scenario: Телефон замаскирован
- **WHEN** человек в разговоре назвал номер телефона
- **THEN** в документе вместо номера метка `[телефон]`

#### Scenario: Кризисная реплика
- **WHEN** среди реплик есть та, на которой сработали признаки кризиса
- **THEN** этой реплики в документе нет, остальные обычные реплики разговора есть

#### Scenario: Мало реплик
- **WHEN** после исключений осталась одна реплика человека
- **THEN** документ не создаётся

#### Scenario: «Без памяти»
- **WHEN** разговор начат «Без памяти»
- **THEN** его реплик нет в индексе

### Requirement: Когда разговор попадает в индекс
Разговор SHALL попадать в индекс после завершения любым путём (в том числе автозавершения брошенного разговора), если к этому моменту память включена, поиск включён, а разговор не «Без памяти». Документ строится из базы в момент выполнения через очередь с повторами: операция ждёт 5 секунд, чтобы разговор успел записаться, очередь просматривается раз в 10 секунд (и сразу после постановки удаления), за проход выполняется до 10 операций. Операция, которая не удалась, повторяется через 1, 2, 4 минуты и так далее; пауза между попытками не больше часа. Повтор индексации уже проиндексированного разговора ничего не меняет. Тексты разговоров в очередь не кладутся. Разговор, удалённый за время ожидания или выполнения, MUST NOT попасть в индекс: документ убирается. Разговор, завершённый при паузе памяти или выключенном поиске, не индексируется; поиск включится для него только пересборкой при включении переключателя.

Поверхности: agent

#### Scenario: Индекс после разговора
- **WHEN** человек завершил разговор с несколькими репликами, а память и поиск включены
- **THEN** через несколько секунд документ разговора в индексе, и в следующих разговорах его реплики могут находиться

#### Scenario: Индекс недоступен
- **WHEN** индекс не отвечает в момент завершения разговора
- **THEN** разговор и заметки работают как обычно, операция повторяется позже, пока не получится

#### Scenario: Разговор удалён до индексации
- **WHEN** человек удалил разговор в течение 5 секунд после его завершения
- **THEN** документ в индекс не попадает

#### Scenario: Поиск выключен
- **WHEN** разговор завершается при выключенном «Опираться на прошлые разговоры»
- **THEN** операции индекса нет

### Requirement: Находки из прошлых разговоров в разговоре
Пока «Память» и «Опираться на прошлые разговоры» включены, агент SHALL после каждой реплики человека искать в его индексе реплики, близкие по смыслу, в фоне и не задерживая ход. Найденное (без реплик, подавленных удалением заметки), не больше 800 знаков, попадает в блок памяти под заголовком «Из прошлых разговоров (слова человека, дословно):» при ближайшей смене сессии голоса (см. capability `dialog-voice`). Остаётся последняя непустая находка. Сбой, медленный ответ или недоступность индекса MUST NOT мешать ходу: берётся то, что есть. На паузе, при выключенном поиске и в разговоре «Без памяти» находки в блок не попадают. Реплики и заметки одного человека MUST NOT находиться у другого.

Поверхности: agent

#### Scenario: Вспомнить сказанное раньше
- **WHEN** две недели назад человек рассказывал о ссоре с сестрой, а сейчас снова говорит о сестре
- **THEN** в блоке памяти следующей сессии есть дословная реплика того разговора с датой разговора из заголовка документа

#### Scenario: Поиск упал
- **WHEN** поиск по индексу отвечает ошибкой
- **THEN** ход не задерживается, блок памяти собирается из заметок и прежней находки

#### Scenario: Пауза
- **WHEN** «Память» на паузе
- **THEN** поиск по реплике не выполняется, блока памяти нет

### Requirement: Удалённая заметка не возвращается из прошлых разговоров
Реплика, на которой выросла заметка, MUST перестать приходить из поиска, когда заметку убирают: удалением, правкой, «Удалить всю память» или выключением «Запоминать чувствительное». От такой реплики хранится только отпечаток, без текста: по нему находки с этой репликой отбрасываются сразу при выдаче, а документ разговора пересобирается без неё через очередь (если реплик осталось меньше двух, документа нет). При «Удалить всю память» индекс удаляется целиком, и при последующей пересборке подавленные реплики в него не возвращаются. Отпечаток хранится, пока жив разговор-источник; удаление разговора или аккаунта стирает его. Заметка, написанная не из реплики, ничего не подавляет.

Поверхности: agent

#### Scenario: Удалённое не возвращается
- **WHEN** человек удалил заметку «Не хочет обсуждать отца», а разговор, где он это сказал, ещё хранится, и потом говорит о семье
- **THEN** агент не получает из поиска ту реплику дословно, а в документе разговора её больше нет; остальные реплики разговора находятся

#### Scenario: Правка тоже подавляет
- **WHEN** человек поправил заметку
- **THEN** реплика, на которой выросла прежняя формулировка, больше не приходит из поиска

#### Scenario: Только отпечаток
- **WHEN** заметка удалена
- **THEN** в базе остаётся отпечаток реплики без её текста, сама реплика остаётся в журнале

### Requirement: Удалённый разговор уходит из поиска
Когда разговор удаляется (человеком из журнала или по сроку хранения; сам маршрут удаления и сброс итога недели задаёт capability `dialog-history`), агент SHALL удалять его документ из индекса жёстко, вместе с производными данными, через очередь с повторами (пауза растёт от минуты и не превышает часа; недоступность индекса не мешает удалить сам разговор), и сразу удалять отпечатки его реплик. Заметки из разговора MUST оставаться (см. capability `memory-notes`). Неразобранные реплики удаляемого разговора в заметки не идут, а последняя находка сбрасывается и пересоберётся по следующей реплике. Открытая сессия голоса к следующему ходу открывается заново без удалённого (см. capability `dialog-voice`). Поиск по уникальной фразе удалённого разговора MUST ничего не находить. Стирание аккаунта удаляет индекс до ответа `204` (см. capability `account-deletion`).

Поверхности: agent

#### Scenario: Удалить разговор
- **WHEN** человек удалил разговор, в котором рассказал о сестре
- **THEN** разговора нет в журнале и в поиске, а заметка «Есть сестра Маша» осталась в листе

#### Scenario: Уникальная фраза
- **WHEN** разговор с уникальной фразой удалён (вручную или по сроку), и выполнен поиск по этой фразе
- **THEN** поиск ничего не находит

#### Scenario: Индекс недоступен при удалении разговора
- **WHEN** человек удаляет разговор, а индекс не отвечает
- **THEN** разговор удалён из журнала сразу, а удаление документа повторяется в очереди, пока не получится

### Requirement: Поиск не ломает память при сбоях
Недоступность индекса MUST NOT ломать заметки, их показ, правку, удаление и разговор. Без индекса блок памяти собирается без находок, а операции индекса (добавление, удаление документа, удаление индекса) ждут в очереди с повторами. Если индекс не настроен, `GET /api/memory` отвечает `available: false`, и память не используется (см. capability `memory-notes`). `/health/ready` агента показывает поле `memory` со значением `on` или `unavailable`.

Поверхности: agent · api

#### Scenario: Индекс недоступен час
- **WHEN** индекс недоступен час
- **THEN** заметки пишутся и видны, разговор идёт с блоком из заметок, а индекс догоняет после восстановления

#### Scenario: Удаление всей памяти при сбое
- **WHEN** человек подтвердил «Удалить всю память», а индекс не отвечает
- **THEN** заметки удалены сразу, удаление индекса повторяется в очереди
