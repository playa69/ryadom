# dialog-history

## Purpose

Журнал — прошлые разговоры человека: список, чтение одной записи и удаление разговора. Текст хранит агент, приложение его только показывает; аудио не сохраняется. Журнал живёт внутри раздела «Дневник» (сегмент «Журнал»), итог разговора в записи описан в capability `dialog-recaps`, ссылка «Поделиться» — в `dialog-share`.

## Requirements

### Requirement: Список разговоров в API

API SHALL отдавать человеку его разговоры на `GET /api/dialogs`: новые сверху по времени начала, страницами по `limit` (1–50, по умолчанию 20) и курсору `before`, который берётся из `next` прошлой страницы; `next` равен `null` на последней странице. Каждая запись содержит `dialogId`, `startedAt`, `endedAt` (`null` у открытого разговора), `summary` (`title`, `themes`, `tensionBefore`, `tensionAfter` и поля итога из capability `dialog-recaps`, у разговора без сводки — `null`) и `memoryMode` (`on` или `off`).

Поверхности: api · agent

#### Scenario: (API) Первая страница
- **WHEN** у человека больше 20 разговоров и клиент запрашивает список без параметров
- **THEN** приходят 20 самых новых разговоров и курсор `next`
- **AND** запрос с `before=<next>` возвращает следующие, более старые, а последняя страница приходит с `next: null`

#### Scenario: (API) Заблокированный или удалённый аккаунт
- **WHEN** список запрашивает аккаунт, которого нет или который заблокирован
- **THEN** ответ-отказ с кодом `USER_NOT_FOUND` или `USER_INACTIVE`

#### Scenario: (API) Агент недоступен
- **WHEN** агент не отвечает
- **THEN** API отвечает `503`, а клиент показывает «Сейчас я не могу ответить. Если тяжело — линии помощи ниже»

### Requirement: Журнал внутри «Дневника»

Клиенты SHALL показывать журнал сегментом «Журнал» раздела «Дневник»: в вебе страницы `/diary/journal` (список) и `/diary/journal/<dialogId>` (запись), в мобильном клиенте экраны `/diary/journal/` и `/diary/journal/<dialogId>/`; старые адреса `/journal…` MUST перенаправлять на `/diary/journal…`. Отдельной вкладки «Журнал» нет.

Поверхности: web · pwa · android · ios · tg

#### Scenario: (Web) Старая ссылка
- **WHEN** открыт `/journal` или `/journal/<dialogId>`
- **THEN** открывается `/diary/journal` или `/diary/journal/<dialogId>`

#### Scenario: (PWA, Android, iOS, Telegram) Старый адрес записи
- **WHEN** мобильный клиент открывает маршрут `/journal/<dialogId>/` (сохранённая история переходов, внешняя ссылка)
- **THEN** он открывается как `/diary/journal/<dialogId>/`

### Requirement: Строка списка разговоров

Каждая строка списка SHALL показывать заголовок разговора (`summary.title`, а без сводки — слово «Разговор»), темы сводки через запятую, если они есть, дату и время начала (день и месяц словом, затем время в 24-часовом формате: «1 октября, 14:30») и подпись напряжения. Подпись напряжения MUST быть «N → M» при известных `tensionBefore` и `tensionAfter`, «было N» при известном только `tensionBefore` и MUST отсутствовать, если `tensionBefore` неизвестно. Разговор «Без памяти» (`memoryMode: off` при `saved` не `false`) SHALL быть помечен словами «Без памяти» (правила режима — в capability `memory-notes`; срок хранения у такого разговора общий, 90 дней после последнего сообщения, и подписи про другой срок нет). Пометка не сохранённого разговора (`saved: false`) описана в требовании «Пометка не сохранённого разговора».

Поверхности: web · pwa · android · ios · tg

#### Scenario: Разговор со сводкой
- **WHEN** в списке разговор с `title`, `themes`, `tensionBefore: 7` и `tensionAfter: 4`
- **THEN** строка показывает заголовок, темы, дату и время начала и подпись «7 → 4»

#### Scenario: Разговор без сводки
- **WHEN** у разговора `summary` равно `null`
- **THEN** строка показывает «Разговор» и дату начала, без тем и без подписи напряжения

#### Scenario: Напряжение «до» неизвестно
- **WHEN** у сводки `tensionBefore` равно `null`, а `tensionAfter` задано
- **THEN** подписи напряжения в строке нет

#### Scenario: Разговор «Без памяти»
- **WHEN** у разговора `memoryMode` равно `off`, а `saved` не равно `false`
- **THEN** (Web) рядом с датой плашка «Без памяти» с подсказкой «Рядом ничего не запомнит из этого разговора»
- **AND** (PWA) под заголовком дата и подпись «Без памяти»
- **AND** подписи про удаление через сутки нет: разговор живёт по общему сроку хранения
- **AND** заголовок, итог и текст такого разговора в журнале видны и открываются как у обычного

### Requirement: Пометка не сохранённого разговора
Список и запись журнала SHALL отдавать поле `saved`; `saved: false` — разговор, который человек не велел сохранять («Не сохранять этот разговор», capability `dialog`): у него нет сводки (`summary: null`) и сообщений, остаётся только пометка. Строка списка SHALL называться «Разговор не сохранён» (вместо заголовка и тем) и показывать дату начала; плашки «Без памяти» на ней нет. Запись такого разговора SHALL показывать вместо сводки, итога и текста карточку «Был разговор, который не сохранён по твоему желанию» с датой, временем начала и длительностью, если разговор завершён, и единственным действием «Удалить пометку». Пометка живёт по общему сроку хранения разговоров (capability `data-retention`) и удаляется человеком так же, как обычный разговор; продолжить её, написать итог или поделиться ею нельзя.

Поверхности: api · web · pwa · android · ios · tg

#### Scenario: Пометка в списке
- **WHEN** человек закончил разговор с галочкой «Не сохранять этот разговор» и открыл журнал
- **THEN** в списке строка «Разговор не сохранён» с датой, без тем, напряжения и плашки «Без памяти»

#### Scenario: Запись пометки
- **WHEN** человек открывает такую строку
- **THEN** вместо текста карточка «Был разговор, который не сохранён по твоему желанию» с датой, временем и длительностью, без итога и без кнопки «Написать итог»
- **AND** единственное действие — «Удалить пометку»

#### Scenario: Удаление пометки
- **WHEN** человек нажимает «Удалить пометку» и подтверждает
- **THEN** запись исчезает из журнала, как после удаления обычного разговора

#### Scenario: Перезапуск агента
- **WHEN** разговор не успел завершиться, потому что агент перезапустился
- **THEN** в журнале его нет

### Requirement: Группировка по дням (веб)

Страница «Все разговоры» и боковая история веба SHALL делить разговоры по календарному дню начала в местном времени на группы «Сегодня», «Вчера», «Последние 7 дней» и «Ранее» именно в таком порядке; пустые группы MUST NOT показываться, порядок внутри группы остаётся таким, как вернул сервер, а разговор с нечитаемой датой начала попадает в «Ранее».

Поверхности: web

#### Scenario: (Web) Граница дня
- **WHEN** есть разговор, начатый сегодня в 00:05, и разговор, начатый вчера в 23:50
- **THEN** первый стоит в группе «Сегодня», второй — в «Вчера»; граница проходит по календарной полуночи, а не по окну в 24 часа

#### Scenario: (Web) Граница недели
- **WHEN** один разговор начат в начале дня семь календарных дней назад, а другой — за минуту до этого
- **THEN** первый в «Последние 7 дней», второй в «Ранее»

#### Scenario: (Web) Пустые группы
- **WHEN** все разговоры начаты сегодня
- **THEN** показана только группа «Сегодня»

### Requirement: Список в мобильном клиенте

Мобильный клиент SHALL показывать журнал одним списком под заголовком «Разговоры» в порядке ответа сервера, без групп по дням. Ниже 1024 px нажатие на строку SHALL открывать запись отдельным экраном со ссылкой назад «Журнал»; от 1024 px список остаётся слева, запись открывается справа в той же вкладке, а выбранная строка подсвечена. Мобильный клиент показывает только первую страницу списка (20 самых новых разговоров), «Показать ещё» в нём нет.

Поверхности: pwa · android · ios · tg

#### Scenario: (PWA, Android, iOS, Telegram) Телефон
- **WHEN** окно уже 1024 px и человек нажимает строку
- **THEN** открывается экран записи со ссылкой назад «Журнал»

#### Scenario: (PWA, Android, iOS, Telegram) Широкий экран
- **WHEN** окно не уже 1024 px и человек нажимает строку
- **THEN** запись показывается справа с названием и датой над сводкой, строка в списке подсвечена, переход на другой экран не выполняется
- **AND** пока ничего не выбрано, правая область предлагает «Выбери разговор слева»

#### Scenario: (PWA, Android, iOS, Telegram) Размер окна меняется с открытой записью
- **WHEN** окно сужается ниже 1024 px при открытой записи справа, или расширяется до 1024 px на экране записи
- **THEN** та же запись открывается отдельным экраном без анимации, либо возвращается список с этой записью справа

### Requirement: Боковая история в вебе

Боковая колонка веба SHALL показывать загруженные разговоры теми же группами по дням, что и «Все разговоры»: в строке только заголовок (или «Разговор»), у открытого разговора — цветная точка с доступным именем «Разговор не завершён». Под списком SHALL стоять ссылка «Все разговоры» на `/diary/journal`, пока в списке есть хотя бы один разговор. В свёрнутой колонке история и ссылка MUST NOT показываться.

Поверхности: web

#### Scenario: (Web) Пустая история
- **WHEN** список загружен и пуст
- **THEN** колонка показывает «Здесь появятся твои разговоры. Аудио не сохраняется — только текст.», ссылки «Все разговоры» нет

#### Scenario: (Web) Загрузка
- **WHEN** список ещё не загружен и ошибки нет
- **THEN** колонка показывает четыре заглушки строк с признаком занятости

#### Scenario: (Web) Открытая запись отмечена
- **WHEN** открыта запись, на которую есть строка в истории
- **THEN** эта строка отмечена как текущая страница (`aria-current="page"`)

#### Scenario: (Web) Ошибка обновления
- **WHEN** список уже загружен, а обновление не удалось
- **THEN** загруженные группы остаются, под ними показан текст ошибки

### Requirement: Открытый и завершённый разговор

Разговор без `endedAt` SHALL считаться открытым; у человека не бывает больше одного открытого разговора. В вебе строка открытого разговора MUST вести на `/dialog/<dialogId>` (продолжение разговора) и быть помечена «Не завершён» (на странице «Все разговоры»), а строка завершённого — на `/diary/journal/<dialogId>`, где запись читается только для чтения. Мобильный клиент открывает запись по любой строке.

Поверхности: web · pwa · android · ios · tg

#### Scenario: (Web) Открытый разговор
- **WHEN** в списке есть разговор с `endedAt: null`
- **THEN** его строка на странице «Все разговоры» помечена «Не завершён» и ведёт на `/dialog/<dialogId>`

#### Scenario: (Web) Завершённый разговор
- **WHEN** в списке есть разговор с заданным `endedAt`
- **THEN** его строка без пометки «Не завершён» ведёт на `/diary/journal/<dialogId>` обычной ссылкой, которую можно открыть в новой вкладке

#### Scenario: (PWA, Android, iOS, Telegram) Строка любого разговора
- **WHEN** человек нажимает строку открытого или завершённого разговора
- **THEN** открывается запись журнала, а продолжение разговора идёт через главный экран

### Requirement: Подгрузка списка (веб)

Веб SHALL показывать под списком кнопку «Показать ещё», пока `next` не равен `null`; по нажатию клиент MUST запросить страницу по курсору и дописать её разговоры в конец списка, не дублируя уже загруженные `dialogId`. Параллельные нажатия MUST делить один запрос.

Поверхности: web

#### Scenario: (Web) Показать ещё
- **WHEN** `next` не равен `null` и человек нажимает «Показать ещё»
- **THEN** страница по курсору дописывается в конец списка, курсор заменяется новым, боковая история показывает те же разговоры
- **AND** скрытая область состояния объявляет «Показано разговоров: N»

#### Scenario: (Web) Последняя страница
- **WHEN** после подгрузки `next` равен `null`
- **THEN** кнопка «Показать ещё» исчезает

#### Scenario: (Web) Сбой подгрузки
- **WHEN** запрос следующей страницы не удался
- **THEN** загруженный список и курсор сохраняются, показано сообщение об ошибке, кнопка остаётся для повтора

### Requirement: Перечитывание списка

Клиенты SHALL перечитывать список, когда экран журнала снова становится видимым, чтобы разговор, начатый или завершённый в другом месте, был показан актуально; параллельные перечитывания MUST делить один запрос, а сбой перечитывания MUST NOT стирать уже загруженный список. Веб перечитывает список при открытии «Всех разговоров», при возврате фокуса на вкладку и при каждой смене адреса (для боковой истории); мобильный клиент — при первом показе, при каждом возврате на вкладку и после завершения разговора.

Поверхности: web · pwa · android · ios · tg

#### Scenario: Новый разговор в списке
- **WHEN** человек завершил разговор и перешёл на другой экран
- **THEN** боковая история (веб) или список журнала (мобильный клиент) показывает актуальный список

#### Scenario: (Web) Подгруженные страницы переживают перечитывание
- **WHEN** подгружены старые страницы, а перечитывание вернуло новую первую страницу, последний разговор которой уже есть в загруженном списке
- **THEN** список становится «новая первая страница, затем загруженные разговоры после её последнего элемента», без дублей, курсор остаётся прежним

#### Scenario: (PWA, Android, iOS, Telegram) Список заменяется
- **WHEN** мобильный клиент перечитал журнал
- **THEN** показанный список полностью заменяется ответом сервера

### Requirement: Список принадлежит аккаунту

Список разговоров SHALL относиться к одному аккаунту: человек, вошедший под другим аккаунтом, MUST NOT видеть список предыдущего даже на один кадр, а ответ на запрос, начатый для прежнего аккаунта, MUST быть отброшен.

Поверхности: web · pwa · android · ios · tg

#### Scenario: Вход под другим аккаунтом
- **WHEN** в клиенте входит другой человек
- **THEN** вместо чужого списка показано состояние загрузки, затем список нового аккаунта

#### Scenario: Запоздавший ответ прежнего аккаунта
- **WHEN** ответ на запрос списка приходит после смены аккаунта
- **THEN** его разговоры не попадают в список нового аккаунта

### Requirement: Загрузка, пустое состояние и ошибки списка

Пока список не загружен, клиент SHALL показывать признак загрузки. Если список загружен и пуст, клиент SHALL показывать «Здесь появятся твои разговоры.» и кнопку к началу разговора: веб — «Начать разговор» (ведёт на `/home`), мобильный клиент — «На главную» (переключает вкладку). Ошибка загрузки SHALL показываться человеческим текстом по причине (нет связи, слишком частые запросы, агент недоступен, сбой сервера), а любая другая — фразой «Не получилось загрузить журнал»; сбой MUST NOT стирать уже загруженный список.

Поверхности: web · pwa · android · ios · tg

#### Scenario: (Web) Первая загрузка не удалась
- **WHEN** список ещё не был загружен и запрос завершился ошибкой
- **THEN** вместо пустого состояния показан текст ошибки и кнопка «Попробовать ещё раз», а «Начать разговор» нет

#### Scenario: (Web) Обновление не удалось при загруженном списке
- **WHEN** список показан, а очередное обновление завершилось ошибкой
- **THEN** над списком плашка с текстом ошибки и кнопкой «Обновить», загруженные разговоры остаются

#### Scenario: (PWA, Android, iOS, Telegram) Первая загрузка не удалась
- **WHEN** список не был загружен и запрос завершился ошибкой
- **THEN** вкладка показывает сообщение пустого состояния и под ним текст ошибки

#### Scenario: (Web) Пустой журнал
- **WHEN** список загружен без ошибки и пуст
- **THEN** страница показывает «Здесь появятся твои разговоры.» и кнопку «Начать разговор»

### Requirement: Пояснение о хранении и предложение привязать почту

Под непустым списком клиент SHALL показывать пояснение «Аудио не сохраняется: разговор превращается в текст и остаётся только он. Стереть всё можно в профиле.»; при пустом списке пояснения нет. Человеку с аккаунтом без подтверждённой почты над списком SHALL предлагаться привязка почты с текстом о двух сроках: разговоры хранятся 90 дней после последнего сообщения, а аккаунт без почты открывается только на этом устройстве и удаляется через 90 дней без визитов (в вебе — только на узком экране, где нет боковой колонки с карточкой гостя). Остальным аккаунтам мобильный клиент SHALL показывать над списком строку «Разговоры хранятся 90 дней после последнего сообщения.» (в вебе такой строки у аккаунта с подтверждённой почтой нет: так ведёт себя код). Стирание данных, срок хранения разговоров и срок аккаунта описаны в capabilities `account-deletion` и `data-retention`.

Поверхности: web · pwa · android · ios · tg

#### Scenario: Пояснение под списком
- **WHEN** в журнале есть хотя бы один разговор
- **THEN** под списком показано пояснение о том, что аудио не сохраняется

#### Scenario: Гость
- **WHEN** у аккаунта нет почты или она не подтверждена, а в журнале есть разговоры
- **THEN** над списком текст «Разговоры хранятся 90 дней после последнего сообщения. Без почты аккаунт открывается только на этом устройстве и удаляется через 90 дней без визитов. Привяжи почту, чтобы сохранить аккаунт.» и кнопка «Привязать почту» (или «Подтвердить почту», если адрес указан, но не подтверждён)

#### Scenario: (PWA, Android, iOS, Telegram) Аккаунт с подтверждённой почтой
- **WHEN** у аккаунта подтверждённая почта, а в журнале есть разговоры
- **THEN** над списком одна строка «Разговоры хранятся 90 дней после последнего сообщения.», без кнопки привязки

### Requirement: Запись журнала

Запись SHALL открываться только для чтения: сводка разговора, затем (для завершённого) итог по `dialog-recaps`, затем текст — сообщения в порядке ответа сервера с различимыми ролями человека и собеседника, без поля ввода. Если у записи нет сообщений, SHALL показываться «Текст этого разговора не сохранён.». Сводка показывает дату и время начала, пометку «Не завершён» у открытого разговора, темы (или «Без тем», если сводка есть, а тем нет) и напряжение; без сводки показываются только дата и пометка. Напряжение MUST выводиться строкой «Напряжение: N → M» (неизвестное «до» — «—»), при известном только «до» — «Напряжение: было N», при неизвестных обоих значениях — не выводиться.

Поверхности: web · pwa · android · ios · tg

#### Scenario: (Web) Запись со сводкой
- **WHEN** человек открывает завершённый разговор со сводкой
- **THEN** страница показывает ссылку назад «Все разговоры» (на `/diary/journal`), заголовок с названием разговора, карточку со сводкой, затем «Текст разговора»
- **AND** заголовок документа — «Разговор — Рядом», а пока запись грузится, название берётся из строки списка

#### Scenario: (Web) Запись без сводки
- **WHEN** у разговора `summary` равно `null`
- **THEN** заголовок страницы «Разговор», вместо карточки только дата начала (и пометка «Не завершён» у открытого)

#### Scenario: Напряжение «до» неизвестно
- **WHEN** у сводки `tensionBefore` равно `null`, а `tensionAfter` равно 4
- **THEN** запись показывает «Напряжение: — → 4»

#### Scenario: Текст не сохранён
- **WHEN** у записи нет сообщений
- **THEN** вместо сообщений показано «Текст этого разговора не сохранён.»

#### Scenario: (PWA, Android, iOS, Telegram) Чтение с начала
- **WHEN** открыта запись с длинным текстом
- **THEN** список сообщений показан с первой реплики, а не прокручен к последней
- **AND** карточка сводки есть только у записи со сводкой, название в панели берётся из загруженного списка, а без него — «Разговор»

### Requirement: Продолжение из записи (веб)

Веб SHALL показывать под текстом записи одну кнопку продолжения: у открытого разговора «Вернуться к разговору» со ссылкой на `/dialog/<dialogId>`, у завершённого — «Продолжить в новом разговоре» со ссылкой на `/home`.

Поверхности: web

#### Scenario: (Web) Открытый разговор
- **WHEN** человек открыл запись разговора, который не завершён
- **THEN** запись показывает «Не завершён» и кнопку «Вернуться к разговору»

#### Scenario: (Web) Завершённый разговор
- **WHEN** человек читает завершённый разговор и нажимает «Продолжить в новом разговоре»
- **THEN** открывается `/home`

### Requirement: Запись недоступна или не загрузилась

Если сервер отказывает в записи, клиент SHALL заменить содержимое текстом отказа: `DIALOG_NOT_FOUND` — «Этот разговор не найден» (так же отвечает сервер и для чужого разговора, клиент их не различает), `USER_NOT_FOUND`, `USER_INACTIVE` и любой другой код — «Разговор недоступен». Сбой самого запроса SHALL показываться текстом по причине с запасной фразой «Не получилось открыть разговор». В вебе у отказа MUST быть ссылка «К списку разговоров» без повтора, у сбоя запроса — кнопка «Попробовать ещё раз».

Поверхности: web · pwa · android · ios · tg

#### Scenario: (Web) Разговор не найден
- **WHEN** человек открывает запись, которой сервер не знает или которая удалена после загрузки списка
- **THEN** страница показывает «Этот разговор не найден» и ссылку «К списку разговоров», без сводки, текста и кнопки продолжения

#### Scenario: (Web) Сбой запроса
- **WHEN** запрос записи завершился сетевой ошибкой или ответом 5xx
- **THEN** страница показывает текст по причине и кнопку «Попробовать ещё раз», которая снова запрашивает запись

#### Scenario: (PWA, Android, iOS, Telegram) Отказ и сбой
- **WHEN** сервер отказывает кодом `DIALOG_NOT_FOUND` или запрос завершился сбоем
- **THEN** экран показывает «Этот разговор не найден» либо текст по причине вместо содержимого

### Requirement: Запись в API

API SHALL отдавать одну запись на `GET /api/dialogs/{dialogId}`: поля строки списка и `messages` (`id`, `role`, `text`, `createdAt`, `safetyLevel`, который сейчас всегда `null`). Чужой и несуществующий разговор MUST давать одинаковый отказ `DIALOG_NOT_FOUND`.

Поверхности: api · agent

#### Scenario: (API) Чужой разговор
- **WHEN** человек запрашивает `dialogId` другого аккаунта
- **THEN** ответ-отказ `DIALOG_NOT_FOUND`, неотличимый от несуществующего

### Requirement: Удаление разговора человеком

Человек SHALL удалять завершённый разговор из записи журнала кнопкой «Удалить разговор» с подтверждением «Удалить разговор?»: «Разговор удалится из журнала вместе с итогом. Факты из него останутся: удалить их можно в разделе «Память».», «Итоги недели, в которую он входит, пересчитаются без него.», «Копии в резервных архивах хранятся до 30 дней.», ссылка «Открыть «Память»» и кнопки «Удалить разговор» и «Оставить». После удаления запись закрывается, список и боковая история перечитываются, а строки удалённого разговора в них нет. Если разговора уже нет на сервере, это считается успехом; другой сбой SHALL показывать «Не получилось удалить разговор. Попробуй позже».

Поверхности: web · pwa · android · ios · tg

#### Scenario: (Web) Удалить разговор
- **WHEN** человек открыл запись завершённого разговора, нажал «Удалить разговор» и подтвердил
- **THEN** открывается `/diary/journal`, удалённого разговора нет ни в списке, ни в боковой истории

#### Scenario: (PWA, Android, iOS, Telegram) Удалить разговор
- **WHEN** человек подтвердил удаление на экране записи или в правой области широкого экрана
- **THEN** экран возвращается к списку (на широком экране правая область очищается), разговора в списке нет

#### Scenario: Открытый разговор
- **WHEN** запись открытого разговора
- **THEN** кнопки «Удалить разговор» в записи нет

#### Scenario: Подтверждение отменено или не вышло
- **WHEN** человек нажимает «Оставить», либо запрос завершился сбоем
- **THEN** разговор остаётся на месте, при сбое под текстом подтверждения показана ошибка

### Requirement: Удаление разговора в API

API SHALL удалять разговор на `DELETE /api/dialogs/{dialogId}` (требует активную сессию, не чаще 60 раз в минуту на человека): агент стирает разговор, его сообщения и итог, ссылка «Поделиться» разговора немедленно отзывается, итог недели, в которую входит разговор, сбрасывается и собирается заново по оставшимся источникам (capabilities `dialog-share`, `mood-diary`), а заметки памяти остаются. Документ разговора в поиске по прошлым разговорам удаляется (capability `memory-search`), заметки удаляются только человеком (capability `memory-notes`). Ответ — `{deleted: true}`; чужой и несуществующий разговор — отказ `DIALOG_NOT_FOUND`; недоступный агент — `503`. Открытый разговор MUST сперва завершаться: его сокет получает `ended`, автоматический итог для него не подводится. Разговор перестаёт читаться сразу, из базы агента убирается фоновой очисткой, из резервных копий — по их сроку (capability `data-retention`).

Поверхности: api · agent

#### Scenario: (API) Разговор удалён
- **WHEN** человек удалил разговор
- **THEN** он пропал из `GET /api/dialogs` и `GET /api/recaps`, повторное удаление даёт `DIALOG_NOT_FOUND`, а заметки памяти остались

#### Scenario: (API) Ссылка и итог недели
- **WHEN** у разговора была активная ссылка «Поделиться», а его неделя имела итог
- **THEN** следующий запрос по ссылке получает `404`, итог недели пропал сразу и пишется заново без этого разговора

#### Scenario: (Агент) Открытый разговор
- **WHEN** удаляется разговор, у которого есть живое соединение
- **THEN** соединение получает `ended` и закрывается, итог разговора не создаётся

#### Scenario: (API) Агент недоступен
- **WHEN** агент не отвечает
- **THEN** ответ `503`, разговор остаётся
