# Design: add-push-notifications

## Context

- Android-приложение «Рядом» публикуется в RuStore: пакет `ru.ryadom.companion` (вариант `prod`, релизный ключ) и
  `ru.ryadom.companion.dev` (вариант `dev`, командный debug-ключ). RuStore Push требует, чтобы пакет и отпечаток
  подписи установленного APK совпадали с пуш-проектом, поэтому проектов два: «Тест» и «Production».
- Dev-сборка ходит на локальный стенд и переключается на прод (`native-app-build`, «Переключатель сред только в
  dev-сборке»), то есть один сервер получает подписки обоих проектов.
- Доставку на телефон выполняет «дистрибьютор»: RuStore или одно из приложений VK. Без него токена нет.
- Референс серверной части — `silqai` (ветка `main-mobile`): хранилище токенов с переездом токена к новому владельцу,
  отправка без исключений наружу, удаление токена по ответу push-сервиса, отвязка при выходе. Референс клиента
  RuStore — PROTEUS-151 (UnionApp): SDK, сервис-наследник `RuStoreMessagingService`, касание через `Intent.extras`.
- `add-notifications` (PROTEUS-243) ещё не реализован и планирует свою таблицу подписок. Этот change кладёт общую
  таблицу и маршруты первым.

## Goals / Non-Goals

**Goals**

- Человек может получить уведомление на Android-телефон, и только если сам включил его в профиле.
- Администратор отправляет уведомление конкретному человеку и сразу видит итог.
- Подписки, отправка, чистка мёртвых токенов, касание с переходом — общие для следующих видов уведомлений.
- После выхода, завершения сессии и удаления аккаунта уведомления на устройство не уходят.

**Non-Goals**

- Виды уведомлений, настройки по видам, расписание, окно, пауза — `add-notifications`.
- Web Push, Telegram, APNs. Рассылки многим.

## Decisions

### D1. Свой плагин Capacitor, SDK `ru.rustore.sdk:pushclient`

Поддерживаемого плагина Capacitor для RuStore Push нет (SDK есть для Kotlin/Java, Unity, Flutter, React Native и
других, для Capacitor — нет). Плагин `RuStorePush` пишется на Java рядом с `MainActivity` (модуль приложения на Java,
Kotlin-плагин Gradle не нужен):

| Метод / событие | Что делает |
|---|---|
| `checkPermission()` / `requestPermission()` | `POST_NOTIFICATIONS` на Android 13+, ниже — всегда `granted` |
| `getToken()` | `{token, projectId, appId}`: токен SDK, ID пуш-проекта из манифеста, пакет приложения |
| `deleteToken()` | удаляет токен у RuStore (выход, выключение) |
| `openSettings()` | экран уведомлений приложения в настройках Android |
| событие `tokenChanged` | `onNewToken` сервиса — клиент переподписывается |
| событие `notificationOpened` | данные касания из `Intent.extras`, при холодном старте — после появления слушателя |

SDK инициализируется сам по `meta-data` `ru.rustore.sdk.pushclient.project_id` в манифесте — значение подставляет
Gradle (`manifestPlaceholders` по варианту), класс `Application` не нужен. Канал уведомлений «Уведомления»
создаётся при загрузке плагина и назначен каналом по умолчанию (`default_notification_channel_id`), значок —
монохромный `ic_notification`.

### D2. Пуш-проект хранится у подписки, сервисные токены — у сервера

Клиент сообщает `projectId` вместе с токеном. Сервер держит `RUSTORE_PUSH_SERVICE_TOKENS` — список
`<ID проекта>:<сервисный токен>` через запятую (Secret). Подписку проекта без токена сервер не отправляет и считает
неотправленной. Так прод принимает подписки и release-, и dev-сборок, а локальный стенд — только «Тест».
`RUSTORE_PUSH_API_URL` (по умолчанию `https://vkpns.rustore.ru`) подменяется в e2e заглушкой.

Вместе с токеном клиент сообщает пакет приложения (`ru.ryadom.companion` или `ru.ryadom.companion.dev`): админка
показывает его у устройства, и по нему видно, release это или dev-сборка, без отдельной таблицы названий проектов.

### D3. Подписка привязана к сессии

`push_subscriptions(id, user_id, session_id, channel, token, project_id, app_id, created_at, updated_at)`, уникальность
`(channel, token)`. `session_id` берётся из `sid` токена доступа. Отправка выбирает подписки только открытых сессий
(есть токен продления с неистёкшим сроком и ни одного, завершённого выходом или отзывом) — так выход, «Выйти на всех
устройствах», завершение администратором, блокировка, смена пароля и кража токена (отзыв всех сессий) отключают
уведомления без отдельного шага в каждом сценарии. Подписки завершённых и истёкших сессий удаляет ежечасная чистка
сессий. Повторная подписка того же токена — `ON CONFLICT (channel, token) DO UPDATE`: строка переходит к новому
аккаунту и сессии, идентификатор сохраняется.

Внешнего ключа на сессию нет: `session_id` в `refresh_tokens` не уникален. На `users` — `on delete cascade`, но
удаление аккаунта мягкое, поэтому подписки стираются в `erase-account.ts`.

### D4. Отправка — процесс ядра, вызывается из админки напрямую

`notifications` process → `SendUserNotificationOperation({adminEmail, userId, title, body, link?})`:

1. Проверка длины (заголовок 1–60, текст 1–500) и существования аккаунта.
2. Подписки открытых сессий (`push-subscriptions-manager`).
3. Отправка параллельно по подпискам через интеграцию `rustore-push` (таймаут 10 с, `android.ttl` 86400 с,
   `notification {title, body}`, `data {link}` при наличии ссылки).
4. Ответ `404` (`NOT_FOUND`) — подписка удаляется. `400`, `401`, `403`, `429`, `5xx`, сеть — подписка остаётся,
   устройство в итоге неотправленное.
5. Запись `USER_NOTIFICATION_SENT` в журнал: заголовок, текст, `sent`, `total`.

Админка вызывает процесс синхронно: администратор видит итог сразу. Очередь задач здесь не нужна — одно действие
одного человека. Следующие виды (по расписанию и событиям) будут звать отправку из воркеров `services/api`
отдельной операцией того же процесса.

### D5. Включение на телефоне — флаг устройства

Переключатель в профиле хранит «уведомления включены на этом устройстве» локально (как «Разговор без рук»):

- включение → `requestPermission()` → `getToken()` → `POST /api/notifications/subscriptions`; ID подписки
  запоминается на устройстве; отказ в разрешении — флаг не ставится, строка «Уведомления запрещены в настройках
  телефона» и «Открыть настройки»; нет дистрибьютора или RuStore ни разу не открывали (SDK не может к нему
  подключиться) — «Не получилось включить уведомления. Нужен RuStore: установи его или открой хотя бы раз»; прочие
  сбои — «Попробуй чуть позже». После каждой попытки переключатель встаёт в фактическое положение;
- при запуске и после входа, если флаг стоит и разрешение есть, — `getToken()` и повторная подписка (идемпотентна,
  переносит подписку в текущую сессию); `tokenChanged` — то же;
- выключение и выход → `DELETE /api/notifications/subscriptions/{id}` (не дольше 3 с, ошибка не мешает) →
  `deleteToken()`, флаг снимается. После выхода новый вход начинает с выключенных уведомлений.

### D6. Старые сборки без плагина

JS проверяет `Capacitor.isPluginAvailable('RuStorePush')` и без плагина не показывает переключатель и не вызывает
плагин. Поэтому пакет JS с этим кодом безопасен для сборки 1.0.0 (2), и `OTA_MIN_NATIVE_BUILD` не поднимается:
поднятие отрезало бы от обновлений JS все установленные сборки ради функции, которую они и так не покажут.

### D7. Касание

SDK показывает уведомление сам (в сообщении есть `notification`) и по касанию открывает `MainActivity` с полями
`data` в `Intent.extras`. Плагин читает их в `load()` (холодный старт) и `handleOnNewIntent` (приложение запущено),
удаляет из интента прочитанные ключи и шлёт `notificationOpened` с `retainUntilConsumed`. Клиент открывает `link`,
только если это маршрут приложения (`isAppRoute` в `lib/nav.ts`), иначе ничего не делает.

### D8. Ограничения текста

Заголовок до 60 и текст до 500 символов: шторка Android показывает около 40 символов заголовка и 4–7 строк текста;
сообщение RuStore — не больше 4096 байт, кириллица в UTF-8 — 2 байта на символ, запас на данные остаётся.

## Risks / Trade-offs

- **[Нет дистрибьютора на телефоне]** Без RuStore и приложений VK токена нет — включение показывает понятную ошибку.
- **[Доставка зависит от фоновой работы RuStore]** Без разрешения на работу в фоне уведомления приходят с задержкой —
  это вне нашего контроля, проверяем на реальном телефоне.
- **[Текст на экране блокировки]** Пишет администратор; форма напоминает, что текст видят все рядом с телефоном.
- **[Сервисный токен]** Секрет только сервера: в репозитории и задачах — только имя переменной.

## Migration Plan

1. Пуш-проекты «Тест» и «Production» в консоли RuStore; ID — в `android/app/build.gradle`, сервисные токены — в
   `RUSTORE_PUSH_SERVICE_TOKENS` Secret `app-secrets` (api и админка).
2. Миграция `0013_push_subscriptions` (до выката api и админки).
3. Выкат api, админки и pwa (пакет JS) — старые APK переключатель не показывают.
4. Нативная сборка 1.0.1 (versionCode 3) с плагином — в RuStore; проверка доставки на production-проекте.
5. Откат: убрать токены из Secret — отправка перестаёт вызывать RuStore, подписки остаются.
