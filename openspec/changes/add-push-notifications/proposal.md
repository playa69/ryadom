Задача: PROTEUS-150

# Proposal: add-push-notifications

## Why

У «Рядом» нет ни одного серверного уведомления: в Android-сборке нет SDK пушей, у сервера нет ни подписок устройств,
ни отправки, в консоли RuStore нет пуш-проектов. Приложение распространяется через RuStore, поэтому канал Android —
RuStore Push (`@capacitor/push-notifications` работает через Firebase и тут не подходит).

Первая польза — администратор может написать конкретному человеку уведомление свободным текстом из карточки в
админке: ответить на обращение, предупредить о работах, проверить доставку на своём телефоне. Главное — это
инфраструктура для следующих видов (напоминание о настроении — `add-notifications`, PROTEUS-243; «итоги недели готовы»;
утренний пуш сценария А): подписки устройств, отправка, чистка мёртвых токенов, касание с переходом на экран, выход и
удаление аккаунта.

## What Changes

- **Android-приложение:** RuStore Push SDK и свой тонкий плагин Capacitor (разрешение, токен, удаление токена, новый
  токен, касание уведомления). Пуш-проект по варианту сборки: `dev` → проект «Тест» (`ru.ryadom.companion.dev`,
  командный debug-ключ), `prod` → «Production» (`ru.ryadom.companion`, релизный ключ). Разрешение `POST_NOTIFICATIONS`.
- **Профиль, раздел «Приложение»:** переключатель «Уведомления» — только в нативной Android-сборке с плагином.
  Системное разрешение спрашивается только после включения переключателя, не при запуске.
- **API:** `POST /api/notifications/subscriptions` (подписка устройства: канал `rustore`, токен, пуш-проект) и
  `DELETE /api/notifications/subscriptions/{id}`. Подписка привязана к сессии: после выхода, завершения сессии и
  удаления аккаунта на устройство ничего не уходит.
- **Отправка** через RuStore Push API (`vkpns.rustore.ru`) по сервисному токену своего пуш-проекта; на ответ «токен не
  найден» подписка удаляется.
- **Админка, карточка пользователя:** блок «Уведомления» — устройства с подпиской, форма «Заголовок» и «Текст»,
  кнопка «Отправить», итог «Отправлено на N из M устройств». Запись «Уведомление отправлено» в журнале действий.
- **Удаление аккаунта** стирает подписки (`erase-account`).

## Capabilities

### New Capabilities

- `push-notifications`: включение на телефоне, подписка устройства, доставка через RuStore Push, связь с сессией,
  касание уведомления.

### Modified Capabilities

- `admin-console`: «Журнал действий» (новое действие); новое требование «Уведомление человеку из карточки».
- `native-app-build`: «Разрешения и платформенные параметры» (`POST_NOTIFICATIONS`), «Нативные возможности клиента»
  (плагин пушей).
- `account-deletion`: «Что стирается в приложении» (подписки на уведомления).

## Зависимости и миграции

- **Миграция `0013_push_subscriptions`**: таблица `push_subscriptions` с каналом (`rustore`; Web Push, Telegram и APNs
  добавят свои значения). Генерируется `drizzle-kit generate` поверх `0012_voice_settings`.
- **`add-notifications` (PROTEUS-243, ветка `pending/add-notifications`)** планирует свою `push_subscriptions` и те же
  маршруты подписок. После этого change'а он берёт таблицу и маршруты отсюда и добавляет свои каналы, а не создаёт их
  заново. Он же меняет «Разрешения и платформенные параметры» в `native-app-build`: кто архивирует вторым, переносит
  свой блок на обновлённую спеку.
- **Пуш-проекты в консоли RuStore** (ID проектов идут в сборку, сервисные токены — только на сервер, хранятся
  локально у администратора).
- **Нативная сборка:** плагин доезжает только с новым APK (versionCode 3). Пакет JS без плагина на старых сборках
  переключатель не показывает, поэтому `OTA_MIN_NATIVE_BUILD` не поднимается (design, D6).

## Вне рамок

- Виды уведомлений по расписанию и событиям, настройки по видам, окно доставки, пауза — `add-notifications`.
- Web Push, сообщения бота Telegram, iOS (APNs).
- Рассылки сразу многим людям и топики RuStore.
- Тексты от администратора с картинками и кнопками.

## Impact

- `app/packages/db`: схема и миграция `push_subscriptions`, действие журнала `USER_NOTIFICATION_SENT`.
- `app/packages/core`: менеджер `push-subscriptions-manager`, интеграция `rustore-push`, процесс `notifications`,
  стирание в `account-deletion`, переменные `RUSTORE_PUSH_*`.
- `app/packages/contracts`: `api/notifications.ts`, пути.
- `app/services/api`: `routes/notifications`.
- `app/apps/admin`: блок в карточке пользователя, подпись действия в журнале.
- `app/apps/mobile`: плагин (`android/`), `src/client/lib/push.ts`, переключатель в профиле, отвязка при выходе.
- `app/e2e`: админка в стенде, заглушка RuStore Push, тест `admin-notifications.spec.ts`.
- `k8s/app`: `RUSTORE_PUSH_SERVICE_TOKENS` в Secret `app-secrets` для api и админки.
