## MODIFIED Requirements

### Requirement: Микрофон или голос недоступны
Если микрофон не работает, клиент SHALL сообщить об этом мягко и оставить возможность писать текстом. Когда слушание включилось само (разговор начат с главного экрана), экран MUST перейти в текстовый вид с уведомлением; когда человек нажал сам — показать окно «Голос» с причиной. Освобождённый поток MUST оставаться освобождённым: индикатор записи не остаётся включённым. При отказе в разрешении клиент SHALL показать окно с пошаговой инструкцией, как включить микрофон, под место открытия страницы (Chrome на Android, Safari на iPhone, Яндекс Браузер, встроенное окно другого приложения, установленное PWA) и кнопками «Попробовать снова» и «Писать текстом». Системный запрос MUST идти сразу, без экрана перед ним; окно с инструкцией показывается только после того, как разрешение не выдано. Где браузер умеет сообщить состояние разрешения без запроса, клиент SHALL при `denied` показывать инструкцию, не вызывая запрос микрофона, а при смене на `granted` предложить продолжить.

Поверхности: web · pwa · android · ios · tg

#### Scenario: Платформа без микрофона
- **WHEN** на платформе нет доступа к микрофону из страницы
- **THEN** автоматический старт даёт текстовый вид и уведомление «Здесь микрофон недоступен. Можно писать текстом.»; нажатие человеком — окно «Голос» с тем же текстом

#### Scenario: Первый запуск голоса
- **WHEN** человек первый раз запускает голос и разрешение ещё не спрошено
- **THEN** клиент сразу вызывает системный запрос микрофона, никакого экрана до него нет; при выданном разрешении голос начинается, окна не бывает

#### Scenario: Окно с инструкцией после отказа
- **WHEN** человек нажал голос, а открыть микрофон не удалось из-за отказа в разрешении
- **THEN** открывается окно с шагами для его платформы: в Chrome на Android — «замок» в адресной строке → «Разрешения» → «Микрофон»; в Safari на iPhone — «Аа» → «Настройки веб-сайта» → «Микрофон»; в Яндекс Браузере — настройки сайта в адресной строке; во встроенном окне другого приложения — открыть Рядом в системном браузере (ссылка и копирование адреса); в установленном PWA — настройки приложения в системе
- **AND** в окне есть «Попробовать снова» и «Писать текстом»; «Писать текстом» закрывает окно и оставляет текстовый вид

#### Scenario: Попробовать снова
- **WHEN** человек нажимает «Попробовать снова»
- **THEN** клиент снова пробует открыть микрофон; при успехе окно закрывается и голос начинается, при новом отказе окно остаётся

#### Scenario: Отказ запомнен браузером
- **WHEN** браузер сообщает состояние разрешения `denied`
- **THEN** окно с инструкцией открывается сразу, системный запрос не вызывается
- **AND** когда состояние сменилось на `granted`, окно предлагает продолжить, и голос начинается по нажатию

#### Scenario: Микрофон не разрешён
- **WHEN** открыть микрофон не удалось из-за отказа в разрешении, а слушание включилось само с главного экрана
- **THEN** экран переходит в текстовый вид с уведомлением «Микрофон не разрешён. Разреши его в настройках — или пиши текстом.» (во встроенном окне и в Safari на iPhone — текст по месту открытия, как в PROTEUS-280), окно не открывается; инструкция показывается, когда человек сам нажимает голос

#### Scenario: Иной сбой микрофона
- **WHEN** микрофон не включился по иной причине (нет устройства, занят другим приложением, небезопасный контекст)
- **THEN** сообщение — «Не получилось включить микрофон. Можно писать текстом.»; инструкция по разрешению не показывается

#### Scenario: Голос недоступен на стороне агента
- **WHEN** приходит `error VOICE_UNAVAILABLE`
- **THEN** показывается «Голос сейчас недоступен — можно писать текстом»; (Web) идущая запись останавливается; вид сам не переключается
- **AND** ошибка приходит, только когда сессию не удалось открыть ни одним путём (запасные пути — друг для друга, см. «Сбои голосовой модели»); на набранное сообщение отвечает та же модель пути разговора, поэтому при недоступных обоих путях ответа не будет и на него (так ведёт себя код)
