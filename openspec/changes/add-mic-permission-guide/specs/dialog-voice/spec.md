## MODIFIED Requirements

### Requirement: Микрофон или голос недоступны
Если микрофон не работает, клиент SHALL сообщить об этом мягко и оставить возможность писать текстом. Когда слушание включилось само (разговор начат с главного экрана), экран MUST перейти в текстовый вид с уведомлением; когда человек нажал сам — показать окно «Голос» с причиной. Освобождённый поток MUST оставаться освобождённым: индикатор записи не остаётся включённым. При отказе в разрешении клиент SHALL показать окно с пошаговой инструкцией, как включить микрофон, под устройство и место открытия страницы: шаги MUST называть только те меню и переключатели, которые есть у этого браузера и этой системы (Chrome, Яндекс Браузер, Samsung Internet и Firefox на Android; Safari и сторонние браузеры на iPhone; Safari, Chrome и Firefox на компьютере; встроенное окно другого приложения; установленное PWA и сборки для Android и iOS) и кнопками «Попробовать снова» и «Писать текстом». Системный запрос MUST идти сразу, без экрана перед ним; окно с инструкцией показывается только после того, как разрешение не выдано. Где браузер умеет сообщить состояние разрешения без запроса, клиент SHALL при `denied` показывать инструкцию, не вызывая запрос микрофона, а при смене на `granted` сразу начинать голосовой разговор без промежуточного экрана.

Поверхности: web · pwa · android · ios · tg

#### Scenario: Платформа без микрофона
- **WHEN** на платформе нет доступа к микрофону из страницы
- **THEN** автоматический старт даёт текстовый вид и уведомление «Здесь микрофон недоступен. Можно писать текстом.»; нажатие человеком — окно «Голос» с тем же текстом

#### Scenario: Первый запуск голоса
- **WHEN** человек первый раз запускает голос и разрешение ещё не спрошено
- **THEN** клиент сразу вызывает системный запрос микрофона, никакого экрана до него нет; при выданном разрешении голос начинается, окна не бывает

#### Scenario: Окно с инструкцией после отказа
- **WHEN** человек нажал голос, а открыть микрофон не удалось из-за отказа в разрешении
- **THEN** открывается окно с шагами для его устройства; шаги не называют меню, которых у него нет
- **AND** в окне есть «Попробовать снова» и «Писать текстом»; «Писать текстом» закрывает окно и оставляет текстовый вид

#### Scenario: Шаги по устройствам
- **WHEN** окно с инструкцией открыто
- **THEN** в Chrome на Android — значок слева от адреса → «Разрешения» → «Микрофон» (и настройки приложения Chrome в системе, если не помогло); в Safari на iPhone — «Аа» → «Настройки веб-сайта» → «Микрофон» → «Разрешить»; в Chrome, Яндекс Браузере и других браузерах на iPhone — «Настройки» iPhone → браузер → «Микрофон»; в Яндекс Браузере на Android — значок слева от адреса → «Настройки сайта» → «Микрофон»; в Samsung Internet и Firefox на Android — свои меню; в Chrome и Firefox на компьютере — значок слева от адреса и перезагрузка страницы; в Safari на Mac — Safari → «Настройки для этого веб-сайта»
- **AND** во встроенном окне другого приложения — скопировать адрес и открыть в Chrome или Safari; в установленном PWA и в сборках — настройки приложения в системе (Android — «Приложения» → Рядом → «Разрешения»; iPhone — «Настройки» → Рядом, для PWA — «Настройки» → «Приложения» → Safari)

#### Scenario: Попробовать снова
- **WHEN** человек нажимает «Попробовать снова»
- **THEN** клиент снова пробует открыть микрофон; при успехе окно закрывается и голос начинается, при новом отказе окно остаётся

#### Scenario: Отказ запомнен браузером
- **WHEN** браузер сообщает состояние разрешения `denied`
- **THEN** окно с инструкцией открывается сразу, системный запрос не вызывается
- **AND** когда состояние сменилось на `granted` (человек включил микрофон в настройках и вернулся), окно закрывается и голосовой разговор начинается сразу, без промежуточного экрана и без нажатия

#### Scenario: Микрофон не разрешён
- **WHEN** открыть микрофон не удалось из-за отказа в разрешении, а слушание включилось само с главного экрана
- **THEN** экран переходит в текстовый вид с уведомлением «Микрофон не разрешён. Разреши его в настройках — или пиши текстом.» (во встроенном окне и в Safari на iPhone — текст по месту открытия, как в PROTEUS-280), окно не открывается; инструкция показывается, когда человек сам нажимает голос

#### Scenario: Нет устройства звука
- **WHEN** микрофон не открылся, потому что устройства ввода звука нет
- **THEN** сообщение — «Микрофон не найден. Подключи его — или пиши текстом.»; инструкция по разрешению не показывается

#### Scenario: Микрофон занят
- **WHEN** микрофон не открылся, потому что его держит другое приложение
- **THEN** сообщение — «Микрофон занят другим приложением. Закрой его там — или пиши текстом.»

#### Scenario: Страница не защищена
- **WHEN** браузер не доверяет странице микрофон (небезопасный адрес)
- **THEN** сообщение — «Здесь микрофон включить нельзя: страница открыта не по защищённому адресу. Можно писать текстом.»

#### Scenario: Иной сбой микрофона
- **WHEN** микрофон не включился по иной причине
- **THEN** сообщение — «Не получилось включить микрофон. Можно писать текстом.»; инструкция по разрешению не показывается

#### Scenario: Голос недоступен на стороне агента
- **WHEN** приходит `error VOICE_UNAVAILABLE`
- **THEN** показывается «Голос сейчас недоступен — можно писать текстом»; (Web) идущая запись останавливается; вид сам не переключается
- **AND** ошибка приходит, только когда сессию не удалось открыть ни одним путём (запасные пути — друг для друга, см. «Сбои голосовой модели»); на набранное сообщение отвечает та же модель пути разговора, поэтому при недоступных обоих путях ответа не будет и на него (так ведёт себя код)
