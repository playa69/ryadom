## ADDED Requirements

### Requirement: Ежедневная выгрузка и retention для Sber500

`REQ-OBS-06`. Сервис SHALL отдавать агрегаты в JSON по `GET /api/v1/metrics/daily` с отдельным Bearer-токеном. Обязательные `date_from` и `date_to` задают включительный диапазон до 90 календарных суток в `Europe/Moscow`. Идентификаторы и тексты пользователей MUST NOT передаваться или храниться в агрегатах выгрузки.

Поверхности: api

#### Scenario: Формат ответа

- **WHEN** запрос авторизован и даты валидны
- **THEN** JSON содержит `startup_id`, `timezone`, `generated_at` и массив `data` по порядку дат. Каждая строка содержит `date`, `dau`, `llm_requests`, `tool_requests`, `total_users`, `new_users`, `retained_d1`, `retained_d3`, `retained_d7`, `retained_d14` и `is_final`. Последнее поле относится к дате строки.

#### Scenario: Защита и проверка запроса

- **WHEN** токен отсутствует или неверен, даты отсутствуют либо диапазон невалиден, или исчерпан лимит
- **THEN** сервис возвращает соответственно 401, 400 или 429 с JSON-полем `error` и без метрик

### Requirement: Когорты регистрации в выгрузке Sber500

`new_users` SHALL считать аккаунты, созданные в эти сутки, включая анонимные. `total_users` SHALL считать накопленное число регистраций. `retained_dN` SHALL считать уникальные аккаунты из когорты регистрации с сообщением агенту ровно в день `date + N`, по тем же источникам и правилам, что и DAU. День определяется по Москве. Аккаунты с метками `test` и `internal` исключаются.

Поверхности: api

#### Scenario: Сообщения ровно в целевые сутки

- **WHEN** аккаунт зарегистрировался 16 ноября и отправил несколько сообщений 23 ноября
- **THEN** в строке за 16 ноября `retained_d7` остаётся `null` в течение 23 ноября и после закрытия суток учитывает этот аккаунт ровно один раз

#### Scenario: История и дни без активности

- **WHEN** коллектор запрашивает последние 15 завершённых суток
- **THEN** ответ содержит 15 строк, зрелые значения retention рассчитаны и за прошлые даты, пустой завершённый день присутствует с нулевыми дневными счётчиками
- **AND** целевые сутки, которые идут или не наступили, дают `null`, закрытые целевые сутки без возвратов дают 0

### Requirement: Таблица удержания на дашборде Sber500

Страница `/dashboard` SHALL показывать число регистраций и D1, D3, D7 и D14 по московским датам когорт. Таблица SHALL использовать агрегаты ежедневной выгрузки. Доступ к странице использует действующий вход дашборда.

Поверхности: web

#### Scenario: Закрытые и незакрытые целевые сутки

- **WHEN** пользователь открывает таблицу удержания
- **THEN** закрытые целевые сутки отображаются числом, включая 0, а незакрытые — прочерком с пояснением

#### Scenario: Агрегаты ещё готовятся

- **WHEN** агрегаты удержания пока недоступны
- **THEN** раздел сообщает об этом, а остальные метрики страницы остаются доступны
