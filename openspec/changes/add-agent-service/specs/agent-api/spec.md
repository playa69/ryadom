# Дельта-спецификация: agent-api

## Purpose

Внутренний HTTP-контракт между backend и сервисом agent: стриминговая обработка реплики с типизированными событиями, авторизация внутренним токеном, служебные эндпоинты, таймауты, коды ошибок и сквозная трассировка. Сервис недоступен извне кластера.

## ADDED Requirements

### Requirement: Стриминговая обработка реплики

Агент SHALL предоставлять два транспорта обработки реплики с единым набором событий: `POST /internal/v1/turns` со стриминговым ответом (SSE или chunked JSON-lines) — для текстовых реплик; WebSocket `/internal/v1/turns/ws` — для голосовых реплик (дуплекс: backend стримит аудио-чанки, агент стримит события, включая частичные транскрипты). Запрос: `session_id`, `user_id`, `mode`, контекст (`incognito`, `voice_id`, флаги антизависимого контура, время последней сессии), реплика — текст ИЛИ поток аудио-чанков. Ответ — упорядоченный поток типизированных событий: `transcript.partial`, `transcript.final`, `safety.status`, `llm.token`, `llm.done`, `tts.chunk`, `crisis.intervention`, `degradation`, `turn.done`, `error`. Каждое событие MUST нести монотонный `seq` в пределах запроса. Событие `turn.done` MUST содержать финальные артефакты: полный текст ответа, эмоциональные теги реплики, данные для записи в память (кроме инкогнито).

#### Scenario: Текстовый ход полного цикла

- **WHEN** backend шлёт `POST /internal/v1/turns` с текстовой репликой
- **THEN** приходит поток `safety.status` → `llm.token`* → `llm.done` → (`tts.chunk`*) → `turn.done` с артефактами, все события с монотонным `seq`

#### Scenario: Голосовой ход

- **WHEN** backend открывает WebSocket `/internal/v1/turns/ws` и шлёт аудио-чанки реплики
- **THEN** поток начинается с `transcript.partial`/`transcript.final`, далее — как текстовый ход

#### Scenario: Кризис в потоке

- **WHEN** кризис-классификатор возвращает `red`
- **THEN** после `safety.status` приходит `crisis.intervention` (детерминированный текст + ресурсы помощи) → `turn.done`; `llm.token` обычной генерации отсутствуют

### Requirement: Внутренняя авторизация

Все эндпоинты `/internal/**` SHALL требовать заголовок авторизации с внутренним токеном (shared secret из конфигурации). Запросы без токена или с неверным токеном MUST отклоняться 401. Сервис MUST NOT публиковаться через ingress наружу.

#### Scenario: Запрос без токена

- **WHEN** запрос к `/internal/v1/turns` приходит без заголовка авторизации
- **THEN** ответ 401, обработка не выполняется

### Requirement: Формат ошибок

Ошибки SHALL возвращаться в формате `{"error":{"code","message","details"}}`. Коды: `AGENT_VALIDATION` (400), `AGENT_UNAUTHORIZED` (401), `AGENT_SESSION_MODE_INVALID` (422), `AGENT_LLM_UNAVAILABLE` (503), `AGENT_SPEECH_UNAVAILABLE` (503), `AGENT_TIMEOUT` (504), `AGENT_INTERNAL` (500). Ошибка в середине стрима MUST передаваться событием `error` с тем же кодом.

#### Scenario: Ошибка валидации

- **WHEN** запрос содержит невалидный `mode` или отсутствует обязательное поле
- **THEN** ответ 400/422 с кодом ошибки из каталога, стрим не открывается

#### Scenario: Сбой в середине стрима

- **WHEN** после начала стрима отваливается LLM-провайдер
- **THEN** в поток высылается событие `error` с кодом `AGENT_LLM_UNAVAILABLE`, поток завершается

### Requirement: Таймауты и отмена

Агент SHALL ограничивать обработку одного хода настраиваемым таймаутом (по умолчанию 60 секунд); по превышении — событие `error` `AGENT_TIMEOUT` и завершение. Разрыв соединения вызывающей стороной MUST отменять обработку (включая внешние вызовы LLM/ASR/TTS) в течение 5 секунд.

#### Scenario: Отмена по разрыву

- **WHEN** backend разрывает соединение посреди стрима
- **THEN** агент отменяет внешние вызовы и освобождает ресурсы хода

### Requirement: Служебные эндпоинты

Агент SHALL предоставлять `GET /health` (liveness) и `GET /health/ready` (readiness: доступность LLM-провайдера, Redis, БД) и `GET /version`. Служебные эндпоинты MUST NOT требовать внутренний токен, MUST NOT логироваться в access-лог и MUST NOT быть доступны извне кластера.

#### Scenario: Readiness при недоступном LLM

- **WHEN** LLM-провайдер недоступен
- **THEN** `GET /health/ready` отвечает 503 с перечнем недоступных зависимостей, `GET /health` — 200

### Requirement: Сквозная трассировка

Агент SHALL извлекать заголовки трассировки (`x-trace-id`/`rqUId`, `x-request-time`, `x-client-id`, `x-session-id`, `x-user-id`) из входящего запроса, включать их во все логи хода и пробрасывать во внешние вызовы, поддерживающие трассировку. Каждый вызов внешней модели (LLM, классификаторы, эмбеддинги, ASR, TTS) MUST создавать трейс в Langfuse с `session_id`, `user_id` (хэш), режимом, моделью, токенами и длительностью.

#### Scenario: Проброс rqUId

- **WHEN** backend шлёт запрос с `x-trace-id: abc-123`
- **THEN** все логи обработки хода содержат `rqUId=abc-123`, трейс Langfuse связан с этим идентификатором
