# Дельта-спецификация: speech-pipeline

## Purpose

Голосовая цепочка агента «Слышу Рядом»: потоковое распознавание речи (ASR) и синтез речи (TTS) через SaluteSpeech внутри сервиса agent, с кэшем типовых фраз и деградацией в текстовый режим при отказе голосовых компонентов. Формат кадров и порядок обмена с вызывающей стороной описаны в specs `agent-api` («Голос — формат и ввод», «Голос — озвучка ответов», «Приветствие»); здесь — поведение цепочки.

## ADDED Requirements

### Requirement: ASR-стриминг

Агент SHALL принимать поток аудиокадров PCM16 (16 кГц, моно, по 100 мс) от вызывающей стороны и транскрибировать его через SaluteSpeech ASR в потоковом режиме, возвращая частичные гипотезы (`transcript` с `final: false`) по мере распознавания и один финальный транскрипт (`transcript` с `final: true`) по сигналу `audio_end`. Финальный текст MUST сохраняться агентом как обычное сообщение человека, а его `messageId` MUST передаваться в финальном `transcript`. Аудио MUST NOT сохраняться ни на диск, ни в кэш.

#### Scenario: Потоковая транскрибация

- **WHEN** вызывающая сторона шлёт `audio_start`, последовательность аудиокадров и `audio_end`
- **THEN** агент возвращает ≥ 0 кадров `transcript { final: false }` (не чаще 5 в секунду) и ровно один `transcript { final: true, text, messageId }` с полным текстом реплики

#### Scenario: Пустая реплика

- **WHEN** аудио не содержит распознаваемой речи
- **THEN** агент присылает `transcript { final: true, text: "" }` без `messageId`, конвейер не запускает генерацию, сообщение не создаётся

### Requirement: TTS-стриминг

Агент SHALL озвучивать каждый сгенерированный ответ через SaluteSpeech TTS, передавая аудиокадры PCM16 (24 кГц, моно, по 200 мс) вызывающей стороне по мере готовности: по предложениям, не дожидаясь полного синтеза. Первый звук (`tts_start`) MUST начинаться не позже 0,9 с после окончания текста ответа, а по `tts_cancel` синтез и отправка кадров этого сообщения MUST немедленно прекращаться. Голос в v1 — голос по умолчанию из конфигурации; выбор голоса пользователем в контракт не входит и добавляется полем, когда у приложения появится экран выбора. Кризисное вмешательство MUST озвучиваться в приоритетном порядке.

#### Scenario: Потоковый синтез

- **WHEN** сгенерировано первое предложение ответа
- **THEN** аудиокадры TTS передаются по мере готовности, по завершении озвучки — `tts_end`

#### Scenario: Перебивание

- **WHEN** вызывающая сторона присылает `tts_cancel` для озвучиваемого сообщения
- **THEN** вызов синтеза отменяется, кадры этого сообщения больше не отправляются

### Requirement: Кэш типовых фраз

Агент SHALL кэшировать TTS-аудио типовых фраз (ритуалы, приветствия, кризисное вмешательство) в Redis с TTL: повторный запрос идентичной фразы тем же голосом MUST отдаваться из кэша без вызова SaluteSpeech. Приветствие, озвучиваемое под `messageId` `"greeting"`, MUST входить в число кэшируемых фраз, чтобы озвучка приветствия укладывалась в срок 0,9 с.

#### Scenario: Повторная фраза из кэша

- **WHEN** запрашивается озвучка фразы, уже синтезированной тем же голосом ранее
- **THEN** аудио отдаётся из кэша, вызов SaluteSpeech TTS не выполняется

### Requirement: Деградация в текстовый режим

При отказе ASR агент MUST продолжать принимать текстовые реплики без распознавания; при отказе TTS агент MUST возвращать ответ текстом без аудио. Каждый отказ MUST сопровождаться сигналом вызывающей стороне и метрикой: недоступность распознавания — кадр `error` с кодом `VOICE_UNAVAILABLE`; недоступность озвучки — `error` с кодом `VOICE_UNAVAILABLE` либо отсутствие `tts_start` (ответ прочитает клиент). Восстановление компонента MUST происходить автоматически (circuit breaker с полуоткрытым состоянием).

#### Scenario: Отказ TTS

- **WHEN** SaluteSpeech TTS недоступен
- **THEN** ответ приходит текстом (`assistant_*`), озвучки нет, диалог продолжается

#### Scenario: Отказ ASR

- **WHEN** SaluteSpeech ASR недоступен, а пришёл аудиопоток
- **THEN** агент присылает `error { code: "VOICE_UNAVAILABLE" }`, генерация по аудио не выполняется, текстовые реплики по-прежнему принимаются

### Requirement: Устойчивость внешних вызовов

Все вызовы SaluteSpeech SHALL выполняться с таймаутами, retry с backoff (для идемпотентных операций) и circuit breaker. Ошибки провайдера MUST NOT приводить к зависанию конвейера дольше настроенного таймаута.

#### Scenario: Таймаут провайдера

- **WHEN** SaluteSpeech не отвечает дольше настроенного таймаута
- **THEN** вызов прерывается, срабатывает сценарий деградации соответствующего компонента
