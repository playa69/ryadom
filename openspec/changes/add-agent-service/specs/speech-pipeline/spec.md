# Дельта-спецификация: speech-pipeline

## Purpose

Голосовая цепочка агента «Слышу Рядом»: потоковое распознавание речи (ASR) и синтез речи (TTS) через SaluteSpeech внутри сервиса agent, с кэшем типовых фраз и деградацией в текстовый режим при отказе голосовых компонентов.

## ADDED Requirements

### Requirement: ASR-стриминг

Агент SHALL принимать поток аудио-чанков (opus/pcm16, base64) от вызывающей стороны и транскрибировать его через SaluteSpeech ASR в потоковом режиме, возвращая частичные гипотезы (`transcript.partial`) по мере распознавания и финальный транскрипт (`transcript.final`) по завершении реплики. Аудио MUST NOT сохраняться на диск; хранение транскриптов — ответственность вызывающей стороны.

#### Scenario: Потоковая транскрибация

- **WHEN** вызывающая сторона шлёт последовательность аудио-чанков и сигнал завершения реплики
- **THEN** агент возвращает ≥ 0 событий `transcript.partial` и ровно один `transcript.final` с полным текстом реплики

#### Scenario: Пустая реплика

- **WHEN** аудио не содержит распознаваемой речи
- **THEN** `transcript.final` содержит пустой текст, конвейер не запускает генерацию, вызывающая сторона получает событие об отсутствии речи

### Requirement: TTS-стриминг

Агент SHALL озвучивать сгенерированный ответ через SaluteSpeech TTS, передавая аудио-чанки вызывающей стороне по мере готовности (не дожидаясь полного синтеза). Голос TTS MUST выбираться из настроек пользователя, передаваемых вызывающей стороной; при отсутствии настройки — голос по умолчанию. Кризисное вмешательство MUST озвучиваться в приоритетном порядке.

#### Scenario: Потоковый синтез

- **WHEN** генерация ответа завершена или накоплено достаточно текста
- **THEN** аудио-чанки TTS передаются по мере готовности, по завершении — сигнал конца озвучки

#### Scenario: Выбор голоса

- **WHEN** в запросе передан `voice_id` из списка доступных голосов
- **THEN** синтез выполняется указанным голосом; при невалидном `voice_id` — голосом по умолчанию

### Requirement: Кэш типовых фраз

Агент SHALL кэшировать TTS-аудио типовых фраз (ритуалы, приветствия, кризисное вмешательство) в Redis с TTL: повторный запрос идентичной фразы тем же голосом MUST отдаваться из кэша без вызова SaluteSpeech.

#### Scenario: Повторная фраза из кэша

- **WHEN** запрашивается озвучка фразы, уже синтезированной тем же голосом ранее
- **THEN** аудио отдаётся из кэша, вызов SaluteSpeech TTS не выполняется

### Requirement: Деградация в текстовый режим

При отказе ASR агент MUST продолжать принимать текстовые реплики без распознавания; при отказе TTS агент MUST возвращать ответ текстом без аудио. Каждый отказ MUST сопровождаться событием деградации для вызывающей стороны и метрикой. Восстановление компонента MUST происходить автоматически (circuit breaker с полуоткрытым состоянием).

#### Scenario: Отказ TTS

- **WHEN** SaluteSpeech TTS недоступен
- **THEN** ответ возвращается текстом, высылается событие деградации голосового вывода, диалог продолжается

#### Scenario: Отказ ASR

- **WHEN** SaluteSpeech ASR недоступен, а пришёл аудио-поток
- **THEN** высылается событие деградации голосового ввода с приглашением написать текстом, генерация по аудио не выполняется

### Requirement: Устойчивость внешних вызовов

Все вызовы SaluteSpeech SHALL выполняться с таймаутами, retry с backoff (для идемпотентных операций) и circuit breaker. Ошибки провайдера MUST NOT приводить к зависанию конвейера дольше настроенного таймаута.

#### Scenario: Таймаут провайдера

- **WHEN** SaluteSpeech не отвечает дольше настроенного таймаута
- **THEN** вызов прерывается, срабатывает сценарий деградации соответствующего компонента
