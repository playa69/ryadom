# Дельта-спецификация: agent-core

## Purpose

Ядро диалоговой логики агента «Слышу Рядом»: конвейер обработки реплики, режимы диалога, кризисный протокол с приоритетом над всем, классификация эмоций, retrieval памяти и стрим-генерация ответов через OpenAI-совместимый LLM API (модели в Cloud.ru, данные в РФ).

## ADDED Requirements

### Requirement: Конвейер обработки реплики

Агент SHALL обрабатывать каждую реплику пользователя конвейером: (1) получение текста реплики (напрямую или из ASR — см. speech-pipeline); (2) кризис-классификация; (3) классификация эмоций; (4) retrieval памяти; (5) стрим-генерация ответа LLM; (6) опциональный TTS (см. speech-pipeline). Порядок MUST гарантировать, что кризис-классификация выполняется до генерации ответа. Каждый этап MUST быть независимо наблюдаем (трейсинг этапа с длительностью и результатом).

#### Scenario: Текстовая реплика полного цикла

- **WHEN** агент получает текстовую реплику в активной сессии с `level=green`
- **THEN** выполняются этапы 2–5, ответ стримится токенами, каждый этап покрыт трейсом с длительностью

#### Scenario: Кризис перекрывает генерацию

- **WHEN** кризис-классификатор возвращает `level=red` на любой реплике
- **THEN** этапы retrieval и обычной генерации пропускаются, запускается кризисная ветвь (см. «Кризисный протокол»)

### Requirement: Режимы диалога

Агент SHALL поддерживать режимы сессии `vent`, `chat`, `gestalt_diary`, `recovery`, `rituals`, заданные при создании сессии. Режим MUST определять системный промпт, набор инструментов и стиль ответов (vent — без советов, если не просят; recovery — бережный, с учётом HALT; rituals — ведение ритуала утро/вечер). Режим MUST передаваться в каждый вызов генерации. Значение `warmth` MUST отклоняться ошибкой валидации (зарезервировано под v1).

#### Scenario: Режим vent без советов

- **WHEN** сессия в режиме `vent` и пользователь выговаривается без явного запроса совета
- **THEN** ответы сгенерированы по промпту режима `vent` (отражение чувств, без непрошеных рекомендаций)

#### Scenario: Зарезервированный режим

- **WHEN** в запросе на обработку реплики передан режим `warmth`
- **THEN** запрос отклонён ошибкой валидации режима

### Requirement: Кризисный протокол

Агент SHALL классифицировать каждую реплику двухступенчатым классификатором с приоритетом recall (быстрые эвристики/словари → LLM-классификатор на дешёвой модели) с уровнями `green`/`yellow`/`red`. При `level=red` агент MUST прервать обычный конвейер и выдать кризисное вмешательство: деэскалационный ответ + ресурсы помощи (горячие линии), независимо от режима сессии, лимитов и метрик. Кризисное вмешательство MUST быть детерминированным (не зависеть от LLM-генерации в момент срабатывания). При `level=yellow` агент MUST смягчить стиль ответа и усилить мониторинг без прерывания диалога.

#### Scenario: Срабатывание red в любом режиме

- **WHEN** реплика с признаками суицидального риска приходит в сессии любого режима
- **THEN** агент немедленно выдаёт детерминированное кризисное вмешательство (деэскалация + горячие линии), обычная генерация не выполняется

#### Scenario: Уровень yellow

- **WHEN** классификатор возвращает `yellow`
- **THEN** диалог продолжается, ответ генерируется в смягчённом стиле, статус `yellow` передан вызывающей стороне

### Requirement: Классификация эмоций

Агент SHALL определять эмоциональные теги каждой реплики пользователя (набор тегов с валентностью, напр. anxiety/sadness/anger/joy + интенсивность). Теги MUST возвращаться вызывающей стороне вместе с ответом для записи в `messages.emo_tags` и персонализации.

#### Scenario: Теги эмоций в ответе

- **WHEN** обработка реплики завершена без кризиса
- **THEN** результат содержит эмоциональные теги реплики с интенсивностью

### Requirement: Retrieval памяти

Агент SHALL обогащать контекст генерации памятью пользователя: факты L2-профиля и релевантные прошлые сообщения (поиск по эмбеддингам pgvector) с весом давности и признаком «время с последней сессии». Retrieval MUST учитывать только данные текущего пользователя. При `incognito_session=true` агент MUST NOT читать долговременную память и MUST NOT возвращать данные для записи в память.

#### Scenario: Персонализированный ответ

- **WHEN** у пользователя есть факты памяти и прошлые сессии, релевантные реплике
- **THEN** генерация использует их как контекст (упоминание близких, триггеров, что работало раньше)

#### Scenario: Инкогнито

- **WHEN** сессия помечена `incognito_session=true`
- **THEN** долговременная память не читается, в результате отсутствуют данные для записи в память

### Requirement: Генерация ответа через OpenAI-совместимый API

Агент SHALL генерировать ответы стримом (токен за токеном) через OpenAI-совместимый Chat Completions API с endpoint и ключом из конфигурации (провайдер Cloud.ru). Модель генерации, модель классификаторов и модель эмбеддингов MUST задаваться конфигурацией независимо друг от друга. При недоступности LLM-провайдера агент MUST вернуть ошибку деградации (см. agent-api), а не молча зависнуть. Эмбеддинги для retrieval MUST получаться тем же OpenAI-совместимым интерфейсом.

#### Scenario: Стрим-генерация

- **WHEN** конвейер дошёл до генерации
- **THEN** токены ответа передаются вызывающей стороне по мере поступления, по завершении — финальное событие с полным текстом

#### Scenario: Недоступность провайдера

- **WHEN** LLM-провайдер недоступен или истёк таймаут
- **THEN** вызывающая сторона получает ошибку деградации с кодом, позволяющим показать пользователю мягкий фолбэк

### Requirement: PII-фильтрация перед внешними вызовами

Агент SHALL маскировать персональные данные (NER: ФИО, телефоны, адреса, документы) в тексте, отправляемом внешним моделям (LLM, классификаторы, эмбеддинги), и восстанавливать маскированные сущности в сгенерированном ответе, если модель их переиспользовала.

#### Scenario: Маскирование ПДн

- **WHEN** реплика содержит ФИО и телефон
- **THEN** во внешний вызов уходит текст с замаскированными сущностями; логи вызова не содержат исходных ПДн

### Requirement: Антизависимый контур

Агент SHALL поддерживать сигнал «долгая сессия/высокая дневная нагрузка» от вызывающей стороны: при наличии флага агент MUST мягко подводить к завершению и рекомендации живого контакта вместо удержания в диалоге. Агент MUST NOT генерировать контент, поощряющий зависимость (обещания «я всегда рядом, только со мной», ревность к живым людям).

#### Scenario: Сигнал перегрузки

- **WHEN** запрос на обработку реплики содержит флаг превышения дневного лимита минут
- **THEN** ответ мягко подводит к завершению сессии и/или рекомендует живой контакт
