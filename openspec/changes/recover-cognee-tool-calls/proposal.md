# Proposal: Восстановить Tool calls из журналов Cognee

## Why

До TOOL-инструментации Langfuse агент не сохранял вызовы памяти в пригодном для backfill виде. При этом часть операций сохранилась во внутренних `pipeline_runs` и HTTP access-логах Cognee. Владелец явно решил заполнить все фактически подтверждённые вызовы по дням без сопоставления с аккаунтами.

## What Changes

- Восстановить успешные `search`, пары `add+cognify` и удаления за 05.11–17.11.2026.
- Хранить восстановленные суточные суммы отдельно от неизменяемых снимков Langfuse и брать максимум двух источников.
- За 05.11–09.11 использовать `pipeline_runs`; за 10.11–17.11 — access-логи; собственные диагностические вызовы `postdeploy-synthetic-*` не включать.
- Сохранить текущий TOOL-трейсинг Langfuse для новых операций.

## Impact

- Поверхности: dashboard.
- Восстановленные исторические значения включают все подтверждённые вызовы без проверки `traffic_type`; новые записи Langfuse по-прежнему исключают test/internal.
- Миграция БД дашборда: новая таблица агрегатов `tool_call_recovery(day, tool_requests, source)` без идентификаторов и текстов людей.
