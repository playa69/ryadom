# Дельта-спецификация: user-profile

## Purpose

Управление аккаунтом и данными пользователя: профиль, настройки (голос, уведомления, приватность, лимиты), прозрачность и редактирование фактов памяти, пуш-токены, состояние дня и необратимое удаление всех данных одним действием.

## ADDED Requirements

### Requirement: Профиль пользователя

Сервис SHALL возвращать профиль через `GET /users/me` и обновлять через `PATCH /users/me` (частично: `display_name`, `age_group`). Возраст MUST храниться возрастной группой (`18_24`, `25_34`, `35_44`, `45_54`, `55_plus`), дата рождения MUST NOT запрашиваться и храниться. Ответ MUST включать флаги `is_anonymous`, `has_email`, `age_confirmed`, `consents_completed`.

#### Scenario: Чтение профиля

- **WHEN** аутентифицированный пользователь вызывает `GET /users/me`
- **THEN** возвращается профиль с флагами состояния аккаунта

#### Scenario: Обновление обращения и возрастной группы

- **WHEN** пользователь вызывает `PATCH /users/me` с `display_name` и валидной `age_group`
- **THEN** профиль обновлён, возвращается актуальное состояние

#### Scenario: Невалидная возрастная группа

- **WHEN** клиент передаёт `age_group` вне перечисленных значений
- **THEN** возвращается 422 `VALIDATION_ERROR`

### Requirement: «Стереть всё» — необратимое удаление данных

Сервис SHALL удалять все данные пользователя по `DELETE /users/me` с обязательной строкой-подтверждением. Удаление MUST быть необратимым и каскадным: транскрипты, память (факты, эмбеддинги), профиль, настройки, пуш-токены, журнал, чекины, сессии, токены доступа. Удаление MUST выполняться асинхронной фоновой задачей; ответ — 202 со статусом `scheduled` и `deletion_request_id`. Факт удаления MUST фиксироваться в аудите (`deletion_requests`) без сохранения контента. Неверное подтверждение MUST отклоняться с 422.

#### Scenario: Запуск удаления

- **WHEN** пользователь вызывает `DELETE /users/me` с верным подтверждением
- **THEN** возвращается 202 со статусом `scheduled`, фоновая задача поставлена, токены пользователя отозваны

#### Scenario: Каскад завершён

- **WHEN** фоновая задача завершается
- **THEN** все данные пользователя во всех таблицах удалены, в `deletion_requests` — запись о факте удаления без контента

#### Scenario: Неверное подтверждение

- **WHEN** пользователь передаёт неверную строку-подтверждение
- **THEN** возвращается 422 `VALIDATION_ERROR`, удаление не запускается

### Requirement: Прозрачность фактов памяти

Сервис SHALL предоставлять пользователю просмотр и редактирование хранящихся о нём фактов памяти: `GET /users/me/facts` (cursor-пагинация, фильтр `category`), `PATCH /users/me/facts/{id}` (правка текста), `DELETE /users/me/facts/{id}`. Категории: `themes`, `values`, `triggers`, `coping`, `close_people`, `big5`, `works_for_user`. Факт MUST содержать `text`, `confidence`, `source`, `updated_at`. Факты MUST NOT отображаться как ярлыки/диагнозы — только редактируемые факты.

#### Scenario: Список фактов

- **WHEN** пользователь запрашивает `GET /users/me/facts`
- **THEN** возвращается страница фактов с категорией, текстом, confidence и source

#### Scenario: Правка факта

- **WHEN** пользователь вызывает `PATCH /users/me/facts/{id}` с новым текстом
- **THEN** текст факта обновлён, `source` помечен как `user_edit`

#### Scenario: Удаление факта

- **WHEN** пользователь вызывает `DELETE /users/me/facts/{id}`
- **THEN** факт удалён и более не используется в retrieval памяти

#### Scenario: Чужой или несуществующий факт

- **WHEN** пользователь обращается к факту другого пользователя или несуществующему
- **THEN** возвращается 404 `FACT_NOT_FOUND`

### Requirement: Настройки пользователя

Сервис SHALL предоставлять `GET /users/me/settings` и `PATCH /users/me/settings` (частичный мерж по полям): `voice_id` (один из 2–3 вариантов, список в `available_voices`), `theme` (dark/light/system), `notifications` (enabled, тихие часы from/to), `privacy` (`store_transcripts`, `incognito_session`), `limits` (`voice_minutes_per_day`, 5–240). Невалидный `voice_id` MUST отклоняться с 422.

#### Scenario: Чтение настроек

- **WHEN** пользователь вызывает `GET /users/me/settings`
- **THEN** возвращаются текущие настройки и список доступных голосов

#### Scenario: Частичное обновление

- **WHEN** пользователь вызывает `PATCH /users/me/settings` только с `notifications.quiet_hours`
- **THEN** обновлены только тихие часы, остальные поля без изменений

#### Scenario: Выключение хранения транскриптов

- **WHEN** пользователь устанавливает `store_transcripts=false`
- **THEN** новые транскрипты не сохраняются

#### Scenario: Невалидный голос

- **WHEN** клиент передаёт `voice_id` вне `available_voices`
- **THEN** возвращается 422 `VALIDATION_ERROR`

### Requirement: Регистрация пуш-токенов

Сервис SHALL регистрировать пуш-токен текущего устройства через `PUT /users/me/devices/current/push-token` (provider: `apns`, `fcm`, `rustore`). Операция MUST быть идемпотентным upsert по устройству; ответ — 204.

#### Scenario: Регистрация токена

- **WHEN** клиент вызывает `PUT /users/me/devices/current/push-token` с валидным provider и токеном
- **THEN** токен сохранён для устройства, возвращается 204

#### Scenario: Повторная регистрация

- **WHEN** клиент повторяет вызов с тем же токеном
- **THEN** состояние не меняется, возвращается 204

### Requirement: Состояние дня и антизависимый контур

Сервис SHALL возвращать агрегированное состояние через `GET /users/me/state`: `minutes_today`, `soft_recommendation`, `who5_last`, `clean_time_seconds` (режим recovery, иначе null), `streak` (count, status active/resting, resting_days). При устойчивом превышении 90 минут в день `soft_recommendation` MUST быть `true` (мягкая рекомендация живого контакта, без жёстких запретов); триггер MUST срабатывать для 100% пользователей с паттерном переиспользования.

#### Scenario: Обычное состояние

- **WHEN** пользователь с умеренным использованием запрашивает `GET /users/me/state`
- **THEN** возвращаются минуты дня, `soft_recommendation=false`, серия ритуалов

#### Scenario: Паттерн переиспользования

- **WHEN** пользователь устойчиво проводит более 90 минут в день
- **THEN** `soft_recommendation=true`

#### Scenario: Пользователь в режиме recovery

- **WHEN** пользователь режима recovery запрашивает состояние
- **THEN** `clean_time_seconds` содержит актуальный счётчик чистого времени
