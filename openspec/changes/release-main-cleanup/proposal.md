# Выкат main-cleanup: ломающие изменения контракта API

Заметка для ворот `release-check` и для истории выката. Ветка только для сборки образов api, web и pwa, в `main` не вливается.

## BREAKING

Контракт API меняется не только добавлением (BREAKING). Что убрано или сужено по сравнению с прежним прод-образом:

- память «фактов» заменена заметками: убраны создание факта (`POST /api/memory/facts`), поля `lastConfirmedAt` и `confirmCount`, статус `Pinned`, подтверждение (`confirm`), слоты и статус в запросе правки, режимы `MemoryServiceMode`, лимит `MemoryFactMin`, коды ошибок `FACT_UNSUPPORTED`, `MEMORY_NOT_ALLOWED`, `MEMORY_DISABLED`;
- `MemoryChangesStatus.Skipped` убран: шлюз отдаёт пустой `ready`;
- убраны `DialogShareApiErrorCode.SHARE_DISABLED` (флаг ссылки на разговор удалён) и `PwaMeta.AppEnv`;
- флаги аналитики в `AnalyticsFeatures` стали постоянными значениями.

## План совместимости

- Решение владельца: прод-клиентов, для которых нужна совместимость со старым API памяти, нет; поддержка старых вкладок и закешированных PWA не требуется.
- Для закешированных клиентов оставлено то, что дёшево: `GET /api/memory` по-прежнему отдаёт `facts` в старой форме (копия заметок), `PATCH` и `DELETE /api/memory/facts/:id` действуют на заметки.
- Образы web и pwa выкатываются в том же шаге после api; пакет JS нативных оболочек приходит по OTA. Нативная сборка не нужна.
- Откат: прежние образы api, web и pwa (тег 0.9.3 и 0.8.1); схема базы только добавляется, прежний api её не читает и не мешает.
