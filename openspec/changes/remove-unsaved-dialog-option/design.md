## Context

Выбор несохранения проходит от первого и главного экранов через общий расчёт старта в `POST /api/dialogs`. PWA, Android, iOS и Telegram используют один JS в `apps/mobile`, поэтому удаление состояния галочки распространяет единое поведение на все эти платформы. API и агент должны продолжать обслуживать старые клиенты и уже начатые несохраняемые разговоры.

## Goals / Non-Goals

**Goals:**

- Удалить выбор несохранения из web и общего мобильного клиента для PWA, Android, iOS и Telegram.
- Во всех актуальных клиентах начинать новые разговоры сохраняемыми независимо от режима памяти.
- Сохранить отображение и завершение уже начатых несохраняемых разговоров везде.

**Non-Goals:**

- Не менять `app/packages/client-core/src/dialog-start.ts`: общий расчёт уже умеет сохраняемый старт и используется тестами совместимости.
- Не удалять `saved` из контрактов, API, агента, базы или ответов сервера.
- Не менять нативный код, нативные версии, `OTA_MIN_NATIVE_BUILD`, продуктовую аналитику и хранение разговоров.

## Decisions

1. **Убрать источник выбора из клиентов.** В `apps/web/components/HomeScreen.tsx` уже удалены состояние и разметка галочки. В общем мобильном JS дополнительно удаляются `unsaved`, платформенные условия и перенос `saved` между первым и главным экранами. Все вызовы `chosenStart` получают отсутствие выбора несохранения.

2. **Сохранить только выбор памяти.** «Запоминать важное» и «Без памяти» продолжают формировать поле `memory` как прежде. Внутренний `TalkRequest` сохраняет только `rememberMemory`; выбор сохранения больше не переносится между экранами. Подпись «Без памяти» прямо называет результат обоих состояний переключателя, чтобы не читаться как второй выбор несохранения.

3. **Серверные ответы не трогать.** `DialogScreen`, `DialogPage`, листы завершения и журнал продолжают читать `saved: false` от сервера. Общие тексты `UNSAVED_LABEL`, `UNSAVED_HINT`, `UNSAVED_NOTE`, `UNSAVED_END_NOTE`, `UNSAVED_GONE` и пометка журнала остаются для существующих разговоров и старых клиентов.

4. **Разделить актуальное поведение и совместимость в тестах.** Актуальные web, PWA и Telegram получают проверки отсутствия галочки и сохраняемого старта. Сквозные сценарии несохраняемого режима создают разговор изменением запроса до `saved: false`, как от старого клиента, чтобы проверить совместимость без удалённого контрола.

5. **Доставить общий JS через OTA.** Образы web и PWA обновляют свои клиенты, образ api несёт OTA-пакет для установленных Android и iOS. Нативные файлы не меняются, поэтому новые сборки для магазинов и рост `OTA_MIN_NATIVE_BUILD` не нужны.

## Risks / Trade-offs

- Старые клиенты продолжат создавать несохраняемые разговоры до обновления → это требование совместимости, а не случайный обход удаления.
- Playwright не проверяет настоящие Android WebView, iOS и Telegram → автоматические проверки общего JS дополняются явным списком непроверенных устройств в PR.
- Один PR включает web и мобильный JS → перед сдачей нужны полный набор тестов и выкат api, pwa и web согласованным порядком.

## Migration Plan

Миграций БД нет. После merge выкатываются api с OTA, PWA и web; порядок и постпроверки определяет скилл deploy. Откат возвращает прежние образы и OTA-пакет; серверные данные и поведение API не меняются, поэтому дополнительный откат данных не требуется.
