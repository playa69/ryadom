# Design: add-backend-journal-rituals-checkins

## Context

Строится поверх add-backend-foundation-auth (каркас, auth, идемпотентность через Redis, rate-limit) и потребляет user_settings (тихие часы, уведомления) из add-backend-profile-settings. Контракт — specs/wellbeing/spec.md + docs/openapi.yaml (теги `journal`, `rituals`, `checkins`). Мотивация — см. proposal.md (Why).

## Goals / Non-Goals

**Goals:**

- Расписания и фон — только Celery + beat (стек config.yaml, решение пользователя; Arq не используем).
- Серии ритуалов — вычисляемые из фактов выполнений, без отдельного счётчика, который можно «сломать».
- Payload чекинов — типизированные схемы по type, хранение в jsonb.

**Non-Goals:**

- Календарные интеграции (EventKit/Calendar Provider) — клиентская сторона спеки, backend не участвует.
- Консолидация памяти L3 («что помогает именно ему») — отдельный change.
- Адаптивный тайминг пушей из темпоральных паттернов — v1; на MVP напоминания по фиксированным окнам + тихие часы.

## Decisions

### D1. Celery + beat для фона (НЕ Arq)

Worker и beat — отдельные контейнеры того же образа (команды `celery worker` / `celery beat`). Задачи: `generate_daily_rituals` (beat, ежедневно), `send_ritual_reminders` (beat, периодически). Решение пользователя: Arq исключён; Celery закрывает и разовые задачи (суммаризация — sessions-streaming), и расписания.

### D2. Серия ритуалов — вычисление из ritual_completions

Отдельного поля-счётчика нет: streak считается запросом по `ritual_completions` (последовательные дни с выполнением; пропуск → `resting` + `resting_days`, счётчик сохраняется). Идемпотентность complete в пределах дня — unique constraint (ritual_id, user_id, date).

**Почему:** единственный источник истины — факты выполнений; «серия отдыхает» — это проекция, а не состояние, которое надо мигрировать/чинить.

### D3. Ритуалы — каталог + персональные экземпляры дня

`rituals` — каталог (kind, title, duration_seconds, content jsonb); персонализация — в `content` экземпляра дня, сгенерированного beat-задачей из памяти пользователя (темы, close_people). На MVP допустимо: каталог статичен, адаптация — подстановка контекста в текст ритуала лёгкой моделью.

### D4. Payload чекинов — дискриминированные схемы

Pydantic-схемы HaltPayload/Who5Payload/TensionPayload, дискриминатор `type`; хранение — jsonb + вычисленный `score` для who5 (сумма × 4) отдельной колонкой для агрегатов. `clean_time_seconds` — вычисляемый: now − started_at режима recovery (или − ts последнего срыва, тип события — чекин/реплика; на MVP — от даты активации режима).

### D5. Идемпотентность чекинов — через общий механизм foundation

`Idempotency-Key` → Redis (ключ user_id + path + key, TTL 24 ч, хранение первого ответа) — механизм из add-backend-foundation-auth; повтор возвращает сохранённый ответ.

### D6. Журнал — шифрование text_enc, поиск по расшифрованному тексту не делаем

Тексты записей шифруются (Fernet/AES-GCM, ключ из foundation). Поиск `q` — по title (нешифрованный) и по расшифровке в пределах страницы на MVP; полнотекстовый поиск по шифрованному контенту — осознанно вне scope (trade-off приватности).

## Risks / Trade-offs

- [Beat-задача генерации ритуалов падает — у пользователей пустой день] → ретраи + fallback на статичный каталог без персонализации; алерт по метрике задач.
- [Подсчёт streak на лету дорожает с историей] → индекс (user_id, completed_at); при росте — материализация streak в user_settings.
- [Поиск q по журналу неполный (только title/страница)] → осознанный trade-off приватности (D6), зафиксирован в контракте поведением, а не скрыт.
- [Часовые пояса пользователей для «дня» и тихих часов] → день и тихие часы считаются в timezone пользователя (настройка, дефолт Europe/Moscow); timezone хранится в user_settings.

## Migration Plan

1. Миграция Alembic `0004_wellbeing` (journal_entries, rituals, ritual_completions с unique (ritual_id, user_id, date), checkins).
2. Деплой worker + beat контейнеров; сидирование каталога ритуалов миграцией (утренний/вечерний базовые).
3. Проверка: создать запись → экспорт → complete ритуала → streak → чекин who5 → history с агрегатами.
4. Откат: откат контейнеров, downgrade.

## Open Questions

- Окна напоминаний по умолчанию (утро/вечер) — подбираются с консультантами, значения в конфиге.
- Точный список базовых ритуалов каталога (тексты) — контент от консультантов-гештальттерапевтов, сидируется миграцией отдельно от кода.
