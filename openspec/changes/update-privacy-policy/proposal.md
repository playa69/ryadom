## Why

Владелец предоставил финальную шестираздельную редакцию `/privacy` и явно потребовал опубликовать именно её, без самостоятельных редакционных поправок. При локальной проверке он дополнительно попросил синхронизировать с ней видимый срок хранения разговоров на `/home` и заменить адрес поддержки на почту Оператора.

## What Changes

- `/privacy` получает предоставленный текст целиком: общие положения; цели, данные, основания и сроки; хранение и передача; порядок обработки и защита; права и удаление; cookie, возраст, изменения и контакты.
- Заголовок становится «Политика обработки персональных данных сервиса «Рядом»». Отдельная строка с датой редакции и добавленные ранее редакторские пояснения убираются, поскольку их нет в предоставленном тексте.
- В документе остаются указанные владельцем сроки: текст разговора и повод для напоминания — 30 дней, неактивный аккаунт — 90 дней, события использования — 12 месяцев, обращения — 1 год.
- Общая клиентская подпись меняется на «Разговоры хранятся 30 дней после последнего сообщения.» на первом экране, в журнале и после разговора во web, PWA, нативных клиентах и Telegram. Срок гостевого аккаунта без визитов остаётся 90 дней. Фактическая очистка разговоров агентом остаётся 90 дней и этим change не меняется.
- Самопроверка описывается как хранящаяся только на устройстве; уведомления — с ежедневным автоматическим анализом; аналитические cookie — только после согласия в баннере.
- В списке обработчиков остаются Timeweb Cloud, Cloud.ru и Яндекс Метрика; PostHog Cloud EU и редакторский абзац о нём убираются. Документ содержит утверждение об отсутствии трансграничной передачи.
- Сохраняются предоставленные положения о шифровании отдельным ключом на аккаунт, двухфакторной аутентификации, QR-переносе и отключённом Вебвизоре. Они публикуются по прямому решению владельца, без изменения кода продукта.
- Почта поддержки лендинга и значение `PUBLIC_SUPPORT_EMAIL` в конфигурации кластера меняются на `playasn@yandex.ru`; ссылки `mailto:` продолжают использовать то же значение. Конфигурация изменяется только в репозитории и не применяется без отдельного разрешения.
- Существующие адаптивные таблицы, ссылка на `/delete-account` и рабочий переключатель отказа от аналитики сохраняются. `/terms` по содержанию не меняется, но использует новую почту из окружения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `landing-site`: новая редакция политики и почта Оператора по умолчанию и в конфигурации окружения.
- `data-retention`: видимый срок разговоров — 30 дней, срок гостевого аккаунта и фактическая очистка не меняются.
- `account-auth`: на первом экране отображается 30 дней для разговоров и 90 дней для аккаунта.
- `dialog-history`: пояснения журнала используют 30 дней для разговоров.
- `telegram-mini-app`: первый экран Mini App использует 30 дней для разговоров.

## Impact

| Поверхность | Затрагивается          |
| ----------- | ---------------------- |
| agent       | нет                    |
| api         | нет                    |
| web         | да                     |
| pwa         | да                     |
| android     | да, текст из общего JS |
| ios         | да, текст из общего JS |
| tg          | да                     |
| admin       | нет                    |
| landing     | да                     |

Меняются текст политики, общая клиентская константа и её unit-тест, публичная почта лендинга, локальные и кластерные значения `PUBLIC_SUPPORT_EMAIL`, e2e и скриншоты. Контракт API, база и нативный код не меняются. Для выката потребуются образы landing, web, pwa и api (OTA), а также применение `PUBLIC_SUPPORT_EMAIL`; новых переменных нет.

`add-explicit-data-consent` также меняет требование `account-auth` «Первый экран: разговор с первого действия». При архивации более позднего change его дельту нужно перенести на уже обновлённую спеку, сохранив и явное согласие, и строку о 30 днях. В `add-explicit-data-consent` следует оставить такую же пометку.

Предоставленный текст местами расходится с текущим кодом и инфраструктурной документацией. По прямому решению владельца страница и клиентские подписи используют 30 дней, тогда как фактическая очистка агента остаётся 90 дней; это и остальные расхождения фиксируются в `design.md` и итоговом отчёте.

Вне рамок: изменение фактических сроков хранения, внедрение шифрования или cookie-баннера, новые функции уведомлений, юридическая оценка текста, правки содержания `/terms` и `/consent`, выкат в прод и применение манифестов.
