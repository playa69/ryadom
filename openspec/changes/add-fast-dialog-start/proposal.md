## Why

Первое сообщение — главное действие продукта, но на Web его затмевают второстепенные настройки, а в PWA и Telegram до диалога можно начать только голосовой разговор. Упрощаем путь к первому сообщению по мотивам анализа Mindglow, сохраняя обязательное согласие и не добавляя анкету перед разговором.

## What Changes

- На главном экране Web появятся короткие подсказки начала разговора. Выбор подсказки только подставит редактируемый черновик и не создаст аккаунт, разговор или запрос.
- На Web необязательная настройка памяти будет свёрнута в «Настроить разговор», чтобы поле сообщения и голосовой старт оставались основными действиями.
- На главном экране PWA и Telegram появятся поле первого сообщения и те же подсказки; новый человек попадёт на главную сразу, без отдельного экрана перед ней. С текстом основная кнопка станет «Отправить», без текста останется «Поговорить» и запустит голосовой разговор.
- Текстовый старт в PWA и Telegram откроет диалог сразу в текстовом виде, покажет первое сообщение под приветствием и отправит его один раз после готовности соединения. Микрофон сам не включится.
- Web, PWA, Telegram и все публичные страницы лендинга (главная и документы) будут по умолчанию использовать светлую тему с 07:00 до 21:59 и тёмную с 22:00 до 06:59 по местному времени устройства. Открытый клиент или вкладка сменит тему на границе без перезагрузки; зависимости от системной темы не будет.
- В правой верхней части Web, PWA, Telegram и каждой публичной страницы лендинга появится компактный переключатель темы, показывающий текущую тему: солнце в светлой и светящийся полумесяц в тёмной. Ручной выбор применяется сразу, сохраняется только на этом устройстве, не создаёт запрос и далее имеет приоритет над расписанием до следующего ручного изменения. Содержимое и поведение лендинга не меняются.
- Отдельного обязательного входного ворота согласия на Web, PWA и Telegram больше не будет. При первой попытке отправить текст или начать голосовой разговор без записанного согласия поверх главной откроется модальное окно (в мобильном клиенте — лист) с существующим обязательным снятым флажком 18+ и согласием на обработку данных, ссылками на условия и согласие и неактивной до отметки кнопкой «Продолжить». До подтверждения аккаунт, разговор и запросы от имени человека не создаются; ввод текста, выбор подсказки и переключение темы запросов не вызывают. Закрытие окна (кнопкой, Esc или нажатием на фон) сохраняет черновик и намерение без запроса. После подтверждения исходное действие продолжается автоматически: создаётся аккаунт при необходимости, записываются согласия, начинается разговор, текст уходит один раз либо начинается голос. Ошибка сохраняет черновик и позволяет повторить без повторного окна.
- Согласие на память останется отдельным необязательным выбором на главной. Вопрос о незавершённом разговоре и восстановление после ошибки сохранятся. Публичный API и агент не меняются; это не **BREAKING**.
- На Android и iOS останутся прежние экраны, включая предварительный входной ворот согласия, тёмная тема и только голосовой старт с главной. Общий JS будет явно исключать нативную платформу из новых сценариев.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `app-shell`: компоновка быстрого старта на Web; поле первого сообщения и подсказки на PWA/Telegram; светлая и тёмная тема по местному времени с сохраняемым ручным переключателем на Web, PWA, Telegram и публичных страницах лендинга при неизменном нативном главном экране и нативной тёмной теме.
- `dialog`: передача и однократная отправка первого текста в PWA/Telegram, выбор текстового вида и сохранение черновика во всех ветках старта.
- `account-auth`: окно согласия при первом действии вместо отдельного входного ворота на Web, PWA и Telegram, автоматическое продолжение исходного действия после подтверждения; прежний предварительный ворот и только голосовой старт сохраняются на Android и iOS.

## Impact

| Поверхность | Затрагивается                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| agent       | нет                                                                                                          |
| api         | нет, код и контракт не меняются                                                                              |
| web         | да                                                                                                           |
| pwa         | да                                                                                                           |
| android     | нет, прежнее поведение через явное исключение в общем JS                                                     |
| ios         | нет, прежнее поведение через явное исключение в общем JS                                                     |
| tg          | да, через общий JS мобильного клиента                                                                        |
| admin       | нет                                                                                                          |
| landing     | да, тема по местному времени и переключатель на всех публичных страницах; содержимое и поведение не меняются |

Затрагиваются стартовые и главные экраны Web и `apps/mobile`, публичные страницы `apps/landing` (только оформление и переключатель темы), передача параметров в экран диалога, общий модуль темы `packages/client-core`, общие цветовые токены `packages/design` и `packages/ui`, связанные unit-тесты, Playwright и `docs/spec.md`. Новых зависимостей, миграций, нативных файлов, плагинов и изменений `OTA_MIN_NATIVE_BUILD` нет. Макеты — `mockups/fast-start.md`.

Параллельный change `remove-unsaved-dialog-option` не изменяется: его код уже есть в `main`, а его требования этот change не переписывает. Формулировки затронутых требований о текущих главных экранах синхронизируются с этим уже влитым поведением, чтобы не вернуть удалённую галочку при будущей архивации.

Вне рамок: анкета знакомства, сбор возраста или пола, изменение содержания лендинга, A/B-инфраструктура, нативные iOS/Android, изменение API и выкат.
