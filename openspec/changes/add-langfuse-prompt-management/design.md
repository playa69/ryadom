## Context

В `agent/` уже есть Langfuse SDK v3 и ручной жизненный цикл generation/span. Установленный SDK поддерживает `label`, TTL кэша, `fetch_timeout_seconds` и параметр `prompt` у generation. Prompt Management в кластере пуст, поэтому начальные версии можно создать без миграции чужих данных.

Инструкции разбросаны по вызовам моделей. Часть диалога составная: базовый текст, addendum Live, правила памяти и правило рода; в пути Сбера добавляются голосовые правила и замена рода под фактический голос. Установленный TTL по умолчанию — 60 секунд, его и принимаем как контракт обновления.

Владелец отдельно потребовал не оставлять локальный резерв: текстов инструкций в репозитории быть не должно. Поэтому исходный вариант с `fallback` в SDK отменён.

## Goals / Non-Goals

**Goals:**

- Langfuse — единственный источник текстов всех статических инструкций.
- Единый каталог имён и меток назначения без содержимого промптов.
- Чтение `production` в месте каждого вызова, а не один раз при старте процесса.
- Связь prompt → generation и метаданные всех составных частей.
- Повторяемая начальная загрузка из внешнего файла без перезаписи административных версий.

**Non-Goals:**

- Не храним резервные тексты в Python, Markdown, тестовых фикстурах или других файлах репозитория.
- Не подставляем пустую или заранее зашитую инструкцию при недоступном Langfuse.
- Не меняем модели, JSON-схемы, валидаторы, кризисные фразы и пользовательские API.
- Не делаем автоматический deploy labels, A/B-тестирование и собственный UI.
- Не меняем инструкцию уже открытой модельной сессии посреди хода.

## Decisions

### 1. Каталог без текстов

Новый модуль `agent/app/prompts/catalog.py` содержит реестр `PromptDefinition`: имя и tags. Текста в `PromptDefinition` нет. Прежние строковые константы и Markdown-файлы с инструкциями удаляются, а не превращаются в локальный резерв.

| Промпт | Назначение |
|---|---|
| `agent.dialog.system` | Основная манера и границы диалога; основная связь с generation |
| `agent.dialog.live-addendum` | Дополнение живого голосового разговора |
| `agent.dialog.memory-rules` | Правила использования непустого блока памяти |
| `agent.dialog.self-gender.male` | Род агента для мужского голоса |
| `agent.dialog.self-gender.female` | Род агента для женского голоса и пути Сбера |
| `agent.dialog.sber-voice-rules` | Формат ответа GigaChat |
| `agent.dialog.gemini-tts-verbatim` | Дословная озвучка фиксированных фраз Gemini |
| `agent.mood.instructions` | Общая инструкция классификатора тона |
| `agent.mood.sber-json-suffix` | Требование JSON для классификатора GigaChat |
| `agent.recap.system` | Системная инструкция итога разговора |
| `agent.digest.weekly.system` | Системная инструкция итогов недели |
| `agent.digest.weekly.task` | Шаблон задания недели с переменными |
| `agent.digest.weekly.hard-week-suffix` | Завершение текста для тяжёлой недели |
| `agent.memory.extract.system` | Извлечение заметок |
| `agent.memory.instruction.system` | Исправление заметок по просьбе |

Tags записываются в Langfuse: `agent`, домен (`dialog`, `memory`, `mood`, `recap`, `digest`, `tts`), путь (`gemini-live`, `sber`, `background`) и операция. Динамические реплики, заметки и итоги в tags и тексты не входят.

### 2. Provider с кэшем, но без резерва

Новый `agent/app/prompts/provider.py` возвращает `ResolvedPrompt`: скомпилированный текст, имя, версию и исходный Langfuse prompt object.

- `get_prompt(name, label="production", cache_ttl_seconds=60, max_retries=1, fetch_timeout_seconds=2)` вызывается **без параметра `fallback`**.
- Действующий кэш SDK позволяет не обращаться к серверу на каждый вызов. Это кэш уже полученной production-версии, а не хранящаяся в репозитории резервная копия.
- Пустая или ошибочно скомпилированная инструкция считается недоступной.
- При отсутствии действующей production-версии provider выбрасывает `PromptUnavailable`. Текст ошибки не содержит переменных, реплик или других динамических данных.
- Ключи Langfuse обязательны для запуска production-агента. Тесты получают поддельный provider с синтетическими короткими инструкциями, а не копии исходных промптов.
- При старте все 15 промптов предзагружаются в отдельном потоке. Ошибка предзагрузки журналируется по имени; вызов, для которого нет действующего кэша, завершится `PromptUnavailable`.

### 3. Подключение к вызовам

Provider передаётся через `app.state` и конструкторы компонентов.

- `DialogSession` разрешает части при каждом открытии модельной сессии и сохраняет их описание для последующих ходов этой сессии. Нет production-инструкции — сессия не открывается, клиент получает существующую ошибку недоступности голоса.
- `GeminiLiveTts` и путь Сбера разрешают свои инструкции на каждое новое открытие; ошибка преобразуется в существующий `TtsError` или `LiveError`.
- Классификаторы тона — на каждый вызов; при недоступном промпте возвращают `None`, не влияя на ответ диалога.
- Рекапы, дайджесты и оба пути памяти — на каждую фоновую операцию. Рекап и извлечение памяти завершаются существующим неуспешным результатом, API дайджеста возвращает `DIGEST_UNAVAILABLE`.
- Шаблон `agent.digest.weekly.task` компилируется с `{{period_start}}`, `{{sentence_min}}`, `{{sentence_max}}`, `{{hard_week_instruction}}`, `{{marks}}`, `{{recap_block}}`. Текст hard-week берётся из отдельного промпта или остаётся пустым только когда неделя не тяжёлая.
- Совместимость публичных методов сохраняется там, где это не требует локального текста; тестовые фабрики явно получают поддельный provider.

### 4. Связь с трассами

`Tracer.start_turn` принимает необязательные `prompt` и сведения о составных частях. Для одиночной инструкции Langfuse prompt object передаётся напрямую в `start_generation`.

- Диалог: основной `agent.dialog.system` связывается с generation; `metadata.prompt_components` содержит список `{name, version, source}` для всех частей, включая основной. Успешно загруженные части имеют `source=langfuse`.
- TTS: версия записывается в metadata собственного generation.
- Рекапы, недельные дайджесты, классификаторы и memory extract/instruct получают generation с именем операции, `session_id` диалога (если есть), `user_id`, моделью и prompt object. Вход/выход продолжают маскироваться существующим способом.
- Трасса ошибки загрузки промпта не содержит ложной prompt-ссылки или выдуманной версии. Источник `fallback` больше не используется.

### 5. Начальная загрузка из внешнего файла

`agent/scripts/sync_prompts.py` использует каталог имён и настройки Langfuse:

1. `--check` читает `production` по каждому имени и печатает `missing` или `present`; содержимое не выводится.
2. Для создания начальных версий администратор передаёт `--seed <путь>` к JSON-файлу вне репозитория вида `{"agent.dialog.system": "...", ...}`. Файл хранится локально у администратора и в git не попадает.
3. Отсутствующий промпт создаётся с `labels=["production"]`, tags и commit message.
4. Совпадающий по тексту пропускается как `same`; отличающийся сообщается как `changed — skipped` и не создаёт новую версию.
5. Неполный seed или лишние имена отклоняются до любых записей. Никакого `--force` нет.

Так начальные тексты не становятся частью репозитория, а повторная синхронизация не затирает административные правки.

## Risks / Trade-offs

- Langfuse недоступен при пустом кэше → соответствующий модельный вызов недоступен. Это осознанная цена требования «без локального резерва»; кризисные правила и валидаторы в коде не меняются.
- Несовместимые версии составных частей диалога → все версии видны в одном `prompt_components`; production меняется осознанно.
- Удалённая правка ухудшает ответы → прежняя версия сохраняется в Langfuse, откат выполняется возвратом label.
- Дополнительные трассы увеличат нагрузку на worker → после выката следим за памятью и очередью; тексты по-прежнему маскируются.
- Runtime-правка применяется не мгновенно → TTL ограничен 60 секундами; текущая модельная сессия меняет инструкцию только на следующем открытии.

## Migration Plan

1. В ветке удаляем все исходные тексты, подключаем только Langfuse, прогоняем unit/integration-тесты с синтетическими инструкциями.
2. После отдельного согласования администратор передаёт начальные тексты через внешний seed-файл. Скрипт создаёт 15 отсутствующих промптов в prod; файл в репозиторий не копируется. Старый агент объекты игнорирует.
3. Отдельным выкатом обновляем агент в тихое окно. Откат кода — прежний образ; откат любой инструкции — прежний `production` label.
4. После выката проверяем health, реальные generation основного диалога и фоновых операций, prompt links, metadata и отсутствие текстов в трасах. Контрольная смена label выполняется только на безопасной тестовой версии по отдельному согласованию.
5. Документируем в `agent/README.md` обязательность Langfuse, внешний seed, смену label и отсутствие локального резерва.
