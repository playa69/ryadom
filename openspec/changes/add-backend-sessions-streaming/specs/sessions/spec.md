# Дельта-спецификация: sessions

## Purpose

Жизненный цикл сессий диалога с ИИ-компаньоном: создание с выбором режима, история с саммари, доступ к транскриптам с учётом приватности, завершение с самооценкой и ограничения (одна активная сессия, лимиты, инкогнито).

## ADDED Requirements

### Requirement: Создание сессии

Сервис SHALL создавать сессию диалога через `POST /sessions` с одним из режимов: `vent`, `chat`, `gestalt_diary`, `recovery`, `rituals`. Режим `warmth` зарезервирован под v1 и MUST отклоняться с `VALIDATION_ERROR`. Создание MUST требовать аутентификации и зафиксированных согласий (иначе 403 `CONSENT_REQUIRED`). На пользователя MUST быть не более одной активной сессии (иначе 409 `CONFLICT`). Ответ MUST содержать `session_id`, `ws_url`, короткоживущий `session_token` (TTL 300 секунд) и `sse_fallback_url`. При включённой настройке «сессия без истории» сессия MUST создаваться с флагом инкогнито.

#### Scenario: Успешное создание

- **WHEN** аутентифицированный пользователь с принятыми согласиями вызывает `POST /sessions` с `mode="vent"`
- **THEN** возвращается 201 с `session_id`, `ws_url`, `session_token` (TTL 300 сек) и `sse_fallback_url`

#### Scenario: Запрос зарезервированного режима

- **WHEN** клиент создаёт сессию с `mode="warmth"`
- **THEN** возвращается 422 `VALIDATION_ERROR`

#### Scenario: Без принятых согласий

- **WHEN** пользователь без зафиксированных согласий создаёт сессию
- **THEN** возвращается 403 `CONSENT_REQUIRED`

#### Scenario: Уже есть активная сессия

- **WHEN** пользователь с незавершённой активной сессией создаёт новую
- **THEN** возвращается 409 `CONFLICT`

#### Scenario: Сессия в режиме инкогнито

- **WHEN** в настройках пользователя включена «сессия без истории»
- **THEN** сессия создаётся с флагом инкогнито и не пишется в память и историю

### Requirement: История сессий

Сервис SHALL возвращать историю сессий пользователя через `GET /sessions` с фильтрами `mode`, `from`, `to` и cursor-пагинацией. Элемент ленты MUST содержать саммари (темы, эмоции, tension до/после, статус, время начала/завершения) и флаг `has_transcript`, но MUST NOT содержать полный транскрипт. Инкогнито-сессии MUST NOT попадать в историю.

#### Scenario: Лента с саммари

- **WHEN** пользователь запрашивает `GET /sessions`
- **THEN** возвращается страница элементов с саммари и `next_cursor`, без полных транскриптов

#### Scenario: Фильтрация по режиму и периоду

- **WHEN** пользователь запрашивает `GET /sessions?mode=recovery&from=...&to=...`
- **THEN** возвращаются только сессии указанного режима в указанном периоде

#### Scenario: Инкогнито-сессия не видна

- **WHEN** пользователь завершил инкогнито-сессию и запрашивает историю
- **THEN** инкогнито-сессия отсутствует в ленте

### Requirement: Детали сессии и доступ к транскрипту

Сервис SHALL возвращать детали сессии с транскриптом через `GET /sessions/{id}` только её владельцу. Если хранение транскриптов выключено (`store_transcripts=false`), транскрипт удалён или сессия инкогнито — сервис MUST вернуть 410 `SESSION_TRANSCRIPTS_DISABLED` с пояснением. Чужая или несуществующая сессия MUST отклоняться с 404 `SESSION_NOT_FOUND`.

#### Scenario: Чтение своей сессии с транскриптом

- **WHEN** владелец запрашивает сессию с сохранённым транскриптом
- **THEN** возвращаются детали, саммари и транскрипт (реплики с ролью, текстом, временем, emo_tags)

#### Scenario: Транскрипт не хранится

- **WHEN** владелец запрашивает сессию, для которой хранение транскриптов выключено
- **THEN** возвращается 410 `SESSION_TRANSCRIPTS_DISABLED`

#### Scenario: Чужая сессия

- **WHEN** пользователь запрашивает сессию другого пользователя
- **THEN** возвращается 404 `SESSION_NOT_FOUND`

### Requirement: Удаление сессии

Сервис SHALL удалять сессию по `DELETE /sessions/{id}` вместе с транскриптом, саммари и связанными эмбеддингами. Доступно только владельцу. Ответ — 204.

#### Scenario: Удаление своей сессии

- **WHEN** владелец вызывает `DELETE /sessions/{id}`
- **THEN** сессия, транскрипт, саммари и эмбеддинги удалены, возвращается 204

#### Scenario: Удаление чужой сессии

- **WHEN** пользователь удаляет несуществующую или чужую сессию
- **THEN** возвращается 404 `SESSION_NOT_FOUND`

### Requirement: Завершение сессии

Сервис SHALL завершать сессию через `POST /sessions/{id}/finish` с обязательной самооценкой `tension_after` (1–10) и опциональным `takeaway` (≤ 500 символов). Завершение MUST запускать фоновую суммаризацию (темы, эмоции, tension до/после, ключевые факты). Повторное завершение MUST отклоняться с 409 `SESSION_ALREADY_FINISHED`.

#### Scenario: Успешное завершение

- **WHEN** владелец завершает активную сессию с `tension_after=4` и `takeaway`
- **THEN** сессия переходит в `finished`, суммаризация поставлена в фон (`summary_status="pending"`)

#### Scenario: Повторное завершение

- **WHEN** владелец завершает уже завершённую сессию
- **THEN** возвращается 409 `SESSION_ALREADY_FINISHED`

#### Scenario: Невалидная самооценка

- **WHEN** клиент передаёт `tension_after` вне диапазона 1–10
- **THEN** возвращается 422 `VALIDATION_ERROR`

### Requirement: Лимиты сообщений в сессию

Сервис SHALL ограничивать частоту сообщений в сессии: 60 сообщений в минуту на пользователя суммарно по WS и SSE. При превышении MUST возвращаться 429 `RATE_LIMITED` с `Retry-After` (SSE/REST) или фрейм `error` с кодом `RATE_LIMITED` (WS).

#### Scenario: Превышение лимита сообщений

- **WHEN** пользователь отправляет более 60 сообщений в минуту
- **THEN** новые сообщения отклоняются с `RATE_LIMITED` до конца окна
