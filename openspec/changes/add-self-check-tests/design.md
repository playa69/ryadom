# Design: add-self-check-tests

## Context

В приложении нет ни опросников, ни их результатов, ни данных о здоровье. Единственная шкала — напряжение 1–10 в листе завершения разговора. Метрика продукта «динамика самочувствия за 4 недели» (`docs/spec.md` §9.2, раньше по WHO-5, теперь по нашему тесту «Самочувствие», D6) не собирается. Чекин `who5` был описан только для Python-сервиса `backend/`, который приложение не вызывало; сервис и его change'ы удалены (Q-02 закрыт, PROTEUS-250). Этот change переносит тесты в `app/services/api` и расширяет их до каталога.

Место в интерфейсе задаёт `add-mood-diary`: блок «Самопроверка» в сегменте «Дневник» и сегмент «Тесты» (третий после «Дневник» и «Журнал», `/diary/tests`). Блок и сегмент есть только при включённых тестах (D9).

## Goals / Non-Goals

**Goals**

- Пройти любой тест каталога внутри приложения на любой платформе, в том числе без сети.
- Увидеть результат как у конкурента: балл, уровень, шкала, оговорка.
- По желанию сохранить результат и видеть динамику.
- Получить помощь сразу, если ответы говорят о риске.
- Каталог расширяется данными, а не новым кодом экранов.

**Non-Goals**

- Статьи и материалы о расстройствах.
- Рекомендации лечения, «вам нужен психиатр», любые диагнозы.
- Передача результатов агенту или в разговор. Обсудить результат с Рядом человек может только сам, рассказав.
- Платный доступ к динамике.
- Свои тесты «под расстройство» без валидизированной шкалы в основе (у конкурента это, вероятно, ОКР, ПРЛ, РПП, ревность и кризис среднего возраста по 15 и 11 вопросов). Наши «Самочувствие», «Стресс» и «Выгорание» (решение владельца от 25.10, D6) к ним не относятся: формулировки наши, логика подсчёта шкалы сохраняется, диагнозов нет.

## Decisions

### D1. Тест — это данные

Описание теста — объект в `app/packages/self-check/src/tests/<id>.ts`:

```ts
{
  id: 'phq9', version: 1, code: 'PHQ-9',
  title: 'Подавленность', subtitle: 'PHQ-9 · 9 вопросов · ~3 мин', icon: 'cloud-rain',
  preface: 'Как часто за последние 2 недели вас беспокоило следующее?',
  options: [{ label: 'Ни разу', value: 0 }, …],
  items: [{ text: '…', reverse?: false, crisis?: false }, …],
  scoring: { kind: 'sum', multiplier?: 1, max: 27 }
        | { kind: 'mean', subscales: [...] }
        | { kind: 'count', rule: … },
  bands: [{ from: 0, to: 4, label: 'минимальная выраженность', tone: 'calm', text: '…' }, …],
  highBandFrom?: 20,
  source: 'Spitzer, Kroenke, Williams; перевод Pfizer «Russian for Russia»',
  license: 'Свободный инструмент: текст дословно, формулировки не менять',
  status: 'ready' | 'review' | 'blocked',
}
```

`source` — откуда текст: открытый источник или «формулировки наши» (D6). `license` — справочная строка об условиях текста, на показ теста не влияет.

Тест показывается в продакшене только со статусом `ready`: текст наш (у свободных инструментов — дословно из открытого источника, D6), ревью пройдено. `ready` ставит владелец. `review` — текст ждёт ревью, `blocked` — тест не показывается ни в одной сборке.

Функции `score(test, answers)` и `band(test, score)` не имеют побочных эффектов. Тесты подсчёта свободных инструментов сверяются с примерами из первоисточника: обратные пункты, множители, подшкалы.

Версия описания растёт при любой правке вопросов или порогов. Результат хранит версию, и история показывает пометку, если версии разные.

### D2. Прохождение — лист, как у конкурента

**Лист.** Мобильный клиент — `Sheet` Framework7, веб — `Modal.tsx` (лист снизу на узком окне). В листе:

- шапка: значок, название, строка «GAD-7 · 7 вопросов · ~2 мин», «×»;
- полоса прогресса и «Вопрос N из M» цветом акцента;
- вводная фраза инструмента;
- текст вопроса;
- варианты ответа — крупные кнопки во всю ширину, касание сразу ведёт к следующему вопросу;
- «← Назад» со второго вопроса, ответ сохраняется.

**Закрытие.** «×» или системное «назад» при трёх и больше ответах спрашивает «Прервать тест? Ответы не сохранятся.» Ответы не уходят на сервер, пока человек не нажал «Сохранить».

**Обращение.** Вопросы свободных инструментов (PHQ-9, GAD-7, шкала Розенберга) — дословно из открытого источника, на «вы». Вопросы наших тестов и тексты интерфейса — на «ты», как во всём приложении.

### D3. Результат

**Лист результата:**

- заголовок «Результат»;
- крупно «15 / 25», для подшкал — строка на каждую;
- уровень цветом его тона;
- шкала из сегментов по числу порогов с отметкой балла;
- 1–2 предложения пояснения;
- оговорка «Это скрининговый опросник, а не диагноз. Если результат тебя беспокоит — обсуди его со специалистом.»;
- кнопки «Закрыть» и «Сохранить».

**Без диагнозов.** Подписи уровней описывают выраженность («лёгкая», «умеренная», «выраженная»), а не болезнь. Нельзя писать «у тебя депрессия» и «депрессия средней тяжести» (`CON-LAW-01`).

**Высокие уровни.** При уровне от `highBandFrom` под пояснением показывается карточка «Поговорить со специалистом» со ссылкой на «Люди рядом».

**Пороги.** Где официальных порогов нет, подпись уровня — ориентир, без слов «норма» и «отклонение»:

- у наших тестов («Самочувствие», «Стресс», «Выгорание») пороги наши, подпись «ориентир: …»;
- у шкалы Розенберга, UCLA, PSWQ — «ориентир по данным исследований».

### D4. Кризисные ответы

У пункта описания может стоять `crisis: { from: n }`:

- PHQ-9, пункт 9, ответ от 1;
- PCL-5, пункт 16, ответ от 3;
- ACE — вопрос о попытке суицида в семье, ответ «да».

Если хоть один такой пункт сработал, после последнего вопроса **до** результата показывается экран помощи.

- **Заголовок:** «Ты отметил(а), что бывают мысли о смерти или о том, чтобы навредить себе» (для PHQ-9). Для других пунктов текст свой.
- **Текст:** «С этим не нужно справляться одному. Если тяжело прямо сейчас — позвони, это бесплатно и анонимно».
- **Кнопки:** «Позвонить» открывает лист SOS (`client-support`), «Поговорить с Рядом», «Посмотреть результат».

Экран нельзя пропустить молча, только одной из этих кнопок. Сохранение результата на него не влияет. Тексты проходят ревью консультантов (`CON-ETH-04`).

**Лист SOS не меняется** (решение владельца от 26.10). Экран помощи теста — отдельный экран этого change, а «Позвонить» открывает существующий лист SOS как есть. «План безопасности» и «Подышать», которые на макетах стоят внутри листа SOS, в него не добавляются.

Факт кризисного ответа не попадает в продуктовую аналитику и не связывается с человеком. Считается только `self_check_crisis_total{test}` в Prometheus.

### D5. Сохранение — только баллы, с отдельным согласием

**Первое сохранение** открывает лист согласия:

> Сохранить результаты? Результаты тестов — сведения о самочувствии. Мы храним их на серверах в России, видишь их только ты, Рядом (ИИ) их не читает. Удалить можно в любой момент.

Это черновик: итоговый текст и версия — по образцу AI Therapist (задача 0.3, D10). Кнопки «Сохранить» и «Не сохранять». Согласие пишется в `user_consents(kind='self_check', version)`. Без него `POST /api/self-check/results` отвечает `403 CONSENT_REQUIRED`.

**Что уходит на сервер.** Клиент отправляет ответы. Сервер пересчитывает балл тем же пакетом, проверяет версию и сохраняет **только** балл, баллы подшкал, уровень и время. Сами ответы не хранятся и не пишутся в журналы.

**История:**

- в «Самопроверке» под названием теста строка последнего результата «19 октября: 8/21 — лёгкая выраженность» с точкой цвета уровня;
- экран теста: история списком и график по датам на SVG, начиная с двух результатов;
- удаление одного результата и «Удалить все результаты тестов» (там же и в профиле, раздел «Данные»).

Удаление аккаунта стирает результаты до объявления удаления. Отзыв согласия удаляет все результаты.

### D6. Каталог и волны

**Тексты** (решение владельца от 25.10, задача 0.1):

- **Наши тесты вместо WHO-5, PSS-10 и CBI:** «Самочувствие», «Стресс», «Выгорание». Формулировки наши, логика подсчёта шкалы сохраняется (сумма баллов, обратные пункты, уровни по порогам), диагнозов нет. Тесты не валидизированы, поэтому уровни подписаны как ориентир (D3).
- **Свободные инструменты** PHQ-9, GAD-7 и шкала Розенберга — дословно из открытых источников: если переписать вопросы, пороги перестают относиться к инструменту.
- **Новые тесты** — по открытым источникам или своими словами. Тексты конкурента не переносим, берём только устройство: порядок экранов, подсчёт, вид результата.

### D7. Без сети

Описания тестов вшиты в клиентский бандл и входят в предкэш PWA. Пройти тест и увидеть результат можно без сети. Если «Сохранить» не прошло, лист остаётся открытым с «Не получилось сохранить. Повторить». Очереди сохранений нет: результат с чужого устройства в очереди не нужен.

**`diary_opened.tab`.** Этот change добавляет третье значение `tests` в свойство `tab` события дневника `diary_opened` (в `add-mood-diary` — `diary | journal`). Открытие сегмента «Тесты» отправляет `diary_opened {tab: tests}`.

### D9. «Самопроверка» и «Тесты» только вместе с тестами

Блок «Самопроверка» в сегменте «Дневник» и сегмент «Тесты» показываются только при включённых тестах (`SELF_CHECK_ENABLED`). При выключенных в дневнике нет ни блока, ни сегмента: раздел такой, как его описывает `add-mood-diary` (сегменты «Дневник» и «Журнал», блока «Самопроверка» нет). Откат флагом (Migration Plan) убирает и блок, и сегмент.

### D10. Решения владельца по разделу 0 задач

- **0.1, тексты тестов** (решение владельца от 25.10): свои формулировки, новые тесты — по открытым источникам. Итог в D6: «Самочувствие», «Стресс», «Выгорание» вместо WHO-5, PSS-10 и CBI; PHQ-9, GAD-7 и шкала Розенберга дословно (владелец подтвердил 25.10). Вопросы 1, 2 и 5 из Open Questions владелец не решал, они остаются открытыми.
- **0.3, согласие на хранение результатов** — продуктовая задача: текст и версия согласия по образцу AI Therapist (решение владельца от 25.10).
- **0.4, подписи уровней, пояснения, экран помощи, предупреждения волны 3** — по образцу AI Therapist (решение владельца от 25.10). Ревью кризисных текстов консультантами (`CON-ETH-04`, D4) остаётся.

## Данные и API

```text
self_check_results(id uuid pk, user_id fk users, test_id text, test_version int,
                   score numeric, subscores jsonb null, band text, taken_at timestamptz,
                   created_at timestamptz)
  index (user_id, test_id, taken_at desc)
```

| Маршрут | Описание |
|---|---|
| `GET /api/self-check/results?testId=&before=` | история, новые сверху |
| `GET /api/self-check/latest` | последний результат по каждому тесту, для «Самопроверки» |
| `POST /api/self-check/results` `{testId, testVersion, answers, takenAt}` | `201 {id, score, subscores, band}`; `403 CONSENT_REQUIRED`, `422` при неверных ответах или неизвестной версии |
| `DELETE /api/self-check/results/{id}`, `DELETE /api/self-check/results` | `204` |
| `POST /api/self-check/consent` `{version}`, `DELETE /api/self-check/consent` | согласие; отзыв удаляет результаты |

## Risks / Trade-offs

- **[Клинические скрининги в приложении самоподдержки читаются как диагностика]** Волна 3 только после ревью, подписи без названий болезней, экран-предупреждение, путь к специалисту.
- **[Наши тесты не валидизированы]** У «Самочувствия», «Стресса» и «Выгорания» пороги наши (D6). Поэтому уровни подписаны «ориентир: …», без клинических границ и слов «норма».
- **[Метрика самочувствия]** Метрика `docs/spec.md` §9.2 считается по нашему тесту «Самочувствие» вместо WHO-5. С исследованиями WHO-5 её не сравнить, только с собой во времени.
- **[Пункт 9 PHQ-9 срабатывает часто]** Это и есть цель: экран помощи короткий, не блокирует, не сообщает никому и не меняет разговор.

## Migration Plan

1. Пакет `self-check` и подсчёт с тестами — без интерфейса.
2. Миграция `0011_self_check` (номер и порядок — ниже), маршруты, вид согласия.
3. Клиенты за флагом `SELF_CHECK_ENABLED` (часть сегментов дневника, D9).
4. Включение тестов по одному, по мере статуса `ready`.
5. Откат — флаг. Сохранённые результаты остаются у людей и снова видны после включения.

### Порядок слияния и миграции шлюза

- **Порядок слияния в main:** PROTEUS-183 (`add-mood-diary`) → PROTEUS-242 (`add-memory-notes`) → PROTEUS-218 (`add-self-check-tests`) → PROTEUS-243 (`add-notifications`) → PROTEUS-246 (`add-unsaved-dialog`) → PROTEUS-245 (`add-recap-search`).
- **Миграции шлюза** (`app/packages/db/migrations`) идут в том же порядке: `0010_mood_diary` (183) → `0011_self_check` (218) → `0012_notifications` (243). 242, 246 и 245 миграций шлюза не добавляют: таблицы агента создаёт сам агент при старте.
- **Как Drizzle решает, что применять.** `drizzle-orm/postgres-js/migrator` применяет миграцию, только если её `when` в `meta/_journal.json` позже последней применённой. Номер в имени файла на это не влияет.
- **Поэтому миграцию генерируют** `drizzle-kit generate` после ребейза на main, где уже есть предыдущая. Если ветка сливается не в свою очередь, она удаляет свою миграцию и генерирует её заново поверх main, а не переименовывает файл.
- **Выкат миграций** — в том же порядке.
- **PR #67** сейчас смотрит в ветку PROTEUS-183. После слияния 183 его переводят на main.
