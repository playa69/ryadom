## Этап 2. Шлюз API

### 3.3 Стирание результатов при чистке гостей и удалении администратором → `cleanup/unify-erasure`

#### Что сделать
Решено стирать. Код делает ветка `cleanup/unify-erasure` (в `main-cleanup` на 28.10 её нет): общий состав стирания `processes/account-deletion/shared/erase-account.ts` для удаления по просьбе человека, удаления администратором и чистки неактивных гостей; в одной транзакции со стиранием согласие на хранение результатов, если оно в силе, получает в журнале `self_check_consent_events` строку `revoked`, сами журналы остаются. Спек ветка не меняет. После слияния:
- в `account-deletion` «Что стирается в приложении» результаты тестов стираются всеми тремя путями, «Удаление администратором» и сценарий «(Админка) Состав стирания» перестают исключать результаты тестов, «Что остаётся после удаления» говорит о строках `revoked` в журнале согласия;
- в `data-retention` «Что срок хранения не затрагивает» и «Что стирает чистка гостевых аккаунтов» — результаты тестов стираются при чистке гостя;
- в `self-check` «Удаление результатов» (абзац про удаление администратором и чистку гостей) и «Отзыв согласия на хранение результатов» (журнал: запись «отозвано» появляется и при стирании аккаунта);
- `docs/spec.md`: статус REQ-WELL-08.

#### Приёмка
- Слияние ветки проверено по коду; база соответствует коду; в `app/packages/core/test` есть тест стирания результатов всеми тремя путями.
