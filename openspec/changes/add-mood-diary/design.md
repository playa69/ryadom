# Design: add-mood-diary

## Context

- **Чего нет в приложении.** Нет виджетов, часового пояса человека (сервер везде считает по `Europe/Moscow`), очереди задач и библиотеки графиков. Фоновые задачи шлюза — `setInterval` в `app/services/api/src/index.ts` на каждой реплике, без выбора ведущей. Это безопасно только для идемпотентных задач.
- **Навигация.** У мобильного клиента три вкладки: «Главная», «Журнал», «Профиль» (`F7App.tsx`, `TABS`). У веба сайдбар: «Новый разговор», «Люди рядом», история, «Все разговоры», меню аккаунта.
- **Название занято.** «Дневник» сейчас — подпись неактивного режима разговора `DialogMode.Journal` на главной (`HomePage.tsx`, `HomeScreen.tsx`). Решение владельца: режим не переименовываем, два «Дневника» уживаются (см. D1).
- **Нативные проекты** `app/apps/mobile/android` и `ios` есть в репозитории, но виджетов и плагинов уведомлений в них нет. JS-часть обновляется по OTA, нативная — только новой сборкой.
- **Готовые точки опоры:**
  - шкала напряжения из листа завершения подходит образцом для выбора из пяти;
  - `lib/nav.ts` (`isAppRoute`) — готовый вход для ссылок с ярлыка PWA и из уведомлений (`add-notifications`).

## Goals / Non-Goals

**Goals**

- Повторить у конкурента: раздел «Дневник», отметку в два касания, график месяца, итоги недели, события недели, «Год в пикселях», итоги года и виджет. Напоминание о настроении — `add-notifications`.
- Отметка сохраняется на сервере и видна на всех устройствах человека: в вебе, PWA, Mini App и нативном приложении.
- Дневник ведёт к разговору и к людям, а не удерживает в себе.

**Non-Goals**

- Статьи и блог.
- Серии, награды, «не прерывай серию» (`REQ-PRD-04`).
- Отметки задним числом: отметить или поменять можно только сегодняшний день.
- Виджет iOS и виджеты PWA на рабочем столе Windows. Это следующий этап, см. Open Questions.
- Платный доступ к любым частям дневника.

## Decisions

### D1. Где живёт дневник

**Мобильный клиент.** Четвёртая вкладка «Дневник» между «Журналом» и «Профилем», маршруты `/diary/`, `/diary/year/`, `/diary/recaps/`, `/diary/tests/`. Значок отличается от «Журнала», в котором уже книга. Вкладки внутри раздела — сегменты «Дневник · Итоги · Год · Тесты» под шапкой, как у конкурента. Плавающую панель с четырьмя пунктами нужно проверить на ширине 320px.

**Веб.** Пункт сайдбара «Дневник» после «Людей рядом», страница `/diary` с теми же сегментами (`/diary`, `/diary/recaps`, `/diary/year`, `/diary/tests`).

Неактивный режим `DialogMode.Journal` на главной остаётся «Дневником»: переименовывать его не нужно (решение владельца, Open Questions 1). Режим разговора и раздел приложения живут под одним именем.

### D2. Отметка настроения

**Уровни.** Пять уровней (`mood` 1–5): «Тяжело», «Так себе», «Нормально», «Хорошо», «Отлично». Под ними подписи, над ними лица в фирменных цветах. Это не системные эмодзи: в интерфейсе их нет нигде.

**Факторы.** Один на день (`factor`):

| Код | Подпись |
|---|---|
| `work` | Работа |
| `people` | Близкие |
| `health` | Здоровье |
| `money` | Деньги |
| `sleep` | Сон |

Факторы идут лентой с прокруткой. Повторное касание снимает выбор.

**Поведение карточки.**

1. Касание лица сразу сохраняет отметку. Заголовок карточки меняется на «Сегодня: нормально», выбранное лицо выделено, остальные приглушены.
2. Появляется «Что повлияло больше всего?».
3. Касание фактора сохраняет его. Это второе касание.

**День** — местная дата человека (D5). Отметка одна на день, повторный выбор её заменяет. После полуночи карточка снова спрашивает «Как ты сегодня?».

**Без сети** отметка ставится в очередь клиента и уходит при появлении связи. Конфликт между устройствами решается так: последняя по времени отметки побеждает.

### D3. Мост к разговору (наше дополнение)

После отметки «Тяжело» или «Так себе» под карточкой появляется строка «Хочешь рассказать, что случилось?» с кнопкой «Поговорить». Кнопка начинает разговор так же, как кнопка на главной.

После трёх подряд дней «Тяжело» строка меняется на «Похоже, сейчас непросто. Можно поговорить со мной или с теми, кто рядом». Кнопки «Поговорить» и «Люди рядом».

Текст отметки агенту не передаётся. Агент о ней не знает, пока человек сам не расскажет (Open Questions 3).

### D4. График месяца — свой SVG

Библиотека графиков не подключается: нужен один простой вид, и бандл не растёт.

**Как выглядит график:**

- ось X — дни текущего месяца;
- ось Y — пять уровней, слева лица верхнего, среднего и нижнего уровня;
- точки отметок соединены линией только между соседними отмеченными днями, пропуск дня разрывает линию;
- сегодняшний день подписан числом в кружке, будущие дни затенены;
- название месяца справа сверху;
- стрелками можно листать прошлые месяцы, где есть отметки.

**Доступность.** У графика есть текстовая альтернатива «В октябре отмечено 12 дней, чаще всего — нормально».

**Пустое состояние:** «Отмечай настроение каждый день — здесь появится график».

### D5. Часовой пояс

`users.timezone` хранит IANA-зону, по умолчанию `Europe/Moscow`. Клиент передаёт `Intl.DateTimeFormat().resolvedOptions().timeZone` при входе и при каждом открытии приложения, если зона изменилась (`PATCH /api/auth/me {timezone}`). Сервер проверяет зону по списку IANA.

Местная дата отметки считается на сервере по этой зоне. Если клиент присылает дату, она должна совпасть с «сегодня» человека: допуск — сутки назад для очереди без сети (D2), иначе `422`. Неделя — ISO-неделя с понедельника по воскресенье в зоне человека.

### D6. Итоги недели и года пишет агент, хранит приложение

`POST /v1/users/{userId}/digests` на агенте принимает:

```json
{
  "kind": "week" | "year",
  "periodStart": "2026-10-19",
  "marks": [ { "date": "2026-10-19", "mood": 3, "factor": "work" } ],
  "weekly": [ "текст прошлых итогов недели" ]
}
```

Поле `weekly` нужно только для года. Агент добавляет в запрос к модели:

- итоги разговоров за период (`dialog_recaps`, `add-memory-notes`);
- при включённой памяти — заметки видов `event`, `situation`, `agreement` за период.

Агент возвращает `{text, stats}` и ничего не хранит. Приложение кладёт результат в `diary_summaries`. Модель та же, что пишет итоги разговоров (`MEMORY_NOTES_MODEL`).

Если итогов разговоров и заметок ещё нет (`add-memory-notes` не выкачен или выбран вариант памяти «только переключатель»), агент пишет итоги только по отметкам и факторам. Сигнатура маршрута от этого не меняется.

**Итоги недели**

- Текст на 4–6 предложений от лица Рядом, на «ты»:
  - как прошла неделя по отметкам, без среднего балла цифрами;
  - что чаще всего влияло;
  - о чём были разговоры и что из договорённостей сделано, если человек об этом говорил;
  - одно наблюдение без оценки и советов.
- После недели с тяжёлыми днями текст заканчивается мягкой строкой про людей рядом. Под текстом тогда показывается кнопка «Люди рядом».
- Кризисное содержание в итог не попадает: итогов кризисных разговоров нет (`add-memory-notes`, D7), заметки о кризисе отсекает чёрный список.

**Когда считаются итоги недели**

- По кнопке «Собрать итоги недели», когда в текущей неделе отмечено не меньше 3 дней. Повторно — не чаще раза в сутки, новая версия заменяет прежнюю.
- Автоматически в понедельник, в первый тик после 06:00 по местному времени, за прошедшую неделю, если в ней не меньше 3 отмеченных дней.
- Итог прошедшей недели — окончательный, он идёт в «Итоги года».

**Итоги года**

- История года появляется сама, когда за календарный год накопилось 6 итогов недели.
- Обновить её можно кнопкой «Дописать историю», когда с прошлого раза добавилось ещё 4 итога недели.
- Текст до 12 предложений: смена настроения по сезонам, что помогало, к чему человек пришёл.

### D7. «Год в пикселях»

**Сетка.** 12 строк (янв…дек) на 31 столбец, над ней подписи 1, 5, 10, 15, 20, 25, 31. Несуществующих дат в сетке нет. Будущие дни бледнее. Цвет клетки — уровень настроения (`--ryadom-mood-1…5`), пустые дни нейтральные.

**Касание клетки** показывает под сеткой «● 19 октября — нормально · Работа». Легенда: «Тяжело ■■■■■ Отлично».

**Под сеткой:**

- плашки «Отмечено дней: N» и «Чаще всего: нормально» (при равенстве — более высокий уровень);
- кнопка «Поделиться моим годом»;
- карточка «Итоги года»: «Каждые „Итоги недели“ сохраняются сюда. Собрано N из 6 — когда накопится, я напишу большую историю твоего года» и полоса прогресса. После 6 итогов в карточке текст истории.

**Картинка для «Поделиться».** Клиент рисует PNG на canvas: сетку, год, легенду и строку «Мой год в Слышу Рядом · слышу-рядом.рф». Факторов, дат и текстов на картинке нет. Дальше `navigator.share` с файлом, а где его нет — скачивание. На нативных платформах — системный лист Capacitor.

Год переключается стрелками, если есть отметки в прошлых годах.

### D8. Напоминание о настроении — в `add-notifications`

Напоминание о настроении и всё, что связано с уведомлениями, вынесено в change `add-notifications`:
- каналы: локальные, Web Push, бот Telegram;
- вопрос перед разрешением;
- подписки устройств, планировщик, окно, пауза;
- ключи VAPID.

Дневник даёт ему место в карточке отметки (строка «Напоминать о настроении» и вопрос «Напоминать вечером?») и таблицу `mood_checkins`, по которой напоминание понимает, что сегодня уже есть отметка.

### D9. Тик автоматических итогов недели

Автоматический итог прошедшей недели (D6) считает тик раз в минуту на каждой реплике шлюза (`setInterval`, как существующие задачи). Чтобы при нескольких репликах итог считался один раз, тик сначала занимает период вставкой строки `diary_summaries(user_id, 'week', period_start)` со статусом «считается» (`ON CONFLICT DO NOTHING RETURNING`), и вызывает агента только для занятых им периодов.

### D10. Виджет Android

**Вид.** Виджет «Чек-ин настроения» размером 4×1: пять лиц, под ними строка «Повлияло: работа». Если фактор не выбран — «Отметь, что повлияло».

**Поведение:**

- касание лица сохраняет сегодняшнюю отметку прямым запросом к API и подсвечивает лицо;
- без сети отметка ждёт в WorkManager;
- касание строки открывает дневник для выбора фактора.

**Кнопка «Добавить»** в дневнике вызывает `AppWidgetManager.requestPinAppWidget`, нужен свой небольшой плагин Capacitor. Это тот же системный лист, что у конкурента. Где закрепление не поддерживается, показывается инструкция «Удерживай пустое место на экране → Виджеты → Рядом».

**Авторизация.** Виджет не трогает сессию приложения. По «Добавить» клиент получает `POST /api/diary/widget-token`. Это отдельный токен с правом только читать сегодняшнюю отметку и ставить отметку, без срока, с отзывом. В базе только хеш. Нативная часть хранит токен в зашифрованных настройках Android. Токен отзывается при выходе, при «завершить все сеансы», смене пароля, блокировке и удалении аккаунта. Отозванный токен переводит виджет в «Войди в Рядом» с переходом в приложение.

**PWA.** В `manifest.webmanifest` добавляется ярлык «Отметить настроение» (`shortcuts` → `/pwa/diary/?checkin=1`): он появляется при долгом нажатии на значок установленной PWA в Android и на рабочем столе. В PWA строка «Виджет на главный экран» заменяется строкой «Быстрая отметка: удерживай значок Рядом». В вебе и Mini App строки нет.

### D11. Данные (`app/packages/db`, миграция `0009_mood_diary`)

```text
users + timezone text not null default 'Europe/Moscow'

mood_checkins(id uuid pk, user_id fk users, local_date date, mood smallint check 1..5,
              factor text null check in (work, people, health, money, sleep),
              source text check in (app, widget, reminder, telegram),
              created_at, updated_at, unique (user_id, local_date))

diary_summaries(id uuid pk, user_id fk users, kind text check in (week, year),
                period_start date, text text, stats jsonb, generated_at,
                unique (user_id, kind, period_start))

widget_tokens(id uuid pk, user_id fk users, token_hash bytea unique, created_at, revoked_at null)
```

Удаление аккаунта (`account-deletion` в `app/packages/core`) стирает строки всех этих таблиц до анонимизации пользователя. Отметки и итоги — данные о самочувствии. В аналитику значения не попадают, только факт действия (D12).

### D12. Аналитика без значений

События добавляются в `app/packages/analytics/src/events.ts`:

| Событие | Свойства |
|---|---|
| `diary_opened` | `tab` |
| `mood_checked_in` | `source`, `with_factor`, `changed` |
| `mood_bridge_clicked` | `target: dialog \| people` |
| `week_summary_generated` | `trigger: button \| auto` |
| `year_story_generated` | — |
| `year_shared` | — |
| `widget_pin_requested` | `result` |

Значений настроения, факторов и текстов в событиях нет. Значение настроения вместе с id аккаунта может считаться данными о здоровье (предупреждение в `services/api/.env.example`).

## API (`/api`, JSON, сессия обязательна, если не указано иное)

| Маршрут | Описание |
|---|---|
| `GET /diary?month=YYYY-MM` | `{today: {mood, factor} \| null, month: [{date, mood, factor}], week: {start, markedDays, summary \| null}}` |
| `PUT /diary/checkins/today` `{mood, factor?, date?}` | сохранить или заменить отметку; `date` нужен только очереди без сети |
| `GET /diary/year?year=2026` | `{days: [{date, mood, factor}], markedDays, mostFrequent, weeklyCount, story: {text, generatedAt} \| null}` |
| `GET /diary/summaries?kind=week&before=` | итоги недель, постранично |
| `POST /diary/summaries/week` `{weekStart}` | собрать итоги; `409 NOT_ENOUGH_DAYS`, `429` — чаще раза в сутки |
| `POST /diary/summaries/year` `{year}` | `409 NOT_ENOUGH_WEEKS` |
| `GET /diary/events?week=` | события недели, прокси к `GET /v1/users/{id}/memory/notes` (`add-memory-notes`) |
| `POST /diary/widget-token`, `DELETE /diary/widget-token` | токен виджета |
| `GET /diary/widget/today`, `PUT /diary/widget/checkin` | только по токену виджета (`Authorization: Widget <token>`), ограничение по частоте |

Типы — новый `app/packages/contracts/src/api/diary.ts`. Маршруты уведомлений — `add-notifications`. Контракт `/api/auth/me` дополняется полем `timezone`.

## Risks / Trade-offs

- **[Нативные части не доставляются OTA]** Виджет выходит только с новой сборкой APK. До неё в нативном приложении строки виджета нет. Клиент проверяет наличие плагина.
- **[Отметки — чувствительные данные]** Хранятся только в РФ, в аналитику не попадают. Агенту передаются только при генерации итогов, без id сессии. Стираются вместе с аккаунтом. Отдельная строка в согласии не нужна (решение владельца, Open Questions 3).
- **[Итоги недели пишет модель за пределами приложения]** Тот же прокси и та же модель, что у итогов разговоров. Входные данные — коды настроения и факторов, итоги разговоров и заметки, уже прошедшие чёрный список.
- **[Тик на каждой реплике]** Итог недели считается один раз благодаря уникальному ключу (D9). Нагрузка — один индексный запрос в минуту на реплику.

## Migration Plan

1. Миграция `0009_mood_diary`. Таблицы новые, старые данные не меняются.
2. **API и клиенты** выходят сразу для всех: серверного флага нет, вкладка и пункт сайдбара видны всем вошедшим.
3. **Нативная сборка Android** с виджетом выходит отдельно (`native-app-build`).
4. **Откат** — выкатить предыдущие образы api, web и pwa. Таблицы остаются, данные не теряются и вернутся при следующем выкате.

## Open Questions

1. **Название.** Решено: неактивный режим «Дневник» на главной оставляем как есть, не переименовываем.
2. **Знает ли агент сегодняшнюю отметку.** Например, строкой «сегодня отметил: так себе, повлияло: работа» в начале разговора. Это сближает дневник и разговор, но превращает отметку в данные для внешней модели. Предлагаем: нет в первой версии.
3. **Согласие.** Решено владельцем: отдельная строка согласия на хранение отметок настроения не нужна, достаточно общего согласия на обработку данных. Подтверждение юриста не требуется.
4. **Виджет iOS** (WidgetKit с App Intents, iOS 17+). Делать ли во втором этапе — зависит от того, выпускается ли iOS-сборка вообще.
5. **Итоги недели голосом.** Конкурент пишет «итоги недели голосом персоны». У нас текст. Добавить ли кнопку «Послушать» с озвучкой голосом агента?
