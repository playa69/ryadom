# Change: Публичный metrics API для системы сбора Sber500

## Зачем

Положение конкурса Sber500 требует от стартапа публичный GET-эндпоинт метрик: `GET /api/v1/metrics/daily?date_from=…&date_to=…` с Bearer-токеном, отдающий по дням за диапазон до 90 дней пять метрик (`dau`, `llm_requests`, `tool_requests`, `total_users`, `new_users`) в строгом формате, с нулями за дни без активности и `is_final`. Сейчас наружу смотрят только `/dashboard` и `/dashboard/api` (basic auth, формат свой, без параметров дат) — система сбора подключиться не может.

Данные уже считаются: снимки `daily_metrics` (закрытые сутки) и предварительный расчёт текущих суток. Change добавляет тонкий публичный слой поверх того же хранилища без новых источников и без изменения определений метрик.

## Что меняется

- Сервис дашборда отдаёт `GET /api/v1/metrics/daily` с авторизацией `Authorization: Bearer <METRICS_API_TOKEN>` (отдельный бессрочный токен, только чтение), лимитом 30 запросов/мин на IP и телом ошибок `{"error": "…"}` (400/401/429/5xx по ТЗ).
- Ответ — строго поля ТЗ: `startup_id` (`ryadom`), `timezone` (`Europe/Moscow`), `generated_at`, `data[]` по одной записи на каждый день диапазона включительно (`date`, `dau`, `llm_requests`, `tool_requests`, `total_users`, `new_users`, `is_final`), числа целые, дни без активности — нули.
- Источники те же, что у страницы: закрытые сутки — неизменяемые снимки (внутренняя `daily_active_account` наружу не отдаётся), текущие сутки — предварительный расчёт с `is_final=false`. `total_users` дня без снимка повторяет последний известный итог.
- Ответ кэшируется на 15 минут по паре (from, to): закрытые дни неизменны, система сбора ходит в 05:00–07:00 МСК.

## Зависимости и рамки

- Зависит от выката метрик v2 (снимки `daily_metrics`) — выкачен ранее (change `update-sber500-dashboard-metrics`, архивирован).
- Вне рамок: изменение определений метрик, пересчёт снимков 05.11–16.11.2026 (требует отдельного разрешения владельца), выкат в прод (отдельное «да» по скиллу `deploy`).
