# Дельта-спецификация: agent-api

## MODIFIED Requirements

### Requirement: Завершение диалога

Агент SHALL предоставлять `POST /v1/users/{userId}/dialogs/{dialogId}/end` с телом `{ "takeaway"?: string, "tensionAfter"?: 1..10 }` и ответом `200 { "summary" }` либо `404`.

Сводка: `{ "title": string, "themes": string[], "tensionBefore"?: number | null, "tensionAfter"?: number | null, "recap": { "about": string, "main": string, "agreements": string[] } | null, "recapStatus": "pending" | "ready" | "none" }`.

Итог (`recap`) считается в фоне после завершения любым путём и готов не позже чем через 60 секунд. До этого `recapStatus` равен `pending`, а `recap` — `null`. Для разговора «Без памяти», разговора с кризисом и разговора, где человек сказал меньше 40 знаков, `recapStatus` равен `none`.

Эндпоинт — запасной путь на случай, когда сокет уже закрыт. Повторный вызов для завершённого диалога SHOULD возвращать ту же сводку с актуальным итогом.

Сводка MAY также содержать `userMessages` и `assistantMessages`: сколько реплик человека и агента сохранено за весь диалог (все соединения и выкаты между ними). Они нужны продуктовой аналитике шлюза, который видит лишь своё соединение. В контракт приложения они не входят, шлюз их клиенту не отдаёт.

#### Scenario: Завершение без сокета

- **WHEN** клиент закрыл приложение и сокета нет, а диалог открыт
- **THEN** `POST …/end` завершает диалог и возвращает сводку с `recapStatus: pending`

#### Scenario: Повторное завершение

- **WHEN** `POST …/end` вызывается для уже завершённого диалога
- **THEN** агент отвечает `200` с той же сводкой, а если итог готов — с `recap` и `recapStatus: ready`

### Requirement: Память

Агент SHALL помнить о человеке короткие заметки и SHALL искать по его прошлым разговорам (capability `memory-notes`). Маршруты `/v1/users/{userId}/memory`:

- `GET` — настройки, заметки, лимит, совместимые `mode`, `facts`, `limits.maxFacts`;
- `PUT …/settings {enabled?, sensitiveEnabled?, chatSearchEnabled?, recapEnabled?, consentVersion?}`;
- `PATCH …/notes/{id} {text}`, `DELETE …/notes/{id}`;
- `POST …/notes/instruction {text}` — «скажи, что поправить или убрать»;
- `DELETE …/notes` и `DELETE` — удалить всю память, настройки не меняются;
- `GET …/notes?since=&kinds=`;
- `GET …/export`.

Прежние маршруты фактов:

- `DELETE …/facts/{id}` удаляет заметку;
- `PATCH …/facts/{id}` с `text` правит заметку, закрепление отвечает `422 MEMORY_ACTION_UNSUPPORTED`;
- `POST …/facts` добавляет заметку через проверки;
- `GET …/changes` отвечает `ready` с пустым списком.

Без включения с версией согласия агент MUST NOT читать память в разговор и MUST NOT писать её. Настройки хранятся в базе агента и переживают перезапуск. Чтение, экспорт, удаление и стирание пользователя MUST работать всегда, в том числе на паузе.

Заметки хранятся в базе агента. Cognee получает только реплики человека из завершённых разговоров, по документу на разговор. Всё, что попадает в заметки, MUST проходить проверки в коде; чувствительное — только с согласием. Источником заметок MUST быть только реплики человека. Данные одного человека MUST NOT попадать другому. Тексты MUST NOT попадать в логи, метрики и тексты ошибок.

Функционал включается флагом `MEMORY_NOTES_ENABLED`. Подробности — `openspec/changes/add-memory-notes/design.md`.

#### Scenario: Включение без согласия

- **WHEN** вызывающая сторона шлёт `PUT …/memory/settings {"enabled": true}` без `consentVersion` у человека без действующего согласия
- **THEN** ответ `422 AGENT_VALIDATION`, память не включается

#### Scenario: Удаление заметки

- **WHEN** вызывающая сторона шлёт `DELETE …/memory/notes/{noteId}` для заметки этого человека
- **THEN** ответ `204`, заметки нет в `GET` и в следующем ходе, а для чужой или несуществующей — `404 NOTE_NOT_FOUND`

#### Scenario: Удалить всю память не выключает её

- **WHEN** вызывающая сторона шлёт `DELETE …/memory`
- **THEN** заметок нет, а настройки и согласие прежние

#### Scenario: Блок памяти в разговоре

- **WHEN** у человека включена память
- **THEN** системная инструкция модели содержит правила памяти, заметки, итог прошлого разговора и находки из прошлых разговоров (каждое — если включено), без сетевых вызовов на ходу

### Requirement: Разговор без памяти

Диалог, начатый с `memory: "off"`, MUST NOT получать блок памяти, MUST NOT порождать заметки и итог, MUST NOT попадать в поиск по прошлым разговорам. Его текст MUST быть удалён целиком через 24 часа после последнего сообщения (если сокет жив — после его закрытия). Удаление выполняет фоновый цикл агента. Журнал и история отдают поле `memoryMode`. Кризисный путь в таком разговоре работает как обычно.

#### Scenario: Удаление через сутки

- **WHEN** разговор «Без памяти» закончился и прошло 24 часа
- **THEN** диалог, его сообщения и идентификаторы реплик удалены из базы агента, и журнал его не показывает

## ADDED Requirements

### Requirement: Итог прошлого разговора при начале

Ответ `POST /v1/users/{userId}/dialogs` SHALL содержать `previousRecap {dialogId, endedAt, about, agreements} | null`. Поле заполнено, когда:

- создан новый диалог (`resumed: false`);
- у человека включён переключатель «Итог прошлого разговора»;
- у последнего завершённого диалога есть итог.

Приветствие от этого не меняется.

#### Scenario: Есть итог

- **WHEN** последний завершённый разговор имеет итог, переключатель включён, и создаётся новый диалог
- **THEN** ответ содержит `previousRecap` с `about` и `agreements` этого итога

#### Scenario: Возобновление

- **WHEN** у человека открытый диалог и ответ `resumed: true`
- **THEN** `previousRecap` равно `null`

### Requirement: Удаление разговора

Агент SHALL предоставлять `DELETE /v1/users/{userId}/dialogs/{dialogId}` с ответом `204`. Чужой и несуществующий диалог — `404`. Удаление убирает сообщения, идентификаторы реплик, итог и документ разговора в Cognee. Заметки, извлечённые из разговора, остаются. Открытый диалог перед удалением завершается, его сокет получает `ended`.

#### Scenario: Удалить завершённый разговор

- **WHEN** вызывающая сторона удаляет завершённый разговор человека
- **THEN** ответ `204`, разговора нет в журнале, его реплик нет в поиске, а заметки из него на месте
