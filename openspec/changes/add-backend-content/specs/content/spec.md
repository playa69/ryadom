# Дельта-спецификация: content

## Purpose

Публичный контент и «мост к живым людям»: новостная лента, кэшируемый справочник поддержки (горячие линии, группы, специалисты) и фиксация SOS-событий без auth-блокировки для метрик безопасности.

## ADDED Requirements

### Requirement: Новостная лента

Сервис SHALL возвращать ленту новостей через `GET /news` (cursor-пагинация, опциональный фильтр `tag`) с элементами (id, title, teaser, tags, published_at) и полную новость через `GET /news/{id}` (дополнительно body_markdown). Эндпоинты MUST быть публичными (без обязательной аутентификации). Несуществующая новость MUST отклоняться с 404 `NEWS_NOT_FOUND`.

#### Scenario: Лента новостей

- **WHEN** клиент запрашивает `GET /news`
- **THEN** возвращается страница новостей, отсортированных от новых к старым, с `next_cursor`

#### Scenario: Фильтр по тегу

- **WHEN** клиент запрашивает `GET /news?tag=recovery`
- **THEN** возвращаются только новости с указанным тегом

#### Scenario: Полная новость

- **WHEN** клиент запрашивает `GET /news/{id}` существующей новости
- **THEN** возвращается новость с body_markdown

#### Scenario: Несуществующая новость

- **WHEN** клиент запрашивает несуществующий id
- **THEN** возвращается 404 `NEWS_NOT_FOUND`

### Requirement: Справочник поддержки «Люди рядом»

Сервис SHALL предоставлять справочник: `GET /support/hotlines` (горячие линии — MUST всегда возвращаться первым блоком в ответе клиенту), `GET /support/groups?topic=` и `GET /support/specialists?topic=` (фильтр topic: `addiction`, `grief`, `burnout`, `anxiety`, `other`). Эндпоинты MUST быть доступны без аутентификации. Ответы MUST кэшироваться по ETag: запрос с актуальным `If-None-Match` MUST возвращать 304. Данные групп MUST NOT содержать аффилиации с конкретными брендами сообществ.

#### Scenario: Горячие линии первым блоком

- **WHEN** клиент запрашивает `GET /support/hotlines`
- **THEN** возвращается список линий с телефоном, часами работы и описанием; на клиенте блок отображается первым

#### Scenario: Группы по типу запроса

- **WHEN** клиент запрашивает `GET /support/groups?topic=addiction`
- **THEN** возвращаются группы темы addiction с городом, расписанием, контактом и пометками (анонимность)

#### Scenario: Специалисты по типу запроса

- **WHEN** клиент запрашивает `GET /support/specialists?topic=burnout`
- **THEN** возвращаются специалисты со специализацией, форматом, ценой от и ссылкой на запись

#### Scenario: Кэширование по ETag

- **WHEN** клиент повторяет запрос с актуальным `If-None-Match`
- **THEN** возвращается 304 без тела

#### Scenario: Справочник без входа

- **WHEN** неаутентифицированный клиент запрашивает любой эндпоинт справочника
- **THEN** данные возвращаются (auth не требуется)

### Requirement: Фиксация SOS-событий

Сервис SHALL фиксировать нажатие SOS и срабатывание кризис-классификатора через `POST /sos/events` (trigger: `sos_button` или `crisis_classifier`, опциональный `session_id`) с обязательным `Idempotency-Key` (повтор с тем же ключом в течение 24 часов возвращает первый ответ без дубля). Эндпоинт MUST быть доступен без аутентификации (SOS доступен всегда, без auth-блокировки). Лимит — 10 событий в час по IP (429 `RATE_LIMITED` с `Retry-After`). Ответ 201 MUST содержать ресурсы помощи (горячие линии). События MUST сохраняться для метрик безопасности.

#### Scenario: Нажатие SOS

- **WHEN** клиент отправляет `POST /sos/events` с `trigger="sos_button"`
- **THEN** возвращается 201 с `event_id` и ресурсами помощи (горячие линии), событие сохранено

#### Scenario: Срабатывание классификатора

- **WHEN** клиент отправляет событие с `trigger="crisis_classifier"` и `session_id`
- **THEN** событие зафиксировано с привязкой к сессии, ответ содержит ресурсы

#### Scenario: Идемпотентность по ключу

- **WHEN** клиент повторяет событие с тем же `Idempotency-Key` в течение 24 часов
- **THEN** возвращается первый ответ, дубль события не создаётся

#### Scenario: SOS без аутентификации

- **WHEN** неаутентифицированный клиент отправляет SOS-событие
- **THEN** событие принято (201), auth не требуется

#### Scenario: Превышение лимита

- **WHEN** с одного IP отправлено более 10 событий в час
- **THEN** возвращается 429 `RATE_LIMITED` с `Retry-After`
