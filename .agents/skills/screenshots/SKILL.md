# Скриншоты

Два инструмента, не путай:

1. **Доказательство сценария** — `pnpm evidence <TASK>`: Playwright-тест фичи проходит сценарий и снимает кадр после
   каждого шага. Это то, что прикладывают к отчёту о новой или изменённой функции.
2. **Снимки экранов** — `app/e2e/scripts/ui-shots.mjs`: для каждого экрана и ширины открывает чистый контекст,
   поднимает экран, проверяет вёрстку на глюки и снимает. Для правок вида (до/после) и обзора.

Видео — только если о нём попросили. Данные на снимках только синтетические.

## Стандарт доказательств

- **По снимку на каждый `THEN` сценария OpenSpec**, который меняет задача, от трёх до восьми шагов на сценарий:
  начальное состояние, действие, результат, плюс пустое состояние и ошибка, если они есть в спеке. Больше восьми —
  сценарий слишком крупный, поделись; меньше трёх — доказательства нет.
- Два проекта: `desktop` (1280×900) и `mobile` (Pixel 7). Снимок — после `expect`, который показывает, что шаг
  произошёл; снимок до этого — картинка без доказательства.
- Подпись каждого шага — по-русски, что видит человек. Имя файла `NN-<slug>.png` (латиница, цифры, дефисы).
- Даты и время закрашиваются серым, чтобы один шаг выглядел одинаково от прогона к прогону. Дата сама есть предмет
  шага — `keepDates: true`; своё скрыть — `mask: [локатор]`.
- Перед снимком страница проверяется на глюки вёрстки (`e2e/scripts/shots/glitches.mjs`): найденное пишется в
  манифест и индекс. Это повод поправить вёрстку до отчёта, а не подпись; `EVIDENCE_STRICT=1` валит шаг.
- **Android** — только если задача меняет нативную часть (виджет, уведомления, плагины); веб-часть Android не
  доказывает. Снимок — `adb exec-out screencap`, и **под замком всей машины**, потому что эмулятор один:
  `node scripts/stand.mjs lock android -- adb exec-out screencap -p > android-<шаг>.png` (в bash; PowerShell портит
  двоичный вывод). Замок держи только на время снимка и действий, которым нельзя мешать, не на всю задачу.

## Как снимать доказательство

В спеке сценария, рядом с `expect` шага:

```ts
import { step } from '../support/evidence'

await expect(page.getByTestId('diary-card')).toBeVisible()
await step(page, 'diary-empty', 'Дневник пуст: карточка предлагает отметить настроение')
```

Без `EVIDENCE` вызов ничего не делает, поэтому `step` остаётся в спеке насовсем. Прогон:

```bash
cd app
pnpm evidence PROTEUS-253 web-diary app-diary      # спеки — как у pnpm e2e; без них — весь набор
E2E_REUSE=1 pnpm evidence PROTEUS-253 app-diary    # на уже поднятом стеке (pnpm stand:up --e2e)
```

Результат — `app/e2e/evidence/<TASK>/`: `desktop/NN-<slug>.png`, `mobile/NN-<slug>.png`, `manifest.json` и `index.md`
(подписи, ветка, коммит, стенд, замечания по вёрстке). Папка в git не попадает; перед каждым прогоном она очищается
(`--keep` оставляет). Команда в конце печатает готовую строку `multica issue comment add …` с вложениями.
**Посмотри снимки сам** до отправки: оверлей dev-сервера, недогруженный экран или пустая страница — не доказательство.
Проверка самой фикстуры — спек `evidence` (`pnpm e2e evidence`).

Старая фикстура `shot` (`await shot(page, 'имя')`) складывает картинки прогона в `e2e/screenshots/<проект>/`, имя файла
включает спек и хэш названия теста, одинаковые имена внутри теста получают суффикс `-2`: ничего не перезаписывается.
Для отчёта используй `step`, а не `shot`.

## Сколько снимать экранов

- **Правка по ходу задачи** — только экраны, которые она меняет, на двух ширинах: 390 (телефон) и 1280 (компьютер).
  Это минуты, а не полчаса.
- **Финальный отчёт** (человек спрашивает «готово?», PR идёт на слияние) — доказательство сценария (выше) и затронутые
  экраны на всех четырёх ширинах (390, 820, 1280, 1920) или полный набор (ниже).

## Стенд и вход для снимков экранов

Нужен поднятый стенд: `pnpm stand:up` (скилл `local-dev`) — для `ui-shots.mjs` адреса берутся из `app/.stand.json`
(то есть из слота worktree), флаги `--base`, `--agent`, `--mail` их переопределяют, `--stack e2e` берёт стек e2e
(`pnpm stand:up --e2e`). Из каталога `app/`:

```bash
# один раз на стенд: демо-аккаунт «Женя» с журналом разговоров; сессия ляжет в .playwright-mcp/web-state.json
node e2e/scripts/demo-account.mjs
node e2e/scripts/ui-shots.mjs --app mobile --login       # входит тем же демо-аккаунтом
node e2e/scripts/ui-shots.mjs --app admin --login        # код из Mailpit
```

## Снимок

```bash
node e2e/scripts/ui-shots.mjs --app web --screens home,profile --widths 390,1280 --out ../screenshots/after
node e2e/scripts/ui-shots.mjs --app mobile --screens home,dialog
```

Файлы — `<app>-<экран>-<ширина>.png`, по умолчанию в `screenshots/` в корне репозитория (в git не попадает).
Под именем каждого снимка скрипт печатает найденные глюки; `--strict` не сохраняет снимок с глюком, код выхода 1 —
были глюки или экран не открылся. Глюк — повод поправить вёрстку до отчёта, а не подпись к скриншоту.

Экраны: web — `home`, `dialog`, `dialog-voice`, `dialog-summary`, `journal`, `journal-entry`, `profile`, `people`,
`sos`, `menu`, `login`, `register` и др.; mobile — `welcome`, `home`, `dialog`, `dialog-end`, `journal`, `profile`,
`people`, `sos` и др.; admin — `login`, `users`, `user-card`, `audit`; landing — `home`, `privacy`, `terms`,
`download`, `delete-account`. Полный список — ключи `screens` в `shots/<app>.mjs`.

## До и после

```bash
node e2e/scripts/ui-shots.mjs --app web … --screens home --out /tmp/shots-before   # до правки
node e2e/scripts/ui-shots.mjs --app web … --screens home --out /tmp/shots-after    # после
node e2e/scripts/ui-diff.mjs --a /tmp/shots-before --b /tmp/shots-after --out /tmp/shots-diff
```

`ui-diff.mjs` пишет, на сколько процентов изменилась каждая картинка, и кладёт `<имя>-diff.png` с изменёнными
пикселями. Рефакторинг, который не должен менять вид, — около 0 %; всё, что заметит человек, — несколько процентов.

## Полный набор

Для финального обзора всего интерфейса — `ui-shots.mjs` без `--screens`: он снимает каждый экран приложения на четырёх
ширинах, по одному запуску на приложение (`--app web`, `mobile`, `admin`, `landing`), и сам проверяет вёрстку на глюки.
Снимает он всё и долго — не для каждой правки. Доказательство сценария по шагам — `pnpm evidence <TASK>` (см. выше).

## В отчёт

- **Задача Multica — комментарием с вложениями**, а не ссылками на файлы на своей машине:
  `multica issue comment add <ID> --content-file e2e/evidence/<TASK>/index.md --attachment <снимок> --attachment …
  --allow-external-file` (файлы вне текущего каталога — с `--allow-external-file`; текст — файлом UTF-8). В тексте —
  что подтверждено, какие сценарии не сняты и почему.
- PR: картинки комментарием `gh pr comment --body-file`, файлы — в отдельной orphan-ветке `assets/pr-<N>-screenshots`,
  не в ветке PR.
- Показывай только изменившиеся экраны и сценарии и подписывай, что на каждом и на какой ширине.
