# Выкат agent 0.6.1: ранбук

Только агент. api, web, pwa, лендинг и база приложения не меняются (с ревизии, из которой собран 0.6.0, `app/` не трогали). Общие проверки выката и
критерии отката — в [POSTDEPLOY-0.6.0.md](POSTDEPLOY-0.6.0.md), автоматические проверки — в [`k8s/postdeploy/`](../postdeploy/README.md).

## Что внутри

| Что | PR | Эффект |
|---|---|---|
| Строка в журнале при каждом открытии сессии Gemini: диалог, цель (`start`, `rotate`, `reconnect`, `voice`, `tts`), голос и его имя у Google | #39 | поведения не меняет; по журналу видно, какой голос запрошен в каждой сессии |
| Смена сессии Gemini раз в N ходов (`GEMINI_ROTATE_EVERY: "4"`), а не после каждого ответа; раньше срока, если аудио в контексте дошло до `GEMINI_ROTATE_AUDIO_TOKENS` (1500) | #40 | меньше открытий сессии: по замеру на живой модели ≈0,7K токенов лимита в минуту на ход вместо ≈1,95K; входных токенов (оплата) больше примерно на треть |

Образ: `cr.yandex/<реестр>/agent/agent:0.6.1`, собран из `main` на ревизии `285dccd` (метка образа `org.opencontainers.image.revision`). Тег `0.6.0` остаётся в реестре для отката.

## Что нужно знать до выката

- **Поведение разговора меняется.** Сессия теперь живёт до четырёх ходов, и накопленное в ней аудио оплачивается на каждый следующий ход (отсюда +⅓ входных токенов). Голос в начале сессии и после смены может звучать по-разному на слух: если после выката снова придут жалобы на смену голоса, в журнале по строкам `gemini live opened … purpose=rotate` видно границы сессий.
- **Откат поведения без смены образа:** `GEMINI_ROTATE_EVERY: "1"` в `agent-config` и перезапуск агента (смена после каждого ответа, как в 0.6.0).
- **Данные и схема не затрагиваются.** Файл диалогов остаётся версии 2, память остаётся включённой (`MEMORY_MODE: "on"`). Откат образа на `0.6.0` безопасен: у обоих образов одна схема, миграции нет.
- **Простой около минуты:** стратегия `Recreate`, живые разговоры оборвутся, клиенты переподключаются сами. Делать в тихое время.

## Шаги (все под admin, каждый отдельным решением владельца)

1. Сверка с кластером (read-only): `kubectl diff -f k8s/agent/00-config.yaml -f k8s/agent/02-deployment.yaml`. Ожидаем **ровно три изменения**: `APP_VERSION` 0.6.0 → 0.6.1,
   новый ключ `GEMINI_ROTATE_EVERY: "4"`, образ `agent:0.6.0` → `agent:0.6.1`. Что-то ещё (чужие ключи, другой образ) — остановиться и разобраться.
2. Образ в реестре: тег `0.6.1`, digest записан в описании PR; нет тега — не применять.
3. Тихое окно: `kubectl -n agent logs deploy/agent --tail=20` — нет открытых разговоров.
4. Применить и дождаться:
   ```bash
   kubectl apply -f k8s/agent/00-config.yaml
   kubectl apply -f k8s/agent/02-deployment.yaml
   kubectl -n agent rollout status deploy/agent --timeout=300s
   ```

## Проверки после выката

- Под `Ready 2/2`, перезапусков 0; образ пода — digest из PR.
- Журнал: `dialog db opened … schema=v2 dialogs=N messages=M` (**N и M не меньше, чем были до выката**: берутся из журнала предыдущего пода или из метрик), `agent started: … memory=on`, предупреждений и ошибок нет, прогрев фраз `озвучено 28, не удалось 0`.
- `GET /version` (port-forward) отдаёт `0.6.1`; `/health/ready`: `"dialogs": "sqlite"`, `"memory": "on"`.
- Новое в журнале: на каждый разговор строки `gemini live opened dialog=… purpose=… voice=… voice_name=…` (`voice_name=Charon` для мужского, `Kore` для женского), `purpose=rotate` примерно раз в четыре хода, а не на каждый.
- Автоматические проверки на тестовом аккаунте (данные не потеряны, диалог работает, Opus, память):
  `EXPECT_MEMORY_MODE=on POSTDEPLOY_BASELINE=<снимок> pytest k8s/postdeploy --expect post` — всё зелёное. Дополнительно память в бою: `POSTDEPLOY_FEATURES=1 pytest k8s/postdeploy/test_features.py`.
- Ручная проверка голосом: длинный диалог (10 и больше ходов) без скачков тембра; после каждой смены сессии голос тот же.
- Наблюдение 30 минут: нет роста ошибок квоты Gemini (`1011`, в журнале `exceeded your current quota`), память пода ниже лимита.

## Откат

| Что случилось | Что делать |
|---|---|
| Жалобы на звук или голос после выката | `GEMINI_ROTATE_EVERY: "1"` в `00-config.yaml` (или правкой ConfigMap), перезапуск агента |
| Агент не стартует или ошибки в журнале | вернуть образ: `kubectl -n agent set image deploy/agent agent=<реестр>/agent/agent:0.6.0` и `APP_VERSION: "0.6.0"`; данные не затронуты |
